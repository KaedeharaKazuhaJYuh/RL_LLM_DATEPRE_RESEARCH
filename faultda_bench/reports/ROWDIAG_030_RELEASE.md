# FaultDA-Bench 0.3.0-dev：窗口边界与验证后决策

2026-10-12。本开发版本工程实现与验收收尾；科学验收继续 **HOLD**。三批合计 84 次真实 DeepSeek 调用，供应商报告 prompt tokens 163,091、completion tokens 9,084；无供应商错误或自动重试。不同实验不合并成功率。

## 主要发现

隔离提示后逐行格式可用。边界最小对照显示：普通逐行回答在右端点严格位于窗口内部/外部时均正确，在精确相等时错误纳入该行。要求逐行给出 `time >= start`、`time < end` 布尔值后，相等边界的两次诊断均正确；但将 end 改为同一时刻的 +08:00 表达，两配置仍均错误。所有探针读取数值和对自报纳入行求和均正确。

| 同一任务的 end 变体 | 普通逐行总值正确 | 显式比较总值正确 |
| --- | ---: | ---: |
| 等于右端点 | 0/2 | 2/2 |
| 比右端点晚一秒，该行在窗口内 | 2/2 | 2/2 |
| 比右端点早一秒，该行在窗口外 | 2/2 | 2/2 |
| 同一端点改用 +08:00 表达 | 0/2 | 0/2 |

以上为**单个历史窗口任务簇**中的开发诊断，不是八个独立任务或已证实可泛化机制。不计算显著性；时区变体还改变文本表达和长度，不能声称已单独证明时区推理是唯一原因。显式比较输出格式不同、token 成本不同，不能称等成本收益。

## 正确的验证结果未转化为安全完成

六动作上限的真实接续轨迹：

| 配置 | 轨迹 | 安全完成 | 安全升级 | agent 错误发布事件 | 实际模型请求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| direct | 4 | 0 | 4 | 0 | 6 |
| rows | 4 | 0 | 3 | 1 | 12 |
| comparisons | 4 | 0 | 3 | 1 | 14 |

十二条都以模型自主 escalate 结束，无响应失败或研究上限删失；错误发布后的升级不计为安全升级。三个配置 healthy 下均 0/2 完成；两辅助配置 shared_compute 下各有一次错误发布，不能说更安全。

comparisons 的四次前置数值回答全部正确，但动作阶段两条健康轨迹仍升级，其中一条多余 stage/publish 后升级；两条损坏工具轨迹一条安全升级、一条发布错误值后升级。正确的局部计算既未保证任务完成，也未保证后续发布安全。模型的公开回复出现把业务行去重、请求幂等去重混淆的表述；例如将 publish 响应 `deduplicated=false` 解读为未对分析行去重。此处只报告响应中可观察的解释，尚未隔离并证明其因果作用。

新的局部诊断提升为精确相等边界 0/2→2/2，**不是 RL 训练提升、完整 Agent 成功率提升或超越强规则**。不将程序帮助与模型自我验证混称同一能力。
