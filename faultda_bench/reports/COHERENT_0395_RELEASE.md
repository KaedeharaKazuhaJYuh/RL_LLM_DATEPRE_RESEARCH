# 0.3.95-dev 收尾报告

2026-10-16。完成状态自洽的真实 CSV/SQLite 环境、72 条读取/终止程序对照，以及技术 GO 后 **24 次真实 DeepSeek 请求、12 对措辞诊断**。全量 **473 项测试通过（121.893 秒）**；独立复审 pending，科学 HOLD。

## 工具环境已经自洽

三窗口的独立总和为 117.89、94.19、94.5；每次重新计算初始产物、错误候选、正确候选、CAS 修复及 SQL 记录，而非改契约后沿用旧报告。三窗口 × 两等价时区 × 两隐藏历史 × 两种前向 actor 边界 = **24 个初始状态**。每状态分别查询第一、第二、修复请求，共 **72 条程序读取/终止对照**：有证据 stop 24、确认违规后升级 24、风险未解升级 24。

这里未解升级是合法保守终止：只查已确认的修复请求，仍不能排除更早的错误提交，且读取预算已经耗尽；不能把它记为无理由过度拒绝。第一次或第二次请求的回执都能区分两种历史。查询前有 12 对完整公开历史相同而私有历史不同的状态，另有 36 对时区等价核验。

固定旧总和只对 8/24 个初始状态，固定 request-17 对 24/72 条读取，固定历史角色对 36/72；旧常量答案不再全对。这只是程序负对照，不证明模型使用了捷径。所有程序动作明确标注 scripted，不计为真实模型工具轨迹。

## 真实配对结果

预先选取 12 个 UTC 条件，每个使用同一公开观察比较两句指代。仅最后一句系统说明变化：final receipt 对比 observation.history[-1] 的 receipt_lookup。请求号三值各四例、提交状态各六例、represented actor 标签各六例。输出固定五项事实，不执行工具。

| 指标 | contextual | explicit |
| --- | --- | --- |
| 完整有效 JSON | 12/12 | 12/12 |
| 五字段全正确 | 0/12 | 6/12 |
| 请求编号正确 | 0/12 | 12/12 |
| committed 正确 | 6/12 | 12/12 |
| revision 正确 | 0/12 | 12/12 |
| publication event_id 正确 | 0/12 | 10/12 |
| represented responsibility 正确 | 12/12 | 6/12 |
| 请求与事件均对，但责任错 | 0（目标正确分母 0） | 4/10 个目标正确条件 |

配对全正确：explicit-only 六对、两臂均不正确六对、contextual-only 和两臂均正确均为零。程序参考在两臂各 12/12，仅作公共事实验算，不是学习策略或等 API 成本的模型成绩。

contextual 十二次都报告最后一次 publish 的修复请求（revision 3、history:8）。这与“final receipt”的另一种理解一致；零分仅表示未命中事前指定的最后 lookup 目标，**不能将其直接称为模型固有恢复缺陷**。显式句使目标/提交元数据更符合预期，但仍有两个事件索引错误，六个 represented role 错误；其中四例目标正确却角色错误。

contextual 的角色碰巧全对，不表示其已正确归属目标，因为本状态里三个 publish 属于同一 represented actor。显式臂全部输出 historical_agent_action，包括六个边界为 3 的脚本当前 actor 条件。该标签指明确说明的程序角色，不是真实 LLM 写出的历史；需独立审查任务解释后，才能判断这种外显错误的研究意义。不能从响应逆推内部原因。

## 可以与不可以得出的结论

本轮支持的是：在这组自洽条件中，明确回执指代改变了外显事实报告；目标定位与 represented role 错误可以分别记录。**不是 RL、权重更新、Agent 完成率或旧综合诊断能力提升，也未通过创新性确认**。模糊臂的另一个合理解释与脚本 actor 命名仍需审阅。

只有一个已有数据/任务簇，三个相关窗口、十二条件对不是十二个独立任务。每单元单次请求，不做显著性/时区因果/泛化结论；条件化角色错误也不是因果中介分析。程序状态、API 事实回答分开计数，不合并成模型成功率。
