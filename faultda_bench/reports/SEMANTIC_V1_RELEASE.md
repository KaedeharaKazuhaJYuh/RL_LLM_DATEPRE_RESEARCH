# FaultDA-Bench 首个开发版本：0.2.0-dev

日期：2026-10-09。完成范围为修订方向的可运行开发基准、强规则对照和单模型接入验证；不是完成研究协议 v2 的所有确认条件。

## 已交付

12 个固定任务，来自三个历史公开数据来源；真实 CSV 运算、版本化 SQLite 报告、带 CAS 的暂存修复、幂等请求绑定、修复确认丢失恢复；E0/E1/E2 证据条件；独立 Decimal oracle；六条固定策略；DeepSeek JSON 适配；冻结配置与逐 episode 审计。具体语义见[实施协议](../docs/SEMANTIC_V1_PROTOCOL.md)。

E2 的盲策略在有 ACK 时直接 stop，恰好有 12 个正常实例正确；这是事后正确，不代表获取了充分证据。它的其他错误 stop 可由虚假完成率识别。全部升级的安全不能代替完成。

强组合基线已解决当前可观察小任务；任务语义策略没有在完成率上超越它。强基线的交互量为 0。盲重试的 I=-1 来自单因素失败重叠/饱和，不是联合条件带来额外正向失败。当前实验没有支持研究规划中“额外耦合失败”的核心假设，不能宣布已找到新机制。

## DeepSeek 实跑

使用本机已配置凭据，共 **73 次请求**；服务返回模型标识 `deepseek-flash`，实际请求别名和所有参数见冻结协议。累计接口报告 **94,495 token**（包含重复上下文及服务返回的 usage；不是估算费用）。无 provider_error，1 次输出解析错误，按无效决策计入。

- 契约完成、安全完成均为 **4/12**。
- 最终产物正确 **12/12**，但 **8/12** 在证据可获得时选择升级，没有完成声明。
- 禁止副作用 **0/12**；错误完成声明 **0/4**，不能以此掩盖过度升级。
- 成功均在版本绑定实例；组汇总和窗口实例最终正确但升级。该现象只描述这三个开发实例，不推断模型一般能力。
- 四条件各有三个 episode，失败率相同，本轮 I=0；正常成功支持仅一个任务，条件恢复 1/1 不具备广泛解释力。

这是首次接入记录，不通过追改提示覆盖负结果。没有 RL 训练，也没有两模型公平比较。不能将规则与 LLM 的差距直接解释为可训练收益。

## 验证及证据

新增测试覆盖扰动有效性、三类任务恢复、CAS 冲突、幂等绑定、暂存/源污染、历史副作用保留、不可辨状态对、预算拒绝、确认丢失及 API 上限/错误隔离。最终全套 **131 项通过**，其中本版新增 15 项。旧 P0 结果不改写。

- [离线汇总](semantic_v1_results.json)及[压缩逐条审计](semantic_v1_results.jsonl.gz)，含数据/代码哈希。
- [API 冻结协议](semantic_v1_deepseek.protocol.json)及[真实调用与轨迹](semantic_v1_deepseek.json)。只记录使用量、响应 ID 和结构化动作，不存储凭据。
- `python -m faultda_bench.semantic.verify_results` 可在不访问网络的情况下校验哈希并从逐条记录重算汇总；它不是重新训练或重新调用模型。
- 加 `--replay` 可重建全部环境并重放保存的动作，逐项核对工具响应和独立 oracle 判定；不消耗 API。

本次已完整重放 **5,196 条轨迹**（5,184 离线 +12 API 保存动作），工具响应和 oracle 判定均一致；暂存的 Git 文件字节也已对照冻结数据/协议/代码哈希，避免跨平台换行改变证据。

## 下一步决策

优先完成独立人工任务审阅，并让同类意图跨多个来源，消除来源/意图混杂；随后加入自然复杂任务中的局部证据、竞争修订和修复依赖，而非为了压低分数增加任意故障。先核验强组合基线是否仍能解决，按 v2 门槛决定是否继续原创性主张。

第二模型家族、固定/随机/条件检查的等成本消融、进程权限隔离、大数据分页、独立最终来源与 RL 另轨均尚未完成。当前不发布正式排行榜，不将 5,184 个相关执行当作 5,184 个独立任务。
