# 聚焦探针复审指南

2026-10-16，0.3.90-dev。范围为 16 个原始事实检查、11 个合成事实反例，以及对应原始案例的 32 单元提示草案；没有新增 API 或新模型结果。不要把此处 27 条算成 27 个恢复任务。

1. 在固定提交上运行 `python -m faultda_bench.probes390.audit`；包内 manifest 逐文件列哈希。该步骤只核查一致性，不认证供应商/历史原貌。
2. 先独立从 receipt_v35_deepseek.requests.jsonl 索引 1、3、5、7 重建输入，确认回执查询对象、历史边界、时区与源行。与 probes_v37_offline.json 的原始事实逐项对照。
3. 对合成事实逐例审查 query/contract 的变化和期待答案；特别标出未同步的报告/账本字段。仅按当前探针计分，不从这些残留字段推断安全 stop。对本探针不适用的检查应确认其不适用并写入 comments，不必假装做了无关计算。
4. 检查常量答案和故意错误规则的通过数，确认原始题与反例分开。2/3 或 2/2 的偶然正确不能隐去；程序参考通过不属于 LLM 能力成绩。
5. 检查 probes_v37_draft.json 每对输出定义、user 字节与设置一致，仅一句变化；判断 final receipt 的指代和显式解释是否公平。不同探针不作因果对照，候选预算未批准。
6. 填 probes_v37_review_template.json，只返回亲自检查案例，写姓名、真人/亲自检查声明、完整 Git SHA、pass/change/reject 和意见。六项 checks 表示该项审查已完成，不表示结论必须 pass；不同意见使用 verdict/comments 记录。

范围核对：`python -m faultda_bench.probes390.review --submission <返回文件> --output <新输出文件>`。代码不能认证身份、解析 Git 提交来源或自动登记人类/科学接受。历史审阅范围不扩用，新审阅仍 pending、科学 HOLD。旧四对实际模型诊断仍用上一版表独立复审。

新科学判别问题建议：在状态自洽、答案变化的相同任务来源中，澄清目标指代后，模型的证据读取与责任归属是否仍可分别错误？先验证状态、权限和评分边界，再决定最小实跑，而不是把当前程序反例当成已证实的机制。
