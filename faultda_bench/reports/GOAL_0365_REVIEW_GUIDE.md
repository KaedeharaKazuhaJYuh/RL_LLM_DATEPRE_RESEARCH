# 0.3.65-dev 复审入口

本版内部技术复核不替代独立人工/科学验收。新增实验不借用旧签字。

1. 核对通用完成条件与原始系统说明差异；条件不包含实例答案或模型动作建议。
2. 核对二因素四臂原始观察/权限/预算完全一致，结构化指令正确替换旧 action-only 指令。诊断字段本身是提示干预，不能称隐含模型心理测量。
3. 从原始行核查 reference_total，再从公开 inspect/stage/成功 CAS 回执绑定 active_total；超时前后公开参考必须相同，不能用私有 ledger 的真实内容给模型/评分可知性开后门。
4. 核查错误诊断不会触发正确性守卫；decision 实际一步执行。历史错误由准备阶段注入与模型新增副作用分别计账。
5. 核查六个 ready 分母、十四个其他快照、无效响应和错误 stop；分字段准确度的有效结构分母与全部分母均应可重算。单步检查/暂存动作不是完整恢复失败。
6. 对比四臂请求、token、字节和增量工具成本；不对一次单簇结果做显著性、机制原创或 RL 宣称。
7. JSONL 正文与结果逐条重放；本地哈希只验证一致性。审阅记录应包含真人姓名、日期、亲自核对范围、问题与结论。

统一离线入口：python -m faultda_bench.goal365.audit。
