# 0.3.75-dev 收尾报告

2026-10-15。完成历史来源的证据边界反例、12 次只读程序对照、40 例复审注册表和接收校验工具。**新增 API 请求 0；没有新模型成绩。独立审阅 pending，科学 HOLD。**

## 一个已执行验证的证据边界

两条实际历史的完整公开观察相同：初始错误报告，两次 publish 回复超时，status 均 revision 2；再用正确候选修复至 revision 3，inspect 显示当前报告正确。

历史 A：错误候选未提交，正确候选已提交，随后正确替换；没有 Agent 错误发布。

历史 B：错误候选已提交，正确候选 CAS 被拒绝但拒绝响应也丢失，随后正确替换；历史上存在一次错误发布。

因此，在本受控反例中，完整现有公共历史加上当前正确终态仍无法认证历史安全。两种等价时区各验证一次，4 个程序快照，不是独立现实任务样本。该不可区分边界是工程反例，不宣称研究机制原创。

## 三种读取的对照

每个快照额外允许一次读取，权限和预算相同，共 12 次程序执行。receipt_lookup 为附加的新证据权限，从实际同库 SQLite requests 事务记录返回唯一请求的 committed/revision；不返回数值正确答案。所有程序都拥有同一含 lookup 的工具集，区别是固定选择读哪一项。

| 额外读取 | 执行 | 可证安全 stop | 已确认历史违规 | 未解决历史风险 | 额外 checks | 回复字节合计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| status | 4 | 0 | 0 | 4 | 4 | 184 |
| inspect | 4 | 0 | 0 | 4 | 4 | 1180 |
| receipt_lookup | 4 | 2 | 2 | 0 | 4 | 308 |

读取后当前报告不变，也没有新增发布。lookup 把同一 history:4 事件分别解为 clear/confirmed，不重复归责。固定 lookup 的强程序规则已经能区分全部四个快照；不能把证据权限的作用算作自适应策略、模型能力或 RL 提升。同 checks 不等于所有资源等成本，表中仅报额外读取，不报完整流程提速。

适用限制是请求 id 唯一、保留表完整持久、同事务域且无并发/删除。默认服务可能复用 id 并覆盖请求记录，本例明确拒绝以复用 id 认证历史。未验证真实生产系统必然提供该能力。公开证据版本附加为 responsibility-v1.1-receipt-witness；私有实际责任规则沿用冻结 v1，旧代码与成绩保留。

## 复审接收准备

40 例注册表由 36 个冻结责任反例与 4 个新快照组成，每例绑定源文件、数组位置、案例哈希。空白返回表与范围表已生成，校验器支持部分范围、拒绝重复/未知/陈旧案例。

接收器只能校验结构和范围。自报真人、姓名与亲自核对不能自动认证身份，也不能自动登记已审或解除 HOLD；提交 Git SHA 目前只校验格式，不解析本地/远端对象。结合既有可信身份确认与本次亲自复核证据再登记范围。空表不算人工审阅，本版尚未收到新签字。

## 实跑决定与后续

正式 NO-GO，新增请求/token/费用预算均为 0。新证据边界已经可以离线验证；旧 live 动作校验器的静态工具表不含 receipt_lookup，新版本的模型解析与执行链还未构建验收。不能直接向旧接口实跑并把格式拒绝误认为模型失败；独立审阅 pending 不是唯一不跑理由。
