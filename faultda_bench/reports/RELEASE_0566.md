# FaultDA-Bench 0.5.66-dev 收尾报告

日期：2026-10-27。分支：`faultda-0.5.66-dev`。**这是 0.5.x 线的收尾版本，不开启 0.5.67。**

本版只做一件事：把 0.5.65 已经登记、但**从未运行过**的那个实例集补上，然后据结果决定这条线是否继续。

## 1. 为什么是这一格

0.5.65 的 Gate 0 地图有 8 个 regime、3 个实例集。预注册的主 regime 是 `k0.30_L3`，取自 `dev_syn`（合成形状）。在该格上最佳固定规则的归一化 regret 为 0.0315 ≤ ε = 0.05，即代价结构可被 9 单元查表绕过。

同一份文件第 25–27 行记录了另一件事：`DEV-SEEN`（24 个真实已见切片）在 `k1.00_L3` 上 `min_fixed_r = 0.1801`，远大于 ε。

**全部 13 个 arm 的离线对照只在 `dev_syn` 上做过。** 也就是说，唯一存在 headroom 的格子上，从未评测过任何一个策略。

本轮补上：`dev_seen` × 8 regime × 13 arm × 24 profile = 192 格，2,496 个 (格, arm) 期望值。全程离线，0 次 API 调用，¥0，CPU 608 秒。

## 3. 四个结果

### 3.1 headroom 是价格的函数，不是任务的函数

同一批 24 个 profile、同一套工具、同一份数据，只改 κ：

`0.0006 (κ=0.03) → 0.0022 (0.10) → 0.0100 (0.30) → 0.1801 (1.00)`

跨度 290 倍（`0.180086 / 0.000621`）。κ ≤ 0.10 时最佳固定规则已贴住 DP，任何策略都不可能被区分；κ = 1.00 时存在 18% 的可见差距。

**这条直接解释了 0.5.65 为什么拿到阴性**：主 regime 选在 κ=0.30、且实例集是合成形状，那里差距只有 1%。不是方法不行，是操作点没有差距。

### 3.2 没有任何学得 arm 回收差距

在唯一有差距的 `k1.00_L3` 上：

- `thompson` = 0.1801，与 bf 完全相同，未回收一个点；
- `linucb` = 0.2031，比 bf 差；
- `q_only` = 0.3872，比 bf 差一倍以上。

四档价格、八个 regime 全部如此。这比 0.5.65 在 `dev_syn` 上的阴性更强：那里的阴性可以解释为"没有差距"，这里的阴性是"有 18% 的差距，三个标准方法一个点都没拿到"。

### 3.3 min_fixed_r 是约定值，不是最小值

`witness.py` 第 235–243 行，`min_fixed_r` 只在 `F, F_size, F_hist` 三族上取最小；`F_hist_plus` 虽然注册在 `FAMILIES` 里、也算了 `regret`，但被排除在 argmin 与 min 之外。本轮实测该族在**每一个** regime 上都不劣于 bf：

| regime | bf (F_hist, 3 单元) | F_hist_plus (66 单元) | 回收差距 |
|---|---:|---:|---:|
| k0.30_L1 | 0.0191 | 0.0152 | 20.4% |
| k1.00_L1 | 0.0999 | 0.0876 | 12.3% |
| k1.00_L3 | 0.1801 | 0.1636 | 9.1% |
| k0.30_L3（主） | 0.0100 | 0.0100 | 0% |

排除它是有理由的：`dev_seen` 只有 24 个 profile，而该族有 66 个单元；`dev_syn` 只有 6 个 profile，它有 198 个单元——它是按 `(整个历史计数, 规模桶)` 建表的细粒度查表，本质上在记忆实例，不是"廉价固定规则"。

但代码与报告都没有写这个约定。读者看到的 `min_fixed_r` 会被读成"所有固定规则里的最小值"，而它其实是"三族固定规则里的最小值"。**两种约定下结论一致**（主 regime 0.0100 ≤ ε；`k1.00_L3` 的 18.0% 或 16.4% 都远大于 ε），所以不撤回任何头条数字，但需要在文档里把约定写明。

推论比这个修正本身更有用：**你测到的"自适应的价值"取决于你把对手类限定得多宽。** 一个更细的查表就吃掉了 9% 到 20%。

### 3.4 价格弹性：学得 arm 过弹四到五倍，而且不换取任何东西

原始检查量 `l/b_ref = spent/κ`（每 profile），以及 κ 从 0.10 升到 1.00（价格 ×10）的弹性：

| arm | l (κ=0.10) | l (κ=1.00) | 弹性 (L=3) | 弹性 (L=1) | regret 变化 |
|---|---:|---:|---:|---:|---|
| bf | 0.990 | 0.547 | −0.26 | −0.38 | 0.0022 → 0.1801 |
| F_hist_plus | 0.990 | 0.580 | −0.23 | −0.39 | 0.0022 → 0.1636 |
| thompson | 0.990 | 0.547 | −0.26 | −0.38 | 0.0022 → 0.1801 |
| linucb | 0.992 | 0.449 | −0.34 | −0.40 | 0.0025 → 0.2031 |
| **q_only** | **0.771** | **0.033** | **−1.36** | **−1.47** | **0.3864 → 0.3872** |

`q_only` 的检查量随价格下降 23 倍，是最优固定规则的 4–5 倍弹性；而它的 regret 在两端完全相同（0.3864 对 0.3872）。

**它确实对价格有反应，但那个反应不换任何东西。** 这比"agent 对价格不敏感"更糟：一个有反应但反应无效的策略，不能靠调价格来修。

## 4. 撤销一条自己的假设

本评估在跑这轮之前写下的预测是：**"检查行为对价格不敏感（|ε| < 0.2），理论最优 |ε| ∈ [1,2]"。**

数据否证了它，方向相反：最优固定规则的弹性是 −0.23 到 −0.38（比预测低），学得 arm 是 −1.36 到 −1.47（比预测的"不敏感"高得多）。这条预测作废，不再作为后续实验的假设。

修正后的提法：不是"弹性有没有"，而是"**弹性落在哪儿**"。可测的量是 `弹性偏差 = ε(arm) − ε(最优固定规则)`，以及"这个偏差是否换来 regret 下降"。在本题上答案是：偏差 −1.1，换来 0。

## 5. 边界（本版不主张什么）

- 24 个**已见开发 profile**，不是独立测试；`Auto MPG` 与 `Glass` 已在本项目中被查看，不能再作为留出来源。
- 单一模型族（`rev1` latent model），`d1` 模型未在本轮重跑。
- 环境是自建的。**本版没有任何外部基准上的模型数据**，因此关于"agent 在真实任务中的行为"一个字的结论都不能下。
- `F_hist_plus` 的优势来自单元数（66 vs 3），不是来自适应；它不能用来支持"自适应有价值"。
- 3.4 的弹性只在两个价格点上算（0.10 与 1.00），中间没有采样；不构成弹性曲线的估计。
