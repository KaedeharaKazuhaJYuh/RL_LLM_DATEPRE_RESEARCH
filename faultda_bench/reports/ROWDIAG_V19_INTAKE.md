# 0.3.0-dev 首轮诊断接收记录（2026-10-12）

本轮是下一版本的实验准备与首轮接口诊断，**不是版本收尾或科学验收通过**。统一验收仍为 0.2.95-dev；新包独立验证，未借用原有人工签字。

## 冻结实验与结果

- 单个历史窗口任务簇；healthy/shared_compute 两状态；direct/coupled 两配置，各重复三次，共 12 次单步决策。
- 每次准备 inspect、inputs、catalog 三次读取，剩余检查数为零。coupled 另有一次模型逐行计算请求，其原始解析结果传给下一次动作请求；私有答案、评分不回传。
- 18 次真实 DeepSeek 请求；thinking disabled，max_tokens 2048，无隐式重试。direct/coupled 实际调用成本不相等，不作等成本收益声明。
- 六次逐行请求全部返回工具动作而非要求的逐行结构，schema 0/6。因此 row_selection、row_values、sum_consistent、total_correct 的 False 是**诊断不可用**，不能解释为四类能力全部失败。
- direct：安全完成 0/6，安全升级 4/6，未终止 stage 2/6；coupled：安全完成 0/6，安全升级 6/6。两配置均无发布、无错误完成。
- coupled 接收的是不合规模型回答，不能据此判断“正确的模型验证结果能否支持停止”。本轮没有有效的数值归因结果，也没有 RL 提升。

逐行提示沿用了原工具动作系统指令，并追加了要求返回数值结构的指令，存在接口冲突；该冲突是合理解释但尚非唯一已证实原因。下一轮须使用单独的逐行诊断系统提示，并保留相同公开任务数据，不修改本轮冻结记录。

## 响应证据与复现范围

保存请求正文及白名单供应商响应：content、id、model、finish_reason、usage。未保存凭据、请求头、异常正文或隐藏推理。实验只使用已有公开任务数据；仍需发布前独立核对响应正文是否包含敏感内容。

独立验证入口：`python -m faultda_bench.rowdiag.suite --verify faultda_bench/reports/rowdiag_v19_deepseek.json`。

验证器重新解析正文、分类、重建模型结果传递与单步工具效果。它证明仓库当前记录的一致性，**不证明供应商身份、历史不可修改或外部时间戳**。代码依赖覆盖冻结时所有 benchmark Python 文件及 DeepSeek 配置模块；之后增加模块也会改变当前协议生成结果，后续需改用显式固定依赖集的独立协议版本，不能覆盖本轮文件。

## 四项审查建议纳入验收

1. 原创性：按需检查与强规则差值为零，不作为已证实贡献。与 UndoBench、Verified Tool Calls 的重叠仍未解除；保持科学 HOLD。新假设通过强基线、语义交互对照与独立审查前不扩源或训练。
2. 安全与完成：必须同时报告安全完成、错误发布、正确状态下的升级和未终止。正确报告停止为正对照，错误报告停止为负对照；不可把升级当完成。语义/证据来源/提交不确定性的独立关联尚需分离因素实验。
3. 数值归因：首先保证逐行结构可读，再分别评分版本、行序与纳入、原始数值、所报合计与自报行的一致性、规范合计。无合法结构时单列接口失败，不推断认知过程。
4. 外部确认：准备固定提交对应的脱敏结果包、公开版本和外部复核记录。本地 SHA 与重放不替代独立确认；尚未发布结果版本或取得新人工复审。用户管理远端发布，当前记录仅本地准备。
