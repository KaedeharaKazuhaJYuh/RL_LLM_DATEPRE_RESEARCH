# 暂存证据的可信边界 · 0.2.55-dev

日期：2026-10-11。研究边界问题：当前报告与暂存候选数值相同，是否足以确认契约正确？本轮以实际计算缺陷构造反例，并区分错误发布与错误宣告完成。

## 故障与物理执行

在新组件 `trust/environment.py` 中继承冻结环境，不改写旧实现。三个模式：healthy 不改变计算；stage_only 仅对暂存计算的每个输出加 1；shared_compute 对初始化及暂存计算均加 1。

错误值先进入真实暂存文件，再由原公开工具发布至 SQLite。参数、版本标识、输入哈希、文件校验和都仍有效；只读 CSV 原件不变。故障不是在结果 JSON 中改标签。它是注入的工具缺陷，不表示旧环境健康实现本来算错。

mode 仅在可信 runner/评价记录中使用，不进入策略观察。三模式的执行前公开契约、工具、预算和 initial_feedback 完全相同；后续数值差异是合法可见现象。此次不同时叠加 ACK 丢失、参数绑定错误、并发或源数据损坏。

## 执行前冻结

`trust_v10_results.protocol.json` 固定代码、来源、任务及 144 个单元：三个旧实例 × E0/E1 × 检查预算 2/3 × 三个计算模式 × 四个程序策略。三个旧来源仍与三意图绑定，不是新增独立样本。故障加 1 是固定工程反例，不用于宣称现实缺陷发生概率。

| 策略 | 行为 |
| --- | --- |
| read_reference | 既有读取/计算规则，发现报告错后使用 stage 修复，但未在发布前验证候选数值 |
| stage_reference | 第九版合法暂存参考规则；E0 有完整输入时退回旧规则 |
| guarded_read | 同读取规则，在发布前用公开输入独立 Decimal 重算，核对候选版本、参数、输出；错误则升级 |
| abstain | 始终升级，作为“没有错误只是因为放弃所有完成”的负控制 |

guarded_read 不调用私有 oracle 或访问环境对象；数值逻辑在独立文件中实现，不复用 stage 的 calculate。它不是身份独立的人工审阅，也不是形式化正确性证明；共享参数绑定解释与干净输入的假设仍保留。

主反例：E1 中 shared_compute 的报告/候选一致但终态错误；stage_only 中正确报告被错误候选替换。按任务簇、证据、预算和模式报告 safe_complete、false_completion、safe_escalation、agent_wrong_publications 与各项实际成本。无新增发布不等于没有 false_completion。

共同检查预算不意味着同等实际支出或程序帮助：guarded_read 读取更多证据并增加独立计算。没有 CPU 耗时、模型 token 或总体性能结论。不能只比较安全升级数，把 abstain 的全放弃策略称为最好。

## 判定与后续边界

计算工具持续损坏时没有合法正确 stage 候选，guarded_read 拒绝发布并升级；这不是已修复报告，也不是安全完成。E1 预算 2 不够公开独立重算时，守卫会放弃，健康条件也可能未完成。

本轮是带明确假设的工程鲁棒性测试，不评价模型是否应该事先知道故障，也没有 LLM 推理、RL 成果或原创机制证据。验证前发布属于已有强对照思路。科学 HOLD 不变，第八至第十版新实验均待独立审阅。

后续模型试验前，必须固定工具可靠性说明和可用独立证据，区分“相同故障源的一致”与“独立来源的支持”，并用 guarded_read 和 abstain 一并对照。不能继续只用 stage_reference 定义强基线。
