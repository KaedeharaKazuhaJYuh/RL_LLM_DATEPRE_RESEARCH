2026-10-16。离线版本，不新增模型成绩。四类探针分别检查时间窗选行、给定行求和、回执目标、历史责任边界。旧协议、旧响应、旧评分不变。科学 HOLD，独立复审 pending。

## 原始问题与澄清草案

“final receipt”可能被理解为最后一次 publish acknowledgement，也可能是最后一步 receipt_lookup。新草案将两种措辞列为配对处理：仅替换一个指令句，保持该探针的输出字段、完整公开观察、查询、模型、温度和预算上限相同。

| 探针 | 固定输出 | contextual → explicit |
| --- | --- | --- |
| window | selected_row_ids | 引用窗口契约 → 明写 start <= aware instant < end |
| arithmetic | reference_total | 对 query.row_ids 求和 → 每个列出的行 ID 加一次原始 decimal value，不重新筛时间窗或按业务键去重 |
| receipt | 请求、是否提交、修订、history:N | final receipt → observation.history[-1]，action=receipt_lookup |
| responsibility | 查询位置的责任列表 | 按责任契约 → 明写 index < boundary 与 index >= boundary |

原始观察四份、探针四类、每类两种措辞，共 **32 个候选提示单元**。每对 user 正文完全相同，系统字段定义相同，仅一个指令句不同。显式句可能同时澄清多个相互关联的规则，是“措辞澄清处理”，不能宣称分离出单个认知机制。探针之间字段与查询不同，不能横比为消融收益；与旧综合诊断也不是同协议。

arithmetic 机械指定全部八个公开源行的 ID，独立测试求和，并不提供正确时间窗选择答案；responsibility 查询 history:4、8、10，独立检查边界，最后一个是读取动作而非发布。均只使用现有公开事实，不传递故障模式、私有评分或旧模型响应。

## 程序参考与反例

原始四快照 × 四探针 = **16 个原始事实检查**。另建 **11 个合成事实反例**：窗口端点三种变化、给定求和行集合三种变化、回执查询目标两例变化、责任边界三种变化。

合成变化仅检验单项事实定义。更改窗口后旧报告不随之重算；更改模型起点后历史构造也未重建，所以它们**不是连贯的恢复任务或真实工具轨迹**，不得用其中残留账本字段评估 stop、安全性或历史违规。必须先重新构造并验证连贯任务，才能作为后续 Agent 实验状态。

Decimal 程序参考按实际时区、精确边界、查询行 ID、唯一 request_id 和零起点历史位置计算。评分区分布尔/整数，拒绝重复查询和行 ID；字段无效整例不得算通过。包含闭区间、业务键去重、找最后 publish、全算 current_model、边界错一位及固定旧答案等人为错误规则。错误规则在有些题上偶然正确是正常现象，完整分组结果保留，不要求每例都失败。

## NO-GO 与预算

固定旧行 ID、旧求和答案、旧责任模式，分别能通过原始四例中的 4/4；改变查询答案后对应固定规则为 0/3。原始四例答案缺少变化，不能单靠其通过率证明模型掌握相关规则。该结论仅是这组探针的程序区分度检查，不是已观察到模型背答案或泄漏。

草案标记 design_only_NOT_APPROVED_FOR_LIVE，**批准/实际 API 请求均为 0**，模块没有 live/Client/传输入口。候选上限如未来获准为每次输出 2048 token、请求正文 65536 字节；32 次总输出 65536 token、正文 2097152 字节。当前只冻结设计，不能视为消费预算授权。输入 token 不预先精确计数；同上限/同公开数据也不代表实际 token 或货币等成本。

技术 NO-GO 理由：当前额外实跑主要回答措辞敏感性；尚未排除固定答案捷径，也没有把合成事实变化变成连贯的 Agent 状态。需要明确竞争解释、任务簇分母、输出/措辞有效性及新计划。独立科学审查仍 pending，本地检查不替代它。
