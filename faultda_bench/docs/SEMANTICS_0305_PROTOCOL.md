# 0.3.05-dev：说明因素、时区表达与验证记录接续

2026-10-12。单个历史 window-01 任务簇，仍属工程开发诊断；没有新真人复审，不扩来源、不训练、不引入第二模型。科学 HOLD。

## 预先冻结的设计

- 八条公开规则对照：四种时间表达 × healthy/shared_compute。
- 十六次独立数值探针：四种时间表达 × 普通显式比较/显式 UTC 转换 × 两次重复。
- 三十二条模型轨迹：分析去重说明 A、请求去重说明 I、验证记录保持说明 C 各开/关，2×2×2 × 两种工具状态 × 两次重复。

固定随机种子 2026101205；每条轨迹先请求一次模型行级比较，然后最多六个工具动作，单条最多七次请求。单探针最多一次请求，整体最多 240 次请求；max_tokens 2048、thinking disabled、45 秒超时、无自动重试。所有配置工具权限和工具执行保持一致，三次准备读取都计入预算。实际写入/决策/调用/token 可能不同，不声明等成本收益。

## 时间表达

utc_end 使用原始 +00:00；plus8_end/minus5_end 只将 end 同一瞬间转换到 +08:00/−05:00；plus8_all 将所有原始行以及 start/end 转成 +08:00。原始值、时刻、行顺序和规范窗口成员不变。变换的是工程任务的时间字符串，不是声明新的公开数据版本。

普通比较沿用上一版 ge_start/lt_end 输出；显式 UTC 格式另要求 start_utc/end_utc/每行 time_utc。独立评分将 UTC 转换事实与比较、选行、求和分开：给出非零偏移字符串或无时区字符串不能算正确 UTC 事实，即使代表同一时刻或总值正确。

## 三项独立动作提示因素

- A：deduplicate_keys 只折叠 group join 的相同维表 key/group 匹配，绝不删除事实行；对 window/version 数值没有影响。
- I：publish 的 deduplicated 是请求去重反馈，不是分析行是否去重，也不是报告数值正确性的结论。当前冻结环境默认未启用 request retry 去重；说明不新增幂等保障。
- C：将模型自己的行级结果作为与原契约/版本相关的工作记录，发布/停止前结合公开证据比较，不能仅因读取预算耗尽而丢弃；记录可能错误，不当作评分器背书。

三个因素只独立追加系统提示，公开观察和前置回答传递格式不变。网络替身测试逐项验证这一点。前置诊断提示在所有轨迹完全相同，不随 A/I/C 改变，未提供私有答案或评分。模型每轮重新调用，历史工具反馈保留；前置模型回答每轮原样提供，不自动纠正、不将评分反馈给模型。

## 强规则与解释范围

规则对照从同样公开 inputs/catalog 得出 Decimal 总值，健康报告正确则 stop，错误报告则 stage；若工具仍返回错误候选则 escalate。适用的是这些初始固定报告、不可并发修改的八个状态，不作为通用恢复规划器。私有参考仅在动作后评分。

shared_compute 的 stage 会继续返回错误值，本设计不提供任意写入正确数值的工具；不能将安全升级算成修复完成，不能因工具没有正确候选而声称模型缺少一般修复能力。健康状态能直接停止，属于检验过度写入/升级的正例。

按照任务簇报告，不把 32 轨迹或 16 探针当独立泛化样本。不计算显著性，不从两次重复归因稳定机制。提示因素的说明长度和模型输出成本不同。独立前置验证正确也不代表后续模型实际保留了同一推理；只检查可见响应和执行轨迹。
