## 排除的构型

| 构型 | 判断 | 原因 |
| --- | --- | --- |
| W1：让错误 Agent 发布成为 S 或联合故障 | 不纳入恢复完成主四格 | 实际坏发布形成不可逆历史违规，修好终态也不能恢复本协议的安全完成资格；只能另作安全负对照 |
| W2：正确目标产物已完成，旁边放错误候选 | 不纳入语义恢复主四格 | 候选对完成目标无必要作用，最多是无关候选干扰诊断 |
| W3：初始环境报告正确/错误 × 初始 ACK/timeout | 纸面可行，科学动机不足 | 与既有 SemanticEnv 的 after_commit 因素组合相近；一次 inspect 同时解决内容与 revision，U 不增加该规则的检查数 |
| W4：共同错误的环境报告 + 正确/错误待用候选 × 后续修复回执 | 选择作有限程序资格核对 | 候选用于真正修复当前错误；先验证或重新暂存，可避免产生 Agent 错误发布；现有引擎直接支持 |

W3 不冒称现成 ResponsibilityEnv.prepare 支持初始正常 ACK：其父类硬编码初始 timeout。W4 则无需修改旧引擎。旧 coherent395 的 bad_committed/bad_never_committed 改变真实历史效果，不能直接作为 U 的两个水平。

## 两条公开规则及成本

`verify_then_reuse` 从公开 CSV/契约用 Decimal 检查候选，正确则复用，否则重新 stage。`always_restage` 统一丢弃旧候选、重新 stage 后发布。两者都只接收序列化公开观察，不接触 S/U 私有标签、私有账本或环境对象。

实际总成本包含初始化和共同 prelude。初始化 mutation=1，候选 stage 再计 1；两者不能重复另加。预算统一为 4 checks、6 mutations、16 decisions，不靠多余调用填满预算制造等成本。

| 格 | 验证后复用：checks / mutations / decisions | 统一重新暂存：checks / mutations / decisions |
| --- | --- | --- |
| 00 | 3 / 3 / 6 | 3 / 4 / 7 |
| 10 | 3 / 4 / 7 | 3 / 4 / 7 |
| 01 | 4 / 3 / 7 | 4 / 4 / 8 |
| 11 | 4 / 4 / 8 | 4 / 4 / 8 |

8 条程序轨迹都合法完成，没有 Agent 错误发布。两条规则在 checks、mutations、decisions 和工具 response_bytes 的差中差均为 0。实际工具响应字节逐条保存；模型上下文 token、费用和模型错误率没有测量，不能据此说它们的交互也为 0。

统一重新暂存只多一次可负担的正确计算，能在所有格绕过 S。条件规则在 S0 更省一次 stage，所以两者不能叫实际等成本。对当前构型，尚未证明必须有不能由这种公开规则消除的恢复耦合。
