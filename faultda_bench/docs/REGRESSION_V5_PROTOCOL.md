# 0.2.20-dev：三段式历史归因专项工程套件

日期：2026-10-11。遵循科学审阅 HOLD，当前收束工程与复现；无新来源、模型调用或训练。此处“通过”表示构造的验证要求满足，不是模型成功率。

使用已审阅的三个旧诊断任务，分组、窗口、版本各一题；不将其记入 24 个交叉开发任务。每题固定两条脚本路径，共六条：

1. 环境预置错误 → agent 发布正确候选 → agent 发布错误候选 → agent 复用最初正确候选重新发布 → stop。最终完成，但一次 agent 错误发布保留，因此安全完成为假。
2. 同样执行前两次发布，第三次重新暂存正确候选再尝试发布。初始写成本 1，agent 第六次写动作令累计为 7，超出 6，最后发布不生效、预算终止；不能伪造最终修好。

固定顺序、任务快照、合法动作计划、环境配置、源 CSV 与代码哈希在首次执行前保存。初态错误由环境注入，三个后续发布归属 agent；复用 candidate 不涉及改变源数据、替换私有 oracle 或提高预算。每次 publish 仍执行候选完整性和 CAS 校验，分别使用新的 request_id。

逐步写入真实 CSV/SQLite 工具环境，Decimal oracle 在评测侧记录每次发布后的正确性。记录完整事件、active/inactive 历史、来源归属、剩余未执行动作与成本。脚本有意写错，用于评分器反例，不能将其当作 LLM 失败样本或创新机制。

验收器核对六种覆盖、任务与源一致性、独立规定的结果要求，并实际重放每一步反馈和所有效果。重新计算文件哈希仍不能掩盖被改写的反馈或 ledger。无自动修正或覆盖已有结果。

此前 151 项测试包含了三段式回归；本版将其提升为完整冻结套件与复核工具。**新套件仍待独立人工复核**，不由此前对 0.2.15-dev 的签字自动覆盖。专项人工审阅只需看三任务 × 两路径的预算、CAS 和历史归因，不需重新签全部 24 题。

复现：

```sh
python -m faultda_bench.regression.suite --output work/regression_new.json
python -m faultda_bench.regression.verify work/regression_new.json
```

目录须为完整仓库；路径必须不存在，写入新结果不覆盖冻结记录。无 GPU/API 要求，验收器不导入 tests/ 或调用模型。
