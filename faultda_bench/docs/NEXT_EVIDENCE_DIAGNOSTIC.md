# 下一阶段：已有证据的使用与结束决策

状态：历史设计草案；第三开发版已实现其中的公开元数据与条件动作探针，见[实际执行协议](EVIDENCE_V3_PROTOCOL.md)。独立人工审阅尚未完成，因此本轮只作探索性工程诊断，未满足本草案的确认性验收条件。依据 0.2.05-dev 的事后轨迹：所有升级轨迹曾有正确暂存候选，但其中两条没有正确发布，其他轨迹没有作出完成声明。该现象不是模型内部原因的证明。

下一实验将“是否看懂产物”和“如何从观察选择后续动作”分开，不先扩大题量或启动 RL。

| 环节 | 计划控制 | 需要排除的解释 |
| --- | --- | --- |
| 状态快照诊断 | 固定相同公开历史，分别问当前产物/暂存候选的可验证事实，再独立评下一动作 | 把数字计算错误、状态理解错误与结束决策混成一种失败 |
| 事实整理对照 | 原始响应与确定性的事实整理享有相同事实集合；不返回 oracle 正确性标签 | 只是把标准答案交给 Agent，或减少任务难度造成表面收益 |
| 发布与结束分开 | 分别覆盖仅候选正确、当前产物已正确、证据不足和修订冲突 | 一律 stop 或一律升级在特殊样本上取得虚假好成绩 |
| 方法与模型 | 对照已有强组合规则；保持同模型对比，随后增加不同模型家族 | 基础规则已经足够，却把说明变化当新算法 |

在调用模型前，须冻结快照选择规则、公共证据字段、允许动作集合、提示、预算和失败归因；对快照是否具有唯一合理判断先做独立人工审阅。合法动作可能不唯一，不强制匹配单条专家路径。

主要指标仍是完整任务与历史安全；诊断问答不能代替端到端成功。前述旧轨迹属于开发资料，不能作为新独立确认集。对不同模型家族的接入应明确实际模型来源，不能以同一服务的另一个别名充数。

如事实整理或强规则足以解释全部差异，将结果定位为接口/执行流程诊断；只有出现跨任务可复核的非平凡缺口，才考虑新的学习方法。下一轮具体样本量和调用预算需在实际执行方案中冻结，本草案不授权无限追加 API 运行。
