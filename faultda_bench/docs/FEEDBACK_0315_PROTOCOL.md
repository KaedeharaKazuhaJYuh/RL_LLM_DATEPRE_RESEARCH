# 0.3.15-dev：两轮复查与公开证据辅助对照

协议在真实请求前冻结为 `feedback_v24_plan.json`，随机种子 2026101215。模型延续 `deepseek-flash`，temperature=0、thinking disabled、max_tokens=2048，无隐式重试。调用上限 216；完成整版后报告实际请求、token 与接口失败。

## 数值复查

四种表示相同时间瞬间的表达 × 无反馈/内部检查/公开绑定检查 × 两次重复，共 24 个两轮案例。所有组均用相同公开状态、第一轮规范化输出结构和第二轮复查要求。反馈仅提供违反项，不给改正后的时间、行选择或总和。第二轮同样输出完整记录；使用独立冻结评分器判断，不将程序通过当模型正确。

三组模型请求数同为两次，但 token、反馈长度和程序消耗不同，不能称实际等成本。初次生成属于各组独立调用，非共享同一回答；同时报告初始成绩和修改方向，不用各组最终正确率单独建立因果关系。

## 多步决策

UTC 与仅右端点 +08 两种表达 × healthy/shared_compute × pure/feedback/guard × 两次重复，共 24 条轨迹。每条先做一次模型规范化计算，最多六个进一步动作；工具、准备读证据、预算和通用说明一致。所有组共同明确业务去重、请求幂等和保留验证记录；不按本轮输出事后选择说明组合。

- pure：没有程序数值反馈。
- feedback：每步显示公开输入、契约和已知发布历史导出的记录/候选核验，没有动作拦截。
- guard：与 feedback 初始动作提示完全相同；执行器在不安全 stop/publish 前拦截，因此后续真实历史可能不同。它改变执行权限，属于辅助系统，不等于模型能力提高。

程序绑定来自序列化公开契约、inputs 和 catalog；不读取私有 task/oracle、SQLite 或 staged 文件。CSV 输入哈希按已公开行及原工具序列化重建。只核验请求指向的 exact stage_id，CAS 修订号和 replace 模式。已有单条正确报告即可停止，前置模型记录错误不会否定独立公开证据。若曾出现错误发布/重复，后续修正也不抹除历史归因。

阻断以 `invalid_model_output` 无效动作进入既有执行器：消耗一个决策及六步机会，零发布/暂存写入，不自动 stop/escalate。完整保留 proposed、executed、reasons 和 public history。新权限可能减少写入成本，要单独报告阻断数量与实际写入，不能称相同工具成本。

## 强对照与边界

同时冻结四表达 × 两计算状态的八条公开强规则控制。健康报告可直接停止；同源计算错误没有合法正确候选时安全升级。强规则没有 API 成本，其算法帮助与模型组分别列示。

仅一个窗口任务簇；重复/时间改写不是独立来源。本版不研究并发、原始源损坏或确认丢失，不开展新 RL 训练。检查器是公开数据程序计算帮助，不是学习到的恢复机制。主报各组安全完成、安全升级、错误发布事件、错误发布轨迹、虚假完成和限额未终止；不把升级等同完成。

程序反馈 bytes 是 JSON 载荷长度；完整请求和供应商 usage 保存可独立计算额外文本消耗。checker_runtime_seconds 是本地墙钟，含 Python 反馈构造/检查开销，不是认证 CPU 周期；重放只校验有限非负与聚合，不重建历史时间。响应白名单不含凭据、headers、隐藏 reasoning 或异常正文。本地哈希/固定提交不认证供应商响应或外部时间戳。

新增证据独立人工复审和科学决策均待完成，维持 HOLD。若结果只达到强规则或守卫机械保护，不作为新增机制或 RL 改善。
