# 0.5.65-dev CI 集成修复｜2026-10-21

PR #9 分支早于 #8 的统一登记表与 v47 冻结，合并时四个活文件冲突。保留两个版本的历史说明，以登记表作为当前证据 CI 的唯一入口，登记全部15个 VeriCost 测试模块和新的集成守卫。

## 失败原因及修复

1. Actions 默认浅克隆，缺少 `540f7fb` 与 amendment 提交。当前证据工作流使用 `fetch-depth: 0`，并显式拒绝浅历史；原 v46 冻结的历史工作流字节不改。历史浅克隆作业中两项依赖真实历史的集成测试明确跳过，**当前证据作业以完整历史实际执行它们**；生产审计始终要求历史，绝不静默放行。
2. 跨解释器测试在导入时访问开发者 `/root/.pyenv`，非 root runner 会 PermissionError。改为显式 `VERICOST_PY312`，当前作业安装并传入第二个解释器，缺失或不可访问时只在本地明确跳过。已记录的跨版本实验文件不改，也不声称重新运行完整历史实验。
3. 探索脚本已在预注册中保存哈希并进入仓库；测试直接与这些哈希核对，不再要求未跟踪 `.agents/.../scratch`。不下载、不补造原临时目录。
4. 计划防覆盖测试单独检验真实写入边界，前置条件由既有专门测试覆盖；不要求浅克隆先通过所有生产历史条件才能确认 FileExistsError。
5. 合入 0.5.60 后，原分支改动白名单会看到上游活文档的合法变更。新增集成清单只接受逐文件固定哈希，不按目录或任意新增路径放宽；冻结代码和输入仍要分别通过 v46/v47 核验。

6. Windows spawn 子进程不会继承测试临时配置的 profile 注册表。多进程一致性测试在真实 worker 初始化时显式装载相同测试数据，仍比较单进程、三进程与冻结 fixture 的完整字节；不改动计划中已冻结的生成器，也不声称自定义 profile 的生产多进程接口已完成跨平台适配。
