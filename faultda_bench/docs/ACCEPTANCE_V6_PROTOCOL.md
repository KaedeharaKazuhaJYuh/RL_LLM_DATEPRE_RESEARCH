# 统一证据验收协议 · 0.2.25-dev

目的：把已有证据整合为一个可离线核验的入口，避免文件缺失、历史记录变化和人工审阅范围混淆。本轮不增加模型成绩、训练、数据来源或独立样本。

## 信任边界

`protocols/acceptance_v6.json` 是提交在仓库中的证据快照，固定 63 份历史代码、任务、数据、协议、轨迹和审阅原件的 SHA-256。核验不自动更新快照；修改快照需要审查原因。它提供版本内一致性，不是外部数字签名，也不能防止同时恶意改写校验器与全部证据。

核验顺序：先检查所有冻结字节，再核对原始审阅 ZIP 内文件与接收回执，最后调用固定的历史验证器。清单不能指定待执行命令。目录越界和缺失文件直接失败。

默认核对第一、第二开发版结果汇总及覆盖，重放第三、第四、第五开发版共 150 条保存路径。`--full-replay` 另重放早期 7,524 条路径。重复任务与条件不视为独立样本，不汇总科学成功率。工具只重放保存动作，不调用模型接口。

## 三层状态

| 层次 | 当前状态 | 依据 |
| --- | --- | --- |
| 工程证据 | verified | 文件校验、结果重算与保存动作重放 |
| 人工审阅 | 24 题通过；旧诊断 3 题单独通过；新增专项 6 例待审 | 用户确认真人亲自复核；原始记录与接收回执；旧签字不覆盖新例 |
| 科学验收 | HOLD；scientific_release_ready=false | 尚无已确立的新机制或超出强基线的发现 |

人工声明的 22 项边界检查未提供本轮脚本，不登记为本入口独立重放。机器 verified 仅代表工程证据一致，不代表研究创新性通过。真人身份依据用户明确确认，不由软件自行认证。

## 自动检查

GitHub 的 Python 作业运行统一入口，并上传结构化验收结果。机器核验失败使作业失败；HOLD 和待人工复审明确保留在结果中，不伪装为成功也不使工程作业失败。Python 优化模式可能跳过历史验证器断言，因此入口主动拒绝 `-O`。输出以独占创建方式保存，避免覆盖冻结证据。

后续收到六例复审后，须新建接收记录与下一版本快照，保留本轮待审快照。科学状态变化需要新的科学验收依据，不能由用例签字自动推导。
