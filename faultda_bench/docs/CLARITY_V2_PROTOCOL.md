# 0.2.05-dev：契约清晰度诊断与跨来源任务

本方案在新 API 调用前制定。旧 `0.2.0-dev` 的代码、manifest、提示、评分、结果均不改写；新模块复用其工具环境和独立 oracle。

## 先纠正解释边界

首版契约的 `column` 使用原始列名，而工具把测量列统一返回为 `value`，未明确给出别名映射。此外，非分组任务的通用 `output` 字段仍写 group -> total，与其具体 analysis 的 total 键描述不完全一致。它们是可见的接口质量问题，但尚不能断定导致了所有升级。

因此旧 4/12 只作为旧契约下的接入结果。不能直接用它证明 DeepSeek 缺乏恢复能力，也不能把修正接口后的任何增长宣传成模型或 RL 提升。

## 同题说明对照

选择旧版 group/window/version 各编号 01 的三个开发实例，各取 C×S 四条件，每条分别运行原始说明和明确说明，共 12 对、24 episode。只新增 `contract.input_binding`、修订 `contract.output`；不改变输入数据、执行参数、工具描述、系统提示、预算、oracle 或停止判定，不提供故障标签/正确性标签。测试逐条件验证工具效果与评分完全相同。

干预是“字段映射＋输出格式”的组合，不能把结果归因于其中单一字段。主要观察是配对契约完成差；另外报告终态正确、升级、假完成、调用量、token、服务错误和解析错误。三个实例及其条件高度相关，不做独立样本显著性检验。

使用同一 DeepSeek 配置，温度 0、响应上限 800 token、E0、检查预算 6、关闭幂等。每条最多 8 个 API 请求，总上限 192；不自动重试。两臂按配对块随机顺序交错，最多并发 2。不能保证服务端随机数耦合；说明长度不同，因此等请求预算不等于等 token。

达到 API 上限记 api_budget_exceeded，网络错误记 provider_error；均保留在主要全样本分母，另外报告，不伪装为模型主动升级。协议/顺序/代码哈希在首个请求前保存，逐条追加日志，既有路径禁止覆盖。

这不是新测试集，也不是对首版模型效果的独立确认。无论是否提高分数，明确合法字段映射都是接口修正；若效果无改善，同样保留结果。第二模型家族本轮不伪造或用同厂商别名替代。

## 跨来源开发设计

三份历史公开数据 Auto MPG、Glass、Occupancy，分别实施分组和版本分析各四个变体，共 **3 来源 ×2 意图 ×4 变体 =24 任务**。每任务取 8 个固定、近似等间隔行；自然类别列 cylinders/type/Occupancy 用作业务键，维表复制一个相同映射模拟重复维表；v2 合成一行数值修订。原始引用、许可、行索引与哈希存档。

两个政策 snapshot/latest 在版本意图中平衡；四个变体来自两数值列与不同固定行切片。切片/意图共享来源，不能当作 24 个独立来源。此设计解除“某个意图只在某个来源出现”的完全混杂，但只有三个已见来源，仍不是来源泛化实证。

Auto MPG、Glass 没有对应真实时间戳，不为凑三意图矩阵编造日期；时间窗口保留在旧版说明对照和已有测试，不进入本轮跨来源主分析。

离线使用六个已有固定基线、E0/E1、检查预算 2/4、关闭幂等和四个 C/S 条件，共 **2,304 次执行**。按每个来源×意图单独给原始计数；不用增加相关执行次数制造统计把握度。本轮不增加故障种类以人为压低强基线。

## 审阅和证据

生成 24 题独立人工审阅表，含原始行位置和供审阅者复算的 Decimal 参考；签字栏保持待审。程序测试和代理自审不称为人工审阅。最终新来源仍未读取。

所有新 JSON 直接按 UTF-8/LF 写入，哈希按真实字节计算；输出使用独占创建，拒绝覆盖既有记录。旧版 hash 校验应继续通过。完成后先判断清晰度混杂及强组合基线，再决定下一轮研究投入；本轮不训练模型。
