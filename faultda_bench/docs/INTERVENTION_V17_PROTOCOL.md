# 三臂多步干预协议 · 0.2.90-dev

冻结日期 2026-10-11；来源设计 `intervention_v17_design.json` 保留旧版的“设计未实现”历史状态，本轮以新可执行 plan/protocol 为准。54 条条件：三个旧任务 × 三种工具模式 × 两次重复 × raw/checklist/checklist_guard。固定随机顺序、单例配额 17、总上限 918、45 秒超时、零隐式重试；实际请求由模型动作终止情况决定，不填满预算。

所有臂使用 deepseek-flash、关闭推理、temperature=0、max_tokens=800、json_object，E1 检查预算三、变更计数上限六（含初始写入）、决策上限十六；原环境拒绝的超限尝试仍计费计步。raw 提示不变；另外两臂仅追加完全相同的公开契约清单。无额外工具或隐藏读取，不向模型传入 oracle、故障标签或答案。

checklist_guard 仅在拟 publish 时调用冻结的公共守卫。允许则执行原动作；否则执行 escalate、结束该条。拟动作、实际动作、守卫理由和 CPU 时间分别保存。此替代会改变实际写入成本与终态，应称系统程序干预，不能登记为模型自行判断正确。守卫不拦截 stop，且严格参数比较可能拒绝仅非相关参数不同、数值仍正确的候选；不能预先宣称安全或完成率最优。

raw vs checklist 只改变指令配置；checklist vs checklist_guard 只增加公共程序守卫。任务条件匹配但响应随机性未锁定，重复只有两次，不能做显著性或稳定提升结论。三个任务与来源/意图混杂，不把 54 条当 54 独立任务。与前轮真实轨迹不混池；独立科学审阅仍为 HOLD。

记录 provider usage、模型/响应编号、结束原因、内容哈希/字节、合法动作及失败类别，不保存响应/推理正文或密钥。规范请求重建、拟动作/实际动作、守卫判断、反馈、状态与评分可重放；供应商真实性、响应解析类别、CPU 和网络时间不能独立复算。CPU 时间用 process_time，受计时分辨率影响，零读数不表示没有计算成本。

执行前完成提示同一性、拒绝替代/计步、非法输出限额与反篡改测试；接收阶段另验证正确候选放行、stop 未被守卫改写。全部请求前已落盘可执行计划。输出使用新路径，逐条 flush；发生错误不隐式重试或覆盖历史。
