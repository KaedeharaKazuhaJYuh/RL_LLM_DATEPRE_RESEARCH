# 0.2.10-dev：公开证据与条件恢复诊断

本轮是探索性工程诊断。机器一致性检查已实现，独立人工审阅仍待完成，不作为确认性研究或 RL 增益证据。

使用前三个已见来源的各一个旧任务，预设 inspect 与正确 stage（不透明条件仅失败的 inspect）。四个状态为：当前报告正确、报告错误但候选正确、读写不可用、观察后并发写入正确报告。并发条件与候选条件在初始公开观察上完全相同，必须通过后续检查或 CAS 反馈发现变化，不能要求模型知道隐藏状态。

每题分别使用原始历史、按动作索引的历史；索引保留全部事件与原始位置，可无损还原，不添加答案或故障标签。它改变序列化布局与长度，因此不是等 token 计算量实验。规则策略还原后处理，作为实现对照。

独立事实请求读取五项公开事实；其回答不传入动作请求。事实评分按字段与严格类型计算，额外键使整题判错。恢复请求自行选择后续动作，不规定唯一正确路径。正确候选由前缀提供，完成率仅指条件继续执行，不能称为自主解题成功率；并发写入者完成的修复也不能归功模型。初始成本与继续成本分别保存。

离线共 72 条（3 题 × 4 状态 × 2 布局 × 3 策略）；API 共 24 条，每条最多 6 次动作请求和 1 次独立事实请求，总上限 168 次，不重试，并发 2，温度 0，输出上限 800 tokens。固定种子打乱执行顺序，协议、任务快照与实现哈希在调用前写入。原始凭据不写入记录。

主指标：可观察状态每布局 9 条条件完成数；不透明状态每布局 3 条安全升级数单独报告。另报告事实整题正确率、错误完成、副作用、调用量与 token 数。状态与来源分层保留；不合并旧版本分母，不对三个旧实例作显著性或泛化宣称。

所有记录通过实际 CSV/SQLite 动作重放与独立 Decimal 验证。人工审阅、新来源、不同模型家族及重复随机运行仍为后续验收项。
