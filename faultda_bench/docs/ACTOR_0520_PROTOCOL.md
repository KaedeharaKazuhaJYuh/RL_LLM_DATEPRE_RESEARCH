# 责任、来源与回执接口契约｜0.5.20-dev

日期：2026-10-19。`actor-receipt-v1` 是新的只读结构视图，保留旧代码、记录和分数。本版只在旧 72 条脚本观察及测试夹具上核对结构；没有新模型动作或真实恢复执行，不声称已经由人类独立确认无歧义。

## 必须分开的轴

| 字段 | 回答的问题 | 不表示什么 |
| --- | --- | --- |
| `environment_setup` | 初始化责任；不属于动作数组 | 不借 `history:-1` 猜测某次物理发布 |
| `responsibility_scope` | 某次发布尝试位于交接前还是交接后 | `active_actor` 不等于真实模型生成 |
| `generation_origin` | 该观察是否精确匹配已冻结脚本来源 | 文本自称 model/LLM 不构成生成证据 |
| `query_event_id` | 哪一次 `receipt_lookup` 读取 | 不是回执所指的发布尝试 |
| `target_publish_event_id` | 哪次先前发布与同一请求对应 | 不能指向 stage、读取事件或未来事件 |
| `request_id` | 哪个逻辑发布请求 | 多次尝试复用一个请求时，回执不自动确定某次尝试的责任 |

输入必须显式给出查询与发布两类事件，不使用 final/latest 等自然语言默认指代。query 参数、返回 request_id 和目标 publish 参数必须相同；回执类型、边界整数和事件位置严格校验。同一请求有多次发布时返回明确歧义及候选事件，拒绝把一个提交回执猜配到某一 actor；实际物理效果归属仍需要独立账本证据。

交接边界沿用前置任务契约的声明，派生器不能认证其在真实历史中提前固定。未来运行器必须在动作前固定交接及责任定义；冻结后不得按成败移动边界。责任范围、模型真实生成来源及工具实际执行证据分开留存。

当前来源只支持精确 pinned 观察对应 `scripted_fixture`，其余 `unknown`。本版没有真实 `model_api_tool_action` 正例，不靠接口标签补造正例；事实问答、脚本的当前 actor 标签都不等于模型执行工具。未知来源不改变动作责任、终止许可或安全标准。

## 不把参考答案隐藏在接口里

视图仅整理发布尝试、原始参数/响应、责任声明和来源绑定，不新增 stop 许可、违规判定或评分器答案。旧 `public_evidence` 和私有真值只在内部资格核对中比较，不能作为免费提示偷偷给模型。

即使新视图不含私有答案，它依然提供了结构处理与显式绑定。未来若给模型使用，必须共同冻结显示内容、帮助程度和处理成本；不能读取旧响应后用新接口重评分，更不能把可逆/只读迁移说成模型提升。实际模型请求、解析动作、执行器接收和账本效果的完整来源链，仍是未来执行协议的独立工作，不由此解析器冒充完成。

## 验收范围

技术检查覆盖旧 72 个视图，精确保持原始观察及公开许可；反例覆盖阶段误指、错误/未来事件、重复请求、交接极值、布尔边界、伪造来源和回执冲突。程序资格只说明结构约束可执行。

独立接口审查需针对本契约回答：责任轴和生成来源轴能否分别唯一判定；查询事件与目标请求是否明确；重复请求是否仍保留歧义；是否偷偷提供了策略答案。审阅在看任何未来模型成败之前完成。确认不合格则整例各臂共同修改/排除；不能因角色答错而临时排掉该输出。
