# 1.0.35：提示成分识别与自动证据读取规划

日期：2026-10-24。继承 [1.0.30 的 12/12 干预结果](RELEASE_130.md)。本轮同时推进因果定位和可运行方法，结果不决定是否临时增加付费实验。

## 阶段一：哪部分提示真正起作用

三个 01 历史实例 × 健康/语义错误两种状态 × 四个提示，共 **24 条真实模型轨迹**。

| 提示臂 | 额外预算强调 | 信息包含关系 |
| --- | --- | --- |
| context | 否，使用背景文字 | 否，使用背景文字 |
| budget_only | 是 | 否 |
| relation_only | 否 | 是 |
| combined | 是 | 是 |

四臂共用原始 SYSTEM；原始 SYSTEM 已有通用预算要求，所以本轮预算因素指**额外预算强调**。两个提示槽分别用背景文字补至相同 ASCII/UTF-8 字节数，token 数另外记录。信息因素明确 inspect 在 E0 中包含 status 字段、当前报告、输入和目录，不提供任务数值或故障标签。

每个任务/状态报告四臂完成及 `(combined - budget_only) - (relation_only - context)` 的描述性交互。六个任务/状态块采用循环提示顺序；不把每次响应当作独立任务样本。

## 阶段二：把有效思路做成自动方法

三个 03 额外开发实例 × 两种状态 × 两种工具命名 × 两个系统，共 **24 条真实模型轨迹**。

- `schema_only`：向模型提供公开结构化读取契约。
- `auto_plan`：提供完全相同契约，并由规划器给出当前尚需读取的证据组合。
- canonical 接口使用原工具名；opaque 接口只把四个读取工具双射改名为 query_a/b/c/d。描述中的工具引用及历史动作随接口映射，业务键、参数、数值和工具执行不变。
- 两臂都看到 E0 工具返回字段、检查成本和固定响应大小估计。额外帮助的来源明确是规划建议，不能把更多原始信息隐含进一个臂。

**自动规划器**把任务所需证据表示成字段集合，从公开工具能力中枚举预算内可覆盖它的读取组合，先最小化检查次数，再最小化公开字节估计。已成功读取的字段从需求中扣除；失败读取、stage/publish 不冒充已验证状态。没有可行组合时返回不可行。

这不是把 inspect 写死成答案：规划器不按工具名分支，单元测试覆盖任意更名、插入顺序、多个小工具优于一个大工具、证据已读取以及预算不足。规划器不会替模型执行、替换动作、给出数值、发布参数或最终正确标签。模型不采纳建议的动作仍照常执行并计分。

响应字节估计是固定接口元数据，非测试状态测量值，不是实际 token 或能耗保证。实际响应字节、供应商用量、多余写入、错误发布和终止均保留。

## 统一运行设置

DeepSeek `deepseek-flash`，温度 0，thinking disabled。总计 **48 条模型轨迹 + 12 次后台规则控制**。规则按任务/状态共享，别名接口不会产生新的后台任务。

检查 1、写入 6（包括初始化）、总决策 16、每轨迹至多 8 次模型调用、总请求上限 **384**、峰值未缓存费用估算上限 **$0.60**。无重试/回退，供应商中断后的计划单元保留未知。01/03 均来自历史开发数据，一个环境家族。

协议及完整提示、代码和数据哈希在首次请求前保存。另做 **48 次离线公开工具契约预检**，验证六个实例、两种状态下四个读取工具确实返回声称的字段；这些不是模型采样。

```powershell
python -m research.reliability_reset.planning_mechanism work/reset135-new --prepare
python -m research.reliability_reset.planning_mechanism work/reset135-new --execute
python -m research.reliability_reset.planning_mechanism work/reset135-new --verify work/reset135-replay
```

prepare/verify 不调用供应商；execute 使用已配置的 DeepSeek 凭据。费用估算依据 2026-10-24 核对的 [官方价格](https://api-docs.deepseek.com/quick_start/pricing/)，不等同实际账单。

## 方法来源与我们要继续挖掘的问题

[HyperAgent](https://arxiv.org/abs/2608.02650) 已研究工具 schema 与依赖图规划；[INTENT](https://arxiv.org/abs/2602.11541) 已研究预算约束下的推理期规划。这次公开证据覆盖原型采用简单精确枚举，作为可核验方法基线，不把集合覆盖或工具预算规划本身包装成新算法。

[RoTBench](https://arxiv.org/abs/2401.08326) 已评估工具噪声稳健性；[Cross-Interface Policy Regularization](https://arxiv.org/abs/2610.20576) 已采用接口等价性进行一致性训练。本轮改名是迁移探针，不以改名本身作为贡献。上述查阅覆盖论文摘要和方法概述，未复现其完整系统。

我们的后续方法问题是：**能否用任务所需证据来统一不同工具接口的读取预算，并预测“模型真不会恢复”和“先把预算花在了不够用的信息上”的差异？** 当前版本为此提供成分实验、公开证据规划器和可追踪的接口对照。若 schema_only 已足够，则吸收为更简单的接口设计；若规划器另有收益，再研究动态成本和信息拆分，直接以实际结果决定下一步。
