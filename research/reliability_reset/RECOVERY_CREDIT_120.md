# 恢复功劳归谁？一个可以立即运行的研究原型

日期：2026-10-24。版本：Reliability Reset 1.0.20。

## 研究选择

继续 AI Agent 可靠性评测，但从增加审计字段转向可执行的干预实验。用户本轮授权更自由的研究探索；本方案直接开展本地开发实验，不把“先等科学签字”作为构建原型的前置条件。1.0.15 及更早记录保持原样。本轮不调用模型服务，不构造声称独立的留出集。

**主问题：当 Agent 系统在故障后成功时，成功来自被测策略、外部修复器，还是两者协同？相同总工具预算下，错误的交接会不会让组合系统反而弱于修复器单独运行？**

这里的贡献候选是评测中的可识别归因与替代对照，不是“首次注入故障”或“首次区分正常能力和恢复能力”。先完成一个有结果的最小原型，再检验其对真实模型选择是否有用。

## 具体设计

固定现有 12 个历史开发任务：分组、时间窗口、版本分析各四个，属于同一个 CSV/SQLite 发布环境。它们是三个分析意图，**不是三个独立任务家族**。保持原始任务、数据和原生完整评分；分别报告每种意图。

每个任务、故障和预算单元运行：

1. 三个公开观察规则策略分别独立运行：`generic_verify`、`version_refresh`、`task_semantic`。
2. 相同三个策略各自加一个公开观察的语义修复器；策略提出 stop/escalate 时显式交接，尚未真正终止，修复器随后通过相同公开工具行动。
3. 修复器直接独立运行，作为替代对照，避免把修复器本来就能完成的工作记为被测策略能力。

修复器使用已有 `task_semantic` 规则，不能访问私有真值。下一阶段增加具名模型适配器，复用相同的公开观察、行动与归因接口。策略与修复器共享检查、写入及决策预算，交接本身也占一个决策；不得在交接后刷新预算。每个执行调用都记录 `primary` 或 `helper` 来源。两档检查上限为 1 和 4，写入上限 6（包含初始化），总决策上限 16。

六种开发条件：健康、合法输入行重排、仅分析语义错误、提交前超时、提交后回执丢失、语义错误叠加提交后回执丢失。时间/版本/分组错误由已有环境的公开约束对应故障生成器产生。完整条件表、任务哈希与评分定义在第一条执行前写入 `study_design.json`。

## 可区分的结果

令每个固定任务/条件/预算下的安全完成为二值结果：

- `A`：策略独立运行；
- `AH`：策略加修复器；
- `H`：修复器单独运行。

逐单元保留三元组，而不是先汇总成一个总分：

| 观察 | 含义 |
| --- | --- |
| A=0, AH=1, H=1 | 存在帮助收益，但替代对照已经足够，不能宣称协同创新 |
| A=0, AH=1, H=0 | 固定预算下的协同候选；须检查信息、成本与交接是否真正匹配 |
| A=1, AH=0 | 帮助造成负作用 |
| AH=0, H=1 | 主策略与交接消耗造成组合干扰候选 |
| A=1, AH=1 | 在该干预下维持成功；不能由一次健康成功推断所有恢复能力 |

报告 `AH-A`（帮助增益）、`AH-H`（相对替代对照的增量）、健康到故障的变化、每种意图的分项结果、全部失败与工具成本。不将设计好的脚本差异当作 LLM 实证，不对这些嵌套执行计算 IID 显著性。

**推翻条件：**若真实模型实验中 AH 与 H 总是相同，且归因结论不改变任何模型/系统选择，则本方法应保留为诊断对照，不作为独立论文贡献。若差异仅来自漏记修复器成本或额外权限，则直接否定该差异。

## 两个后续创新候选

**候选一：按替代对照校准的恢复评测。** 将“用了修复器后更好”与“模型本身更会恢复”分开，寻找在同预算下仍有解释价值的模型×修复器交互，以及这种交互是否随分析语义而变化。实际增量须由跨模型结果决定。

**候选二：按系统排序分歧选择最小诊断案例。** 在一组开发干预中，选择能区分自主恢复、替代恢复与交接干扰的少量案例，而不是继续机械扩展故障数量。原型先完整枚举；后续在独立任务上检验选择效率与迁移，不能在当前案例上选完再宣称泛化。

下一次模型实验沿用用户偏好的 DeepSeek，固定相同模型快照和工具接口，比较无修复器/有修复器/修复器单独运行。先以一个小规模、预先记录上限的开发实验验证归因表是否改变结论，再决定是否引入第二模型家族与独立任务。

## 与相关工作的实际关系

- [UndoBench，v1](https://arxiv.org/html/2610.05622v1) 已有反事实配对、能力/恢复分离、机制和执行边界对比；因此这些不列为本项目原创点。本轮重点查看摘要、设计、指标及机制隔离章节。
- [AgentCheck，v3](https://arxiv.org/html/2607.11098v3) 已有缓存回放、单点工具响应干预和修复前后对照；本原型不把“复现—干预—修复”本身当作新方法。本轮查看摘要、系统与受控比较章节。
- [AgentPerturb，v1](https://arxiv.org/abs/2610.21624v1) 已系统研究受控扰动及成本，因此“更多故障类型”不是我们的核心区别。本轮查阅摘要。
- [Same Winners, Different Success Rates，v1](https://arxiv.org/abs/2609.34215v1) 已指出恢复评测中相对排序与绝对成功可能脱节；本原型保留绝对结果和完整单元绑定。本轮查阅摘要。
- [Princeton agent-evaluation synthesis](https://sage.cs.princeton.edu/trends/) 已建议控制 scaffold、权限、预算并做因子对照。这意味着因子实验本身是成熟方法；候选增量在于可执行的替代对照及其是否揭示稳定、有用的分析语义交互。

本轮文献阅读是聚焦设计查阅，不是穷尽查新。原型允许积极尝试，报告则区分已实现的测量、设计控制的现象和未来模型证据。
