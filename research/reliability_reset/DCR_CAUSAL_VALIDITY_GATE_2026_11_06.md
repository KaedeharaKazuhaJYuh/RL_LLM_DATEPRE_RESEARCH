# 候选研究设计门槛：DCR 跨系统比较的支持集可比性

日期：2026-11-06  
状态：**原“DCR 因果效度”表述 NO-GO；窄化后的支持集可比性候选 HOLD。尚无独立贡献证据，不运行模型或付费 API。**

## 一句话研究问题

> 不同 Agent 系统的 DCR 差异，有多少反映相同任务/轮次上的下游错误变化，有多少来自父节点正确性和可评分支持集变化？在支持集对齐后，方法比较是否改变？

该候选不提出新的通用 Agent 故障归因算法，也不把描述性 DCR 错写成因果估计量。它检验一个已有分析 Agent 评测指标的比较边界：**跨系统 DCR 差异是否受模型特异的父节点状态和可评分支持集构成影响**。此前的“DCR 因果效度” framing 已在文末复审中关闭。

> 版本说明：下文「已确认定义与缺口」至「当前决定」保留了最初的因果效度候选设计，现已由文末 2026-11-06 复审取代。当前唯一待审问题是 DCR 跨系统比较的支持集可比性。

## 已确认定义与缺口

**[事实]** StateGuard §C.4 将分析单元定义为 LongDS 的 turn 或 DAComp-DE 的派生表。对有可观测父节点的单元，令 `c=1` 表示至少一个声明的上游依赖错误，`c=0` 表示可观测依赖均正确；DCR 为 `P(child error | c=1) - P(child error | c=0)`。LongDS 依赖由参考代码注释确定性解析后人工检查并冻结；DAComp-DE 依赖从参考 SQL 的 `FROM`/`JOIN` 提取。

**[事实]** 该量是观测分组的错误率差。StateGuard 论文把它用于量化 downstream contamination；DCR 本身没有随机化父节点错误，也没有对同一分析状态实施“只修父节点”的评估干预。

**[推断]** 任务难度、共同源错误、依赖边的声明密度或父节点与子节点共享输入，均可能同时提高父、子错误率。因此 DCR 可能高估或低估可归因于上游错误的下游损失。是否发生、大小和排序后果均未知；这不是对 StateGuard 模型效果或其 DCR 数值的反证。

## 可证伪假设

**H1（效度）**：按任务簇估计时，观察性 DCR 对匹配的上游修正干预效应存在足以改变方法比较的校准误差：DCR 排名与干预效应排名的方向不一致，或在误差区间内无法区分。

**H2（边界条件）**：这种不一致随依赖图结构、共同源输入和根/中间节点位置变化。若差异只由错误依赖标注、不同模型重采样或预算不匹配造成，候选关闭。

主张限定为**评测指标效度**，不主张新的因果估计理论；H1/H2 尚未实测。

## 最小实验设计（候选，不是结果）

1. **冻结原始运行。**在每个任务、模型和方法臂上记录完整父子状态、状态输入、原生评分、预算及随机种子。只把公开任务中的声明依赖作为主分析；人工补注依赖只作敏感性分析。
2. **建立匹配分支。**在同一已完成轨迹的下游决策点恢复精确状态，设置两个臂：原父状态回放（placebo）与只替换为参考正确父状态后由同一策略继续（parent-corrected）。所有其他任务输入和可见信息一致；分支后的模型采样按配对种子/分布处理，不把单次路径差称为因果效应。
3. **定义干预量。**对子节点正确率或原生任务分数，估计 `Δ_parent = E[Y | do(parent=correct)] - E[Y | do(parent=observed)]`。按任务簇聚合；节点/边、轮次、重复采样不能当独立任务。
4. **与 DCR 比较。**报告 DCR 与 `Δ_parent` 的方向一致率、排序一致性、校准曲线及区间；比较各系统在观察性 DCR 与干预估计下的顺序是否变化。结论使用“同一轨迹状态上的受控干预效应”，不外推为自然任务中所有原因的结构因果效应。
5. **负对照。**修正无路径关系的平行节点；做结果不变的 sham edit；没有上游错误的任务；仅改变模型随机种子而不改父状态。负对照若也产生类似增益，说明恢复/重采样效应尚未隔离。

## 与近邻工作的边界

|---|---|---|
| StateGuard | DCR 的观察性定义；显式状态依赖、有效性检查和修复；通过改变分析假设生成反事实训练轨迹 | 最直接近邻。其 DCR 公式本身是分组差，论文没有报告对每个错误上游节点做匹配纠正干预后的效度校准；需复核补充材料与代码，不能把“未在已读章节看到”说成完全不存在 |
| Causal Agent Replay | Agent 步骤干预、下游随机重放、分布效应及置信区间 | 覆盖一般步骤级因果归因方法；候选只问该方法能否检验数据分析依赖污染指标的效度 |
| CausalFlow | 多步轨迹依赖图、步骤级干预、因果责任和最小修复 | 对“修正错误步骤是否恢复结果”高度接近；需证明分析状态父子单位和指标校准提供了实质新知识，而不是迁移已有方法 |
| EMFA | 建模多 Agent 错误传播并用反事实验证决定性 agent-step | 覆盖传播与反事实归因；其重点是识别失败步骤，不是对 DCR 这类群体指标作校准审计 |
| ReplayRCA | 恢复失败前状态、替换动作、同 Agent 继续，并用配对 placebo 扣除自然恢复 | 覆盖同态恢复/安慰剂控制；本候选必须沿用其对照思想，不能声称首次使用配对反事实重放 |
| LongDS | 长程分析任务、跨轮依赖与原生 turn 评分 | 提供可能的分析任务基础；是否可合法复用、是否能精确替换父状态与复放仍待技术核验 |

## 主要威胁与技术门槛

- **干预定义：**“正确父状态”必须是任务原生参考状态或确定性重算结果；若只是提示更好的文本/答案，会把额外帮助混进 treatment。
- **轨迹依赖：**把终点改对再接着跑并非总可行；须能恢复持久环境、消息上下文、工具状态与预算。无法精确恢复的案例单独标 unknown，不能丢弃后再报完整样本。
- **共同原因：**如果父、子错误来自共同的错误数据/语义输入，修父节点可能修复不了子节点；这是待测机制而非自动归为干预失败。
- **算法近邻：**CAR、CausalFlow、EMFA、ReplayRCA 已覆盖通用轨迹级因果干预与修复；若贡献只是把它们用于另一组任务，独立性不足。
- **任务独立性：**至少两个独立数据分析任务族；若只能使用 LongDS 的不同轮次/变体，最多是单基准测量研究，不能声称跨任务稳定。

## GO / NO-GO 门槛

只有在以下条件全通过后，才考虑配对实跑：

1. 完整核验 StateGuard 全文、附录、公开代码/产物，确认它没有已报告的同类父节点纠正效度校准；
2. 找到至少两个许可清楚、可恢复且可独立审查的真实数据分析任务族；
3. 离线协议证明干预只改变指定父状态，且原状态 placebo、采样、工具返回、成本可匹配；
4. 预先定义 DCR 与干预效应不一致的最小实际意义阈值、样本量和系统排序影响；
5. 先在合成已知真值控制上验证估计器，再在真实任务上验证；合成控制不能单独支持论文主张。

任一条件不满足就 **NO-GO**：若 DCR 与干预效应基本一致、差异不改变任何结论、只能在人工改写任务上出现，或已有工作已做同样指标校准，则关闭候选，不通过改名或增加对照重启。

## 当前决定

**HOLD。** 当前完成了从“反复找评分缺陷”转向“检验方法比较的测量边界”的设计修订，但没有新实验结果，也没有独立论文贡献成立。候选须先取得逐任务评分及运行轨迹，证明支持集构成足以改变系统比较；LongDS 数据许可与真实重放能力也未过门槛。不要把“关联不是因果”当成对 DCR 原定义的缺陷，也不进入模型/API 实跑。

## 2026-11-06 复审：修正问题边界与实跑准入

### 对原问题的修正

**裁决：原“DCR 因果效度”表述不作为独立贡献（NO-GO）。** StateGuard 明确将 DCR 定义为观测条件概率差，并称其测量错误依赖下游的关联错误增量；因此指出 DCR 没有随机化父节点，并不能反驳其原始描述性定义。StateGuard 还构造过可执行的反事实状态扰动和修复轨迹，但论文没有据此报告 DCR 对父节点纠正效应的校准。这个未报告项本身仍不足以构成新贡献：若研究只是在 LongDS 上把通用反事实回放用于 DCR，Causal Agent Replay、CausalFlow、EMFA 和 ReplayRCA 已覆盖步骤级干预、前向重放或反事实修复的核心方法。

### 可继续审查的更窄候选：DCR 跨系统比较的支持集可比性

**[事实]** StateGuard 的定义只纳入成功获得二值评分的分析单元；缺失或失败的父节点评分不进入父状态判定，且当 contaminated 或 clean 组为空时 DCR 未定义。每个系统按自身父节点正确性分组，因此跨系统的两个条件组不必包含相同任务/轮次。论文也指出较弱系统可能缺少 clean 组，令 DCR 低或未定义。

**[推断]** 若比较某方法与基线的 DCR，差值可能同时反映子节点错误率变化，以及方法改变了哪些任务/轮次落入“上游错误”组和“上游全对”组。现有公开表格不能区分这两项；这构成一个可检验的“比较解释”问题，不意味着 DCR 的单系统描述性估计有误。

**[合成算术反例，不是基准结果]** 设低/高难度单元中，父节点错/对时的子错误率分别固定为 `0.20/0.10` 与 `0.90/0.80`，两种难度内的父错误关联差都为 `+0.10`。若系统 A 的污染组全来自高难度、干净组全来自低难度，其 DCR 为 `0.90−0.10=+0.80`；若系统 B 的污染组全来自低难度、干净组全来自高难度，其 DCR 为 `0.20−0.80=−0.60`。两个系统在各难度层中的风险差完全相同，但合并 DCR 的方向相反。该例只证明构成混合可以造成排序/符号翻转的数学可能性，不能证明 StateGuard 或任何已发表结果实际发生了该问题。

**候选问题：**在相同任务、模型和依赖图下，StateGuard 相对基线的 DCR 改善，有多少来自相同任务/轮次内条件错误率变化，有多少来自父节点状态与评分可用性改变所造成的组构成变化？分解后，原方法比较或结论是否改变？

**最小、可否证设计：**

1. 以固定的 `task × turn × dependency-map` 为主键，保存每个实验臂的子节点评分、每个父节点评分及缺失原因；先复算论文口径 DCR，并逐臂报告 `|U1|`、`|U0|`、可评分单元覆盖率和任务簇覆盖率。
2. 对配对基线/方法运行作任务簇内分解：将总 DCR 差拆为同一任务/轮次支持上的条件错误率变化与组成员构成变化。预先固定权重；共同支持之外的样本单独列出，不用插补将 missing 伪装成正确或错误。
3. 做一项独立的受控父状态扰动/修正分析，只作为外部效标，检验“支持标准化后的 DCR 改善”能否预测真实下游恢复。将效标与 DCR 的关联和因果效应分开报告；模型重采样、重复轮次不视作独立任务。
4. 主要结果不是 DCR 是否变化，而是构成项是否实质改变方法差值、方向或系统排序，并报告按任务簇重采样的不确定性。

**否证条件：**若论文原始轨迹显示评分支持对所有比较臂完全相同，且依赖错误组的 task-turn 构成差异不足以改变结论；或共同支持/分解结果与原 DCR 比较同方向、差异低于预注册的实际意义界限；或受控扰动结果不能验证测量解释；或已有工作已完整做同类分解，则关闭此候选。仅有合成例子或重算汇总表不能支持论文贡献。

### 可复现与许可审计

- **[事实]** 当前检出的 LongDS 数据集卡将许可证标为 `other`。它要求下载竞赛数据前注册 Kaggle、加入相关竞赛并接受各自规则；发布者将预处理数据限定为教学/研究用途，并要求使用者自行确保不侵犯原始权利。LongDS v1.1 Lite 公布 24 个任务、777 轮；当前 checkout 未发现 LongDS 任务/运行资产。
- **[事实]** DAComp 官方仓库及 Hugging Face 的 DAComp-DE / gold 数据卡标注 MIT；官方 DE 评测器可保留逐任务评测输出，并以 CFS 模式从完整流水线检查各表。它是目前可用的第二个任务族候选；下载后仍需核对具体文件、上游数据来源和冻结版本。DAComp 数据包较大，本轮未下载。
- **[事实]** StateGuard 论文页面及正文没有找到其作者仓库链接或逐任务实验轨迹。发现一个 Hugging Face 上名为 `bmbgsj/StateGuard-RL` 的公开 checkpoint，页面账号显示名为 “zhao wang”，权重约 16.4 GB，模型配置为 Qwen3 8B BF16；但仓库无模型卡、无许可证声明，论文也未链接该账号，故不能据此确认它就是可合法复用的论文官方 checkpoint。仅账号同名不是作者身份或实验血缘证明。
- **[事实]** 当前机器检测到的 GPU 显存约 12.2 GiB，低于该 BF16 checkpoint 单是权重文件的约 16.4 GB；不能原样常驻 GPU。CPU offload 或量化会改变运行条件，需作为单独的复现偏差记录，不能冒充原设置。
- **[事实]** 当前 Python 环境没有 `torch`、`transformers`、`huggingface_hub`、`vllm` 或 `llama_cpp_python`；系统也没有 Hugging Face CLI、Ollama 或 llama.cpp 命令。GPU 存在，但本机目前并没有可直接复现实验的模型运行栈。本轮没有安装依赖或下载模型。
- **[结论]** StateGuard 论文级轨迹仍无法从公开材料重算。现实的独立复现路线是：先用 DAComp-DE 建立许可明确的任务/逐表结果管线，再在确认 LongDS 源数据规则后加入 LongDS；模型可用性必须先解决权重许可证/来源与可复核运行协议。若不能确认 checkpoint 权利，则只能选许可证清楚的公开基座并将研究问题改为跨系统测量效度复现，而不能声称精确复刻 StateGuard。

### 研究门槛裁决

**当前状态：HOLD；没有独立论文贡献成立，也不进入模型实跑。** 候选已有一个实质的数学动机（合成支持集反例）和 DAComp-DE 的许可清楚的第二基准路线，但尚无任何真实数据支持集分析，也未证明排序或结论实际变化。本机目前没有模型运行栈；StateGuard 权重许可证与 LongDS 数据使用条件也未确认。下一步先冻结 DAComp-DE 与 LongDS 的逐表/逐轮结果 schema、固定共同支持与缺失处理规则，再决定是否值得建立隔离的本地推理环境并获取许可清楚的模型/数据。只有这些完成后，才做有限开发集实跑并预注册跨任务验证。合成算术反例、公开汇总表或单一基准结果都不能单独支持论文贡献。

### 2026-11-06 共同支持近邻复核与剩余差异

**[事实]** Huang, *What Does an LLM-Agent Leaderboard Rank Actually Compare?*（arXiv:2609.07785v1）已经给出 Agent 配对比较流程：先明确目标估计量，再检查系统间共同支持，在支持单元内做直接标准化，并按任务/报告单元的重复结构计算不确定性；其经验分析覆盖 SWE-bench、AgentRewardBench、τ²-bench，并说明公开数据粒度限制可识别结论。该工作是本候选“支持不一致会改变跨 Agent 比较”的直接方法基线，不得把共同支持、重加权、成对 bootstrap 或排序变化本身声称为创新。来源：[论文 §III、§V](https://arxiv.org/html/2609.07785)。

**[事实]** Hardy et al., *Agent Evaluation Reliability: More Tasks Won’t (Always) Fix An Agent Leaderboard*（arXiv:2610.00651v1）以 G-theory 对任务、benchmark、模型与 scaffold 的变化作方差分解，并讨论重复任务无法消除的异质性与任务簇不确定性。一般的“跨系统结果可靠性/不确定性”也不是候选增量。来源：[论文](https://arxiv.org/html/2610.00651)。

**[有限范围推断]** 在上述两篇论文已检查的定义和方法范围内，比较单元主要按运行前可识别的 benchmark、domain、repository、task 或 scaffold 条件组织；本次未见其专门处理 DCR 的 `c=1/0` 分组。DCR 的 `c` 则由每个系统运行后实际观察到的父节点评分和缺失状态共同决定，是 system-specific 的后运行变量。因此可能剩下的窄问题不是“普通 common support 是否有用”，而是：配对 Agent 运行中，各任务/轮次在 clean、contaminated、不可评分三种状态间的**成员迁移**，是否足以改变 DCR 的跨系统差值；分离成员构成变化与同一预先固定任务/轮次上的子节点错误变化后，结论是否改变。这个描述仍是候选，未证明为统计新方法或独立科研贡献。

**强基线与退出条件：**任何实证必须先实现原生 DCR；其次实现 Huang 式任务/benchmark 共同支持与目标标准化、任务簇不确定性；再对配对运行中的 `(c_A,c_B,e_A,e_B,missing_A,missing_B)` 作透明分解，并将父节点纠正重放仅作机制外部效标。若成员迁移分解等价于常规标准化/分层分解、没有改变预注册的比较结论，或仅靠事后选择支持单元才产生差异，候选即 NO-GO。不得以给常规分解另起名字来保留主张。

**当前决定：HOLD。** 公开复现仓库没有输出、StateGuard 作者逐任务记录未找到、标准 Agent 排名工作已覆盖绝大多数比较方法；候选尚无真实逐任务证据。下一步需要在不付费的新运行之外，先确定是否存在可合法复算的公开配对轨迹。若只有聚合表，本候选无法验证，须转向有公开原始评分/重复系统输出的任务来源；新 API/完整基准调用仍需独立预算准入。
