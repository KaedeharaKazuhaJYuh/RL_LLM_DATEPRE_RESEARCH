# Reliability Reset 1.0.35：从提示收益走向证据与终止的联合规划

日期：2026-10-24。分支：`agent-eval-reliability-reset`。

## 本轮完成

完成[四组提示成分实验与自动证据规划实验](PLANNING_MECHANISM_135.md)：**48 条真实 DeepSeek 轨迹、12 个后台规则控制、155 次实际请求**。155 次均收到响应，无解析失败、无供应商错误；模型返回名均为 `deepseek-flash`。

新增一个可运行的公开证据规划器：按工具返回字段与检查成本，精确枚举能覆盖当前证据需求的读取组合，并给模型建议。它不把 inspect 写成规则答案、不替模型执行动作、不生成数值或发布参数。读取工具更名后仍能运行，转换只作用于动作及工具引用，业务数据原样保留。

## 成分实验：两种提示作用不同

三个 01 历史实例 × 健康/语义错误状态，检查预算均为 1；四臂提示采用相同基础指令和等 UTF-8 字节的两个文字槽。

| 提示臂 | 首选 inspect | 安全完成 | 总 tokens |
| --- | ---: | ---: | ---: |
| 背景对照 | 0/6 | **0/6** | 6,568 |
| 仅额外预算强调 | 3/6 | **3/6** | 12,642 |
| 仅信息包含关系 | 6/6 | **2/6** | 23,227 |
| 两者结合 | 6/6 | **6/6** | 20,414 |
| 共享后台规则 | 6/6 | **6/6** | 0 个模型 tokens |

信息关系说明让六个单元都选对首步，但其中四条仍在正确发布后申请 status，触发预算拒绝。额外预算强调改善了部分首步选择，同时有三条在已花掉唯一检查后升级，未完成任务。

组合提示的三个语义故障任务均完成 inspect → stage → publish → stop，三个健康任务也正确停止。它相对仅信息说明不仅完成更多，本轮总 tokens 还降低约 **12.1%**。

六个任务/状态块的描述性交互 `(combined - budget_only) - (relation_only - context)` 依次为 `1, 1, 0, 0, 0, -1`，合计 1。这里的预算因素是原基础指令之外的额外强调；该小实验支持继续研究两种作用的配合，不把六个块当作独立同分布总体来计算显著性。

## 自动方法：接口迁移已接通，收益尚不均匀

三个 03 额外开发实例 × 两种状态。两种接口分别使用原读取工具名和 query_a/b/c/d；每个接口的两臂看到完全相同的结构化公开工具契约，auto_plan 另加自动规划建议。

| 接口 | 仅结构化契约 | 契约＋自动规划 | 配对收益/退化/持平 |
| --- | ---: | ---: | ---: |
| 原工具名 | 1/6 | **2/6** | 2 / 1 / 3 |
| 不透明别名 | 3/6 | **4/6** | 1 / 0 / 5 |

24 条迁移轨迹全部先调用实际 inspect，说明从公开契约选择读取和别名映射已接通。自动规划相对结构化契约净增加两次完成，但存在一个原接口退化案例；没有达到一个可直接替代模型控制过程的成熟策略。

规划器本地微基准为五批、每批 1,000 次调用，中位耗时约 **9.76 微秒/次**，无需额外模型请求。它目前只覆盖四个读取工具、至多 16 个组合；这不是完整实验时延或硬件能耗测量。结构化契约及规划提示的真实模型 token 成本保留在结果中。

## 新发现：修复成功与正确终止是两个能力

对冻结轨迹进一步定位失败发生的位置，得到以下**事后描述性分析**，不替换预先指定的主要完成指标：

- 48 条模型轨迹中，**43 条最终物理状态正确，21 条满足安全完成**。
- **16 条**在成功发布、当前报告正确之后又请求额外读取，最终超预算。
- 另有 **5 条**在已有正确状态下超预算，以及 **1 条**在正确状态下选择安全升级。
- 所有模型和规则执行均未出现被确认的新增错误发布、重复发布或输入篡改。预算拒绝的读取未执行，不能把这 22 条“终态正确但未完成”统称为安全事故。

终态与完成的差异已经被现有完整评分捕获，本轮不是发现旧评分器的新漏洞。新增价值在于可复核地定位真实行为：部分模型已经有正确的语义修复结果及成功发布回执，却仍未在资源边界内停止。具体单元、最终提案、事件位置和证据索引保存在证据包的 `FAILURE_LOCATIONS.json`。

这使后续目标从笼统的“多检查一点更可靠”，转为：**在证据获取、正确修复和停止三个阶段，如何联合分配动作，并识别已经足够的证据？**

## 成本、实现与复核

输入 171,588 tokens、输出 3,256 tokens，总计 **174,844 tokens**。按 2026-10-24 核对的 [DeepSeek 官方峰值未缓存单价](https://api-docs.deepseek.com/quick_start/pricing/)估算 **$0.0553836**，低于 $0.60 设计上限；这不是供应商账单。

- `evidence_planner.py`：公开字段覆盖、预算可行性及按检查次数/字节估计排序。
- `planning_mechanism.py`：四组实验、结构化契约、别名接口、原始响应绑定及离线重放。
- 客户端按每次实验实际公布的工具名严格解析，未放宽为任意动作，也不把模型错误静默修正。
- 48 条模型轨迹逐条离线重放，155 条响应重新解析并核对动作映射；状态、完整原生评分、独立判断、终止和成本一致，无新增 API 调用。
- 所有 60 个模型/规则执行的原生判断与独立 Fraction/CSV/SQLite 判断一致。
- 全仓测试共 997 项：**994 项通过、3 项条件跳过，零错误/失败**，用时 344.825 秒。跳过的是未配置的第二解释器以及两项未编译的可选 native 库测试；继承发布元数据检查通过。

最终测试记录与哈希见 [VALIDATION_135.json](VALIDATION_135.json)。[完整脱敏证据包](evidence/1.0.35/deepseek-planning-mechanism-1.0.35.zip)和[公开校验记录](evidence/1.0.35/PUBLIC_RECORD.json)保留提示、请求、响应、SQLite、CSV、源码快照、公开契约预检、失败定位和来源说明。

## 下一版 1.0.50：联合规划取证与停止

遵照版本规则，1.0.35 后跳过 1.0.40–1.0.49，下一版为 **1.0.50**。

1. 在自动证据规划之上加入预算可行动作集合：清楚展示哪些操作仍可执行，让模型在真实剩余资源内选择，而不是替它强制 stop。
2. 区分首次取证、候选校验、发布确认和停止；显式记录写入后哪些旧证据仍有效、哪些需要更新。当前简单覆盖规划器还没有完整的写入后证据有效期机制。
3. 比较组合提示、自动读取规划、联合动作规划；重点看本轮 16 条“正确发布后仍超预算”轨迹揭示的现象是否减少，同时保留错误停止和过度升级对照。

这些比较仍先使用小规模、固定的开发实验；本轮没有训练权重。方法引用与已有工作位置在[设计文档](PLANNING_MECHANISM_135.md)中说明。新的 03 实例也曾用于离线开发，三种分析意图仍共享一个环境。
