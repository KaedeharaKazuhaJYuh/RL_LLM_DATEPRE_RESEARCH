# 三份评估的回应：已见切片、终止分类与检查价格

2026-10-28。两份材料来自不同来源：一份跨分支评估，一份 Word 评估；后者明确说明只读过文档，没有审查代码。这里采用可核对的建议，并对不受证据支持的推论作更正。来源不同不自动证明两份均为独立人工审阅。本轮没有模型/API 调用，也没有新增模拟训练或任务环境运行。

两份评估的侧重不同：跨分支评估建议先利用 VeriCost 的 DP 和已见切片，探索检查价格；Word 评估侧重诊断与动作、安全副作用的区分，并建议未来增加真实修订数据、代码执行接口和独立来源。两者都指出现有工作缺少独立任务与跨模型证据。前者关于价格研究空白的绝对判断、后者关于 RL 失败由数据规模造成的解释，尚不能直接采纳。

第三份晚间推送审查核对了 0.5.66 与终止分类。依据冻结逐条数据，本次修订了[分类说明](TERMINAL_TAXONOMY.md)中的非完整交叉设计和责任措辞；复核命令已改为默认只读，并拒绝覆盖现有输出。对于 `k0.30_L1` 的 LinUCB 反例及分别训练策略的两点价格比较，已更新[0.5.66 报告](../../faultda_bench/reports/RELEASE_0566.md)而不改原数值；该报告同时澄清 0.5.65 已包含可汇总的逐来源学习结果。晚间报告提供的是另一个评估视角，不自动等于独立科学验收。

已把 CostBench、CAM-DF、ACL VoI 及既有定价干预纳入[近邻比较](../../faultda_bench/docs/NOVELTY_AUDIT_2026_10_27.md)，并形成不运行模型的[外部试点方案](EXTERNAL_PRICE_PILOT_2026_10_28.md)。由于原生计量记录尚不覆盖所有需审查的事件，试点尚未具备实跑资格；论文主张仍为 HOLD。

## 先做了什么

跨分支评估建议把 `q_only`、Thompson、LinUCB 和固定规则放到 DEV-SEEN 的 `k1.00_L3` 上比较。这些分来源结果其实已存在于 [learned_eval.json](../../faultda_bench/reports/vericost565/learned_eval.json) 的 `per_cluster` 中；本轮按原实例清单选出 3 个已见来源的 24 个 profile，求和后除以 24，再与 [Gate 0](../../faultda_bench/reports/vericost565/gate0_rev1_dev.json) 的同一集合和 regime 核对。**这是既有开发结果的事后汇总，不是新训练或独立测试。**

| 策略 | 期望效用 | 相对 DP 的归一化 regret | 与预注册规则族最优值的效用差 |
| --- | ---: | ---: | ---: |
| 精确 DP | 0.280302 | 0 | +0.050478 |
| F_hist（规则族最优） | 0.229824 | 0.180086 | 0 |
| Thompson | 0.229824 | 0.180086 | 约 0 |
| LinUCB | 0.223360 | 0.203145 | −0.006464 |
| Q-only | 0.171772 | 0.387191 | −0.058052 |
| F_hist_plus（更大规则族，参考） | 0.234437 | 0.163627 | +0.004613 |

`regret = (E[U*] − E[U]) / E[U*]`。因此 0.180086 是相对于**模型中 DP 期望效用**的归一化差距，不是实测业务收入提升 18%；F_hist_plus 在该集合有 66 个单元，F_hist 有 3 个单元，两者的规则容量不同。DP 的最优性以该环境、故障先验、动作及成本模型为条件，不等于真实 Agent 的全局最优。

保留的 Thompson 策略在此设置的三个已见历史单元恰好选择与 F_hist 相同的规则；Q 的未见状态回退所用映射也与 DEV-SEEN 的三个单元一致。`bf` 在这三个来源的效用之和与 Gate 0 的 F_hist 结果一致。已有训练使用开发数据；**24 个 profile 来自 3 个已见来源，不是 24 个独立来源，也不是 LLM 样本**。上述差距不支持泛化或统计显著性。

为避免只挑一个价格，还检查了原记录中 L=3 的四档 κ；期望效用如下：

| κ | DP | F_hist | Thompson | LinUCB | Q-only |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0.03 | 0.970909 | 0.970306 | 0.970306 | 0.969246 | 0.525375 |
| 0.10 | 0.903029 | 0.901019 | 0.901019 | 0.900801 | 0.554116 |
| 0.30 | 0.710173 | 0.703056 | 0.703056 | 0.697903 | 0.546155 |
| 1.00 | 0.280302 | 0.229824 | 0.229824 | 0.223360 | 0.171772 |

这些是不同价格下各自已有的策略结果，不是模型对价格变化的行为弹性。另一个事后观察：在 κ=0.30、L=1 上，LinUCB 效用 0.734790 略高于预注册 F_hist 的 0.733914，但更大 F_hist_plus 为 0.736827；该差异不能当作独立正结果或据此事后做显著性推断。

## 修正已见集合选择

冻结版 `policies.evaluate_learned` 在未显式给出 `profiles` 时只对 `dev_syn` 做了过滤；直接传入 `instance_set='dev_seen'` 会选到全部 30 个 profile，其中 6 个是合成数据。模拟空评分器的软件检查已确认该选择行为；历史按 `all` 生成的文件没有因此被改写。

新增 [seen_evaluation.py](seen_evaluation.py) 在调用旧评估器时显式传入 24 个 `seen_development` profile，空集合直接报错，防止旧入口把空集合回退成全部数据。该入口保留原评分器及冻结源码；要重算时还需原有证书和运行时。本轮只检查了集合选择，没有运行完整策略评估。不要直接依赖旧入口的默认 `dev_seen` 筛选。

需要重算时，可以显式使用 `evaluate_seen(regimes=('k1.00_L3',))`；这会执行 CPU 枚举，不是本轮的只读汇总。

## 对两份建议的取舍

- **采纳：**将价格条件下的效用、检查成本和强规则对照作为可探索问题；优先利用已保存的分来源结果，并计划未来真正不同环境、模型与来源的验证。原生分数和新成本效用应并列保留，不能把更换效用后的排序直接称作原基准评分错误。
- **修正新颖性表述：**[Judged Useless, Queried Anyway](https://arxiv.org/html/2610.06191v1#S4) 已让模型看到每次调用的价格，附录还按多个价格对已有轨迹重计效用并比较简单停止策略。不能称已有研究只把成本当约束、从未为调用定价；该论文的固定价格干预和事后重计，与完整价格扫描的行为干预不是同一实验，也不能据此断言后者已经或尚未发表。
- **补充 Word 评估提出的近邻：**[ToolBench-X](https://arxiv.org/abs/2606.25819) 研究可恢复工具故障，[RADAR](https://arxiv.org/abs/2609.32528) 研究数据分析中的静默语义错误及运行时反馈，[Ambig-DS](https://arxiv.org/abs/2605.09698) 研究数据科学任务表述的歧义。它们与提交状态故障并非完全相同，但会影响诊断、语义检查与可靠性机制的原创性比较；本轮核对原文入口及摘要，没有复现作者实验。
- **不预设弹性：**有限动作环境的最优策略可能随价格分段切换；检查次数、计费量和安全收益也不是同一指标。不能预先断言弹性落在 −1 到 −2、检查次数必然单调下降，或把一次排序变化自动解释为评测误判。
- **对照与统计：**固定规则和更大规则族要保留，公开信息与工具权限须说明；开发集只按 3 个来源理解，不把 24 个切片当作 24 个独立样本。对于未来二元配对结果，精确 McNemar 的独立配对假设也要与来源聚类及多重比较一起考虑。
- **暂缓扩张：**新来源、代码执行轨道、多模型、外部基准和 RL 再训练均属于后续研究设计，当前没有足够证据证明其预算、样本量或论文收益。现有 RL 退化原因不能仅凭其中一份评估确定为数据量不足。已有人工复审的身份及来源仍按原记录保留，不因本次外部意见更改。

## 下一项可否证的研究问题

在固定任务与工具权限下，若只改变**明确呈现给模型的价格参数**，模型的实际检查行为和效用相对同信息强规则及模型内 DP 会如何变化？先明确价值函数、公开先验、价格归一化、规则族、可得工具和独立任务单位，再审查与上述近邻、[AFT-Bench](https://arxiv.org/html/2608.23628v2) 和[面向人机沟通的信息价值框架](https://arxiv.org/abs/2601.06407)的实质差异。该问题是候选，不是已证实的新机制。

如果价格不呈现给模型，仅事后重计轨迹效用，只能研究评分敏感性，不能推断行为弹性；如果价格变化导致不同效用下的策略合理排序改变，也不自动说明原评分错误。未形成明确差异、合适独立任务和成本计划前，不启动付费模型实验或扩源。论文主张仍为 HOLD。

下一步的最小设计：先在已有 AppWorld train 链上核对任务、工具及记录能否接入同一个价格字段，保留不带价格提示的对照和原生完整分数；再针对一条开发任务定义正常状态、可核对的公开价格及强规则对照。价格条件除数值字段外共享提示模板、权限和预算。初次运行只检验接口、故障是否实际触发及费用记录是否完整，单任务结果不用于估计模型弹性或声称排名反转。只有这些条件可执行且相对近邻的差异明确，才制定来源级扩展、预算和统计方案。

方法来源：评审采用 Scientific Agent Skills 的科学批判与统计分析流程；Kassis 等（2026），[Scientific Agent Skills](https://doi.org/10.48550/arXiv.2609.00065)。其用于组织判断，不是独立审稿或结果认证。
