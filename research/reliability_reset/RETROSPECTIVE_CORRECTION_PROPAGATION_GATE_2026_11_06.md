# 候选研究设计门槛：追溯更正后的分析发布状态

日期：2026-11-06  
状态：**已关闭为独立论文主张（NO-GO）；该判断针对当前候选，不表示相关工程问题不存在。**

## 一句话研究问题

> 当外部数据在分析报告发布后被追溯更正时，Agent 是否能同时保留“按当时已知信息发布的历史报告”并修复“按当前已知信息应成立的下游分析”，而常见终态答案评分是否会漏掉这类状态错误并改变系统比较？

这不是“数据会变化”“Agent 需要状态图”或“要做增量计算”的新提法。候选增量只在一个待验证的交叉条件上：**事实有效时间与系统获知时间分离 + 已持久发布的分析对象 + 同一依赖链上历史复现与当前修复两种并存语义**。是否尚未被直接近邻完整覆盖，当前只能说“在本次有限检索的已读范围内未看到同一评测契约”，不能声称首次。

## 可证伪假设

**H1（测量影响）**：在任务契约明确区分 valid time 与 record/knowledge time 的条件下，只按最终当前答案评分，会把“当前答案正确但历史报告被覆盖或下游结果未修复”的运行判为成功；加入历史可复现性与依赖修复证据后，系统排序或实践决策会发生可复核变化。

**H2（任务结构影响）**：上述差异随更正位置和依赖链结构系统变化；如果全部差异都可由普通新鲜度错误、一般分析错误或不可达/含糊的保存语义解释，则候选关闭。

两个假设均未实测。H1 为主假设，H2 是机制诊断，不应分别包装成多项贡献。

## 与直接近邻的边界

| 工作 | 已直接覆盖 | 对本候选的约束 | 尚待核实的窄差异 |
|---|---|---|---|
| TimeSage-EV | 周期性释放的时间序列、按时点隔离证据、历史截止有效性、独立/顺序运行 | 不能把“时间截止下的回答可靠性”当创新 | 是否评分在源修订后已发布分析对象的历史保留及当前后代修复 |
| ChurnBench | 多源变更账本；按当前时点与实际取数时点区分 freshness error | 不能把变化数据、新鲜度、双时点账本或成本对照当创新 | 论文公开契约主要评价查询答案；已发布的分析报告及其版本化后代是否作为持久副作用评分，待逐代码核对 |
| StateGuard | 分析状态图、版本化变量、依赖传播、有效性检查与修复；其反事实分支保留原已提交状态 | 不能把分析依赖、状态有效性、修复或“旧状态不被覆盖”单独当创新 | 其测试干预是分析假设/公式/过滤条件改变；是否研究来源事实的追溯更正及双时点发布语义，需逐节与代码再核对 |
| LongDS-Bench | 长程分析状态继承、更新、恢复、组合与重置对照 | 不能以多轮数据分析或状态更新作为增量 | 已读的 reset 研究未显示来源更正后持久发布对象的双时点评分；不等于完整排除 |
| Bitemporal agent-memory work | 事实的 valid-time / record-time 表示及历史时点检索 | 不能以 bitemporal QA 或记忆本身作创新 | 是否包括可执行分析依赖、外部提交的报表及后续修复归因，尚需核验一手论文/官方实现 |

## 原始任务契约与最小实例

一条任务包含：

1. `t0`：来源事实 `x` 被记录；Agent 计算 `y0=f(x)` 并发布带输入版本与发布时间的报告 `R0`。
2. `t1>t0`：来源方发布追溯更正 `x'`，其有效时间早于 `t1`、记录时间为 `t1`。
3. 任务同时要求：(a) 重建“截至 `t0` 当时可知信息”的 `R0`；(b) 按截至 `t1` 新获知的信息更新当前报告 `R1`；(c) 正确标记受影响的下游对象；(d) 不静默改写 `R0`。

每个子项都必须写进用户任务/系统公开契约并可由工具实际观察。若只有评分器暗含要求、任务没有告诉 Agent 保留历史，违反即不得作为 Agent 违规；这种情况只能评估评分器设计，不能归责给模型。

## 最小有判别力的实验（设计，不是已完成实验）

- **对照系统：**同权限 Agent；完整重算的强规则；依赖感知的确定性规则；不刷新规则。统一任务、工具、交互/计算预算和提交接口。
- **任务因子：**更正类型（值更正 / 延迟记录）、更正位置（根输入 / 中间派生值）、依赖结构（单层 / 多层 / 分支共享）、请求语义（历史快照 / 当前状态 / 双时点）。只把脚本生成变体当配对条件，不计为独立任务族。
- **指标：**当前结果正确；历史报告可按当时可知快照复现；当前下游结果正确；受影响对象修复 precision/recall；不受影响历史/并行对象误改率；重复发布/覆盖次数；成本与耗时。
- **主要对比：**原终态评分 vs 双时点持久对象评分的配对系统排序变化。不得只报告新增指标不同于 0；须说明它是否改变系统选择，按独立任务簇计算区间。
- **负对照：**无更正；不影响分析结果的元数据更正；明确要求“只问当前状态”的短任务；要求历史快照且输入版本未改变的任务。
- **最小来源要求：**至少两个真正独立的数据/工作流任务族，任务来源、许可、真值构造和任务契约可审；一个族只用于开发，一个或多个冻结族用于确认。样本量按任务簇与预设最小有意义排序变化确定，不能现在臆造具体数目。

## 进入实跑的门槛

全部满足才转为 GO：

1. 从 TimeSage-EV、ChurnBench、StateGuard、LongDS 及 bitemporal agent-memory 直接论文/代码逐项确认，候选的四项联合语义没有被现有任务与指标直接覆盖；
2. 至少找到两个许可可用、具有真实来源血缘或可公开复核来源的独立任务族；合成部分须标为合成，不能替代独立来源；
3. 证明 Agent 可通过公开工具实际观察来源更正、已发布对象与依赖关系；每项被评分的责任均在任务契约中明确；
4. 离线构造反例显示“当前终态答案相同，但历史持久副作用不同”，且两套评分确实给出不同判断；这只是指标可区分性，不是模型实证；
5. 冻结强规则、成本、任务簇、排除与统计方案，并给出可负担的样本量和 API 成本后再作执行决定。

## 关闭条件

- ChurnBench 或 StateGuard 的已发布材料已直接覆盖相同的追溯更正、历史发布保留、下游修复和终态评分交互；
- 任务只靠未告知的历史保留义务区分好坏，或不能从运行记录中确证 Agent 的责任动作；
- 双时点评分不改变任何配对结论/系统选择，或差异由普通新鲜度错误完全解释；
- 找不到两个独立且许可清晰的任务族；
- 相同条件下强规则完成全部工作且 Agent 结果没有诊断价值。

满足任一项即关闭主张；不能通过继续增加任务变体、指标名或版本号挽救。

## 当前决定

**NO-GO，关闭为独立论文主张。** StateGuard 不只覆盖抽象的依赖状态修复：其正文直接以 COGS 来源值被修订为例，创建链接旧状态的新状态、标记旧派生结果失效并定点重算；其运行时还将已提交状态设为不可变。TimeSage-EV 和 ChurnBench 又分别覆盖按时间截止的分析证据，以及按取数时点/评估时点区分新鲜度。因此候选的主要机制已被近邻覆盖；剩余的双时点术语差异不足以单独支撑论文贡献。该结论不声称这些工作的评分器完全相同，也不否认不同真实系统存在相关工程风险。
