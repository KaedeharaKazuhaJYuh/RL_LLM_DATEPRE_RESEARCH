# τ²-bench 已发布轨迹：程序确认规则重分析

日期：2026-11-06  
状态：**计算性复核完成；无排序变化；不构成新机制或独立顶会增量。**

## 研究目的

**[事实]** 本研究线此前缺少不同任务族中的原生满分案例。上游 τ²-bench Issue #298 和独立仓库 `llmcontract-tau2` 已经报告，在已发布客服 Agent 轨迹中，存在原生满分但违反政策“先说明写操作并取得明确用户确认”的轨迹。

**[待补]** 本次只问一个更窄的问题：独立重算该既有事件顺序标签后，把已确认违反显式确认规则的原生通过扣除，是否改变两个域内的模型成功率次序？不重新主张此类违反首次被发现。

## 数据和方法

- **[事实]** 只读取 τ²-bench GitHub 快照 `033bf082f48e4a3c6a1256208e93cf2ce9c3bb6f` 中 8 个 retail/airline 已发布的 4-trial JSON 文件；不执行任务环境、Agent 或模型，不调用 API。
- **[事实]** 轨迹文件自身记录了两个不同的运行代码提交：6 个文件为 `c30d59aaa71c65f9b9eb6a8f8636b48945028fcf`，GPT‑4.1 mini 的 2 个文件为 `ade39493be54aad326a4c65295f77fe09780329b`。本次未能从上游当前可访问历史取回这两个旧代码提交的源码快照。
- **[事实]** 使用独立实现的简化有限状态扫描器：助手调用一旦属于零售/航空写工具即记为 `Mutate`；用户消息若包含宽松肯定词集合则记为 `UserConfirm`；任意首次肯定将会话切换为“已确认”，之后写调用不再标违规。该映射刻意复刻上游 LLMContract 报告的宽松、永久确认状态，不评价确认内容是否绑定到具体对象、金额或操作。
- **[事实]** 写工具集合和肯定词规则来自配套公开研究的协议映射。对每条轨迹保留上游 `reward_info.reward`；分别计算原生 pass 与 fail 中发生该事件顺序违规的条数。**调整后通过数 = 原生满分数 − 观察到的满分违规数**，不修改或重算原生评分器。
- **[待补]** 原始运行提交对应的 task/policy/tool 源码仍需人工核对。当前仓库快照与各轨迹文件内的 `git_commit` 不同；因此这次结果是对公开归档数据及公开标签规则的计算性复核，不是对原运行版本的完整源代码取证。

**[事实]** 重算结果与上游公开报告相符：11/1,755 条原生满分轨迹、13/869 条原生非满分轨迹被该规则标为违规。Retail 原生通过数的观察结果组次序为 Claude 3.7 Sonnet > GPT‑4.1 > o4-mini > GPT‑4.1 mini；调整后仍相同。Airline 原生通过数的观察结果组次序为 o4-mini > GPT‑4.1 > GPT‑4.1 mini > Claude 3.7 Sonnet；调整后仍相同。该次序不等于受控模型能力排序：GPT‑4.1 mini 使用不同的 `base` 配置，且记录了不同运行代码提交。

**[事实]** 原生满分改为调整通过的绝对变化：零售 Claude −3/456、GPT‑4.1 −4/456、GPT‑4.1 mini −2/456、o4-mini −1/456；航空 Claude −1/200，其他三组为 0。此次在该既有规则下没有观察到域内结果组次序翻转。

**[推断]** 这个结果说明该数据集中的特定规则违规存在，但本次重算没有显示其改变观察到的结果组次序。它不证明模型排序普遍稳健：结果只覆盖两个域、固定旧轨迹与一个单调扣分规则，也没有纳入任务级独立性、成本、抽样不确定性或强规则基线。

## 先行工作与科学边界

- **[事实]** τ²-bench Issue #298 已公开报告同一语料上的 11/1,755 和 13/869 计数、模型/域明细及样例轨迹；配套仓库发布同一确认规则的离线重放代码。因此事件本身、估计量及核心程序监控机制都不是本项目的新发现。
- **[事实]** τ²-bench Issue #384 另报告空评分条件和未进入 reward basis 的书面条件，并在后续评论更正了 no-op 任务计数。这说明仅根据任务字段或 issue 初稿归纳错误有误判风险，必须对固定任务版本、评分 basis 与原生 evaluator 同时核对。
- **[推断]** 这次排序重算是对同一公开结果的独立代码实现，并非独立数据收集、独立标签团队或独立实验室复现。它只能加强对已有计算结果的可复核性。
- **[推断]** 当前的永久确认状态可能比政策逐次操作语义更宽松，但“确认是否逐次绑定到写操作”“批量确认覆盖哪些操作”必须回到原任务文本和轨迹进行盲审；本报告未据此改写违规分子，也没有将它作为新候选贡献。
- **[结论]** FaultDA-Bench 的科学状态维持 **HOLD**。跨任务证据缺口部分缩小：公开 τ²-bench 轨迹带来另一个 benchmark 及模型/域切片，但相同主张已被先行工作直接研究，且本次没有排序改变、强规则对照或独立人工标签。不能把它作为创新性 GO 的依据。
