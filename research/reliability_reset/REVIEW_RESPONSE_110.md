# 1.0.05 外部代理审阅复核与 1.0.10 修订

日期：2026-10-23。来源为用户提供的 `REVIEW_105_INDEPENDENT_2026-10-23.md` 与 `review_filled_2026-10-23.csv`。原记录明确自述“我是代理，不是人”；本项目登记为外部代理技术意见，不登记为真人独立科学验收。原件另存并按字节记录哈希，结论、异议和局限均保留。

本轮对原始材料重新复算，并修正工程问题。旧 1.0.05 的数据、原评分器输出及验证记录不被覆盖；1.0.10 在新目录生成显式标注的工程派生控制，不增加新的独立来源、模型结果或科学准入。

## 对十条发现的核对

| 原发现 | 本项目复核 | 处理 |
| --- | --- | --- |
| 1：只覆盖一条主体违规规则 | 成立：旧输出事件仅有 incorrect_publication | 新增 append 后修复控制，验证 duplicate_active_reports；按规则列阳性执行数 |
| 2：输入修改规则无法由公开工具触发 | 在受限工具接口下成立；宿主/外部篡改仍可能发生 | 移出主体禁止规则，单列 assessment_integrity_monitor；失配时事实保留未知，不归罪主体 |
| 3：v1/v2 数值相同导致版本不可测 | 字节相同成立；“完全不可检测”过强，旧参考还检查版本标识及绑定哈希 | 仅在新工程派生中给 v2 首值 +1，增加错误版本发布后修复控制；原始 task manifest 不变 |
| 4：缺少数据库/分布式系统文献 | 成立 | 补入线性一致性、事务恢复、SQLite 原子提交与历史检查工具；明确没有做真实崩溃或并发验证 |
| 5：16 次执行只有 7 种行为签名 | 复算成立，签名忽略程序来源名称但含动作/参数/响应、最终记录和终止 | 报告执行数、行为分组、单一来源家族；不将签名数当独立样本量 |
| 6：正常臂的 agent_error_repaired 实际无错误修复 | 行为复核成立；旧派生标签本身按事实仍为 reliable_success，没有从条件名生成违规 | 更名 publication_intervention，表示压力臂施加干预的机会；另存实际发布次数与动作签名 |
| 7：14/14 是 13 阴 + 1 阳 | 成立；恒预测阴性也可有 13/14 表面一致率 | 新记录分列相对旧 oracle 的 TP/TN/FP/FN/unknown 和恒阴性对照；不称独立有效性或泛化精度 |
| 8：缺失终止抓取却仍给确定终端值 | 表述需要区分快照事实与终止证据，旧命名确实易混 | 新增 snapshot_correct；抓取不完整时 terminal_correct/termination_action 为 null；原运行评分保留并单列 |
| 9：审阅包直接暴露条件和臂身份 | 成立，旧 state.evidence 还暴露派生事件标签 | 旧式包明确标为第二轮非盲核验；首轮归一化视图去除条件/臂名称、派生 state/reference/facts/grade，私有映射另存 |
| 10：终态正确性无方差 | 旧物理快照 16 条均正确成立；但原 contract_complete 实为 14/16，不是审阅文字的 16/16 | 保留原稿异议并更正事实；新加未修复错误终态控制，限定为工程校验 |

第 8 项的原始位置也需更正：旧确定终止来自 `native_trace.json.terminal`；旧 `trace.json` 没有 `terminal` 字段。原 oracle 在完整运行时得到的结果不是之后删掉抓取就被改写的历史事实，故保持原样；新提取器只报告当前证据能支持的终止状态。数据库快照本身仍可支持 snapshot_correct，这与缺少 stop 证据可以同时成立。

## 最小工程修订范围

原范围保留健康、环境错误修复、提交前/后超时、修复回执丢失、公开状态未知、抓取不完整等控制。新派生仅补齐：数值不同的 v2、重复发布后修复、错误版本后修复、错误终态、空值排除。主体仍是同权限的公开规则程序与刻意压力程序；压力臂不是模型基线。

主体 actor 统一为 `subject`，另设 `actor_kind=programmatic_driver` 和原始程序来源。环境初始化单列记录尝试及失败反馈，不把失败尝试编造成持久写入，也不把环境初始责任转给主体。旧环境原始 oracle 中的 `agent` 是其接口角色，保留原记录并说明映射，不宣称有模型动作。

## 对独立性与科学路线的处理

收到的是有价值的代理技术审查。其本人未读项目源码、未读相关论文全文、未访问候选仓库，不能据此宣布完成独立人审、穷尽查新或“所有后续问题均不存在”。这些局限保留在原件中。

本轮修复不改变当前宽泛研究主张 NO-GO 的判断。科学状态 HOLD，付费/API 预算 0；当前工程版本的人工技术复核与独立科学意见仍 pending。任何未来研究重启都需要具体的新假设及来源、完整旧指标、成熟系统方法的直接对照，不能把这次工程补齐写成科研增量。
