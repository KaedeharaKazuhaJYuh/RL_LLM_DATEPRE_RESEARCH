## 问题与本版结论

本项目聚焦一个可否证的问题：**原生完整评分判为成功的 Agent 运行中，是否存在原任务契约能证实、但该评分未识别的实际违规或有害副作用？** 不能把完成信号、部分测试通过或终态答案正确当成完整原生评分通过。AppWorld 原生评分本就包含部分额外状态检查；先前具体反例被它检出，不是新的成功案例。

本版首次整理官方已发布的真实模型轨迹，而非新增模型运行。**没有独立副作用裁决，不能估计误判率、论文贡献或模型改进；研究状态仍为 HOLD。** 已收到的人类复审仍按原范围有效，本版新增数据尚未经独立复审。

## 主指标与证据规则

先冻结原任务契约、违规类型和裁决流程，至少区分：重复造成的不允许副作用、未授权状态变更、不能由证据支持的提前终止。重复请求本身不证明重复成功；用户授权、回滚、失败响应、故障和任务语义都可能改变判断。独立裁决者需要完整轨迹与相应状态证据；材料不足就记 unknown，不能凭不存在的记录推断无违规。

以 **原生完整评分通过的任务**为分母，统计其中已证实违规的比例；同时保留原生失败／未知与违规／无违规／未知的交叉表。对于尚未裁决的原生通过任务，分别假定全部无违规和全部违规，得到不确定性上下界；这不是置信区间。当前全部 76 个原生通过任务的安全性均未知，边界为 0%–100%，并非观察到 0% 违规。统计函数要求已给出的结论附有证据引用，但不会自动证明该引用充分或审阅独立。

## 后续决定性实验

1. **开发验证：**先用 train 熟悉任务和证据，再从 dev 按场景及应用类型固定小样本，盲审原任务契约、状态变化和请求／响应证据；保留分歧与 unknown。若旧输出无法完成归因，记录缺口，转向真实重跑，而不是补造标签。现有 GPT-4o 轨迹是一个模型、一个 Agent 和历史版本的探索性样本。
2. **匹配比较：**固定一种原生数据与评分版本、任务列表和工具权限；让至少四个真实且有区别的模型，以及不使用私有解答的强公开规则，在相同可见信息和预算下比较。遵循上游关于不硬编码任务 API 的限制。把模型、场景和任务分别记录，按场景聚类而非将三条变体当作独立研究单位。
3. **计量：**新执行逐次记录提供方、模型、请求 ID、实际输入／输出及缓存 token、错误／重试、时间，以及可核验的费率来源和估算；真实付费与估计分别报告。工具事件需带响应、提交状态和原始证据，API 失败、完成、升级和未知分别统计。历史日志无法补出缺失账单。
4. **决策：**预先确定有实际意义的效应门槛、分母、场景级不确定区间、标注一致性和预算，再决定扩大样本。只有在独立任务与多个模型上发现可复核、稳定的原生评分通过但实际违规，且改变评价结论时，才继续 Datasets & Benchmarks 主张；否则探索测量方法的较小论文或停止该路线。尚无数据支持训练 RL；只有确认存在可学习差距并安排匹配 SFT 对照之后才启动。

当前仅配置了 DeepSeek 的云端凭据，其他模型家族的合法可用来源、资源与成本尚需落实。没有启动新的付费调用，没有对已有运行结果声称改进。
