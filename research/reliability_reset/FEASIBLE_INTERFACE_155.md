# 1.0.55：把预算变成当前工具接口

日期：2026-10-24。研究起点是 [1.0.50](RELEASE_150.md) 的六次已触发修复回执丢失：联合规划虽显示预算内动作，仍有五次请求无法支付的读取。

## 可推翻的局部问题

在相同条件性完成说明、工具权限和检查预算下，把“可行动作建议”投影成模型当前看到的工具注册表及动作枚举，能否减少超预算读取，同时保留正常状态下的完成能力？

比较三臂：

| 系统 | 原始公开历史、读取契约与相同提示 | 派生证据状态 | 工具注册表／动作枚举 |
| --- | --- | --- | --- |
| matched_text | 有 | 无 | 完整 |
| soft_joint | 有 | 有 | 完整 |
| feasible_tools | 有 | 有，与 soft_joint 一致 | 删除预算付不起的读取／写入 |

三臂使用完全相同的系统提示和输出 schema 格式。只有 soft_joint 与 feasible_tools 的比较隔离注册表／动作枚举呈现差异；matched_text 与 soft_joint 的比较检验公开状态整理的增量。没有将上版对照的额外文字差异混入此比较。静态读取能力契约保留完整，因此移除可调用入口不删除历史响应或工具成本知识。

投影只依赖剩余检查／写入预算，不根据私有数值真值、故障标签或“应该升级”的隐藏答案筛选。stop 与 escalate 始终保留；有写入预算时 stage/publish 仍保留。每个动作及参数都由模型决定。

## 固定设计与执行准入

group-03、window-03、version-03 × 健康／语义错误／修复回执丢失 × 原名／别名 × 三臂，**54 条真实模型轨迹**；另有 **9 个共享后台规则控制**。固定种子 2026102455，按任务／状态／接口块洗牌并轮换臂顺序。

检查 1、写入 6（含初始化）、总决策 16；每轨迹最多 8 次模型调用，总请求最多 **432**，费用按峰值未缓存价格估算上限 **$0.60**。模型 `deepseek-flash`、temperature=0、thinking disabled、输出上限 512 tokens。供应商错误后停止进一步网络请求，不自动重试、改模型或补做挑选出来的单元。每格一个模型样本，无显著性或跨任务推广主张。

2026-10-24 核对 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)：输入未缓存峰值 $0.30/M、输出峰值 $1.20/M；文档列出的版本为 DeepSeek-V4.1-Flash-1017，实际响应标签另行保存，不将可变别名当成不可变权重标识。估算不等于账单或能耗测量。

执行准入为：投影／别名／未确认状态单测通过、离线模拟全部 54 轨迹和 9 个规则重放通过、源码和任务哈希冻结。延续用户要求推进实际开发实验的授权，不增加训练、数据源或模型家族。

## 不隐藏拒绝的接口

`action_schema` 是放在用户消息里的结构化说明，不是供应商约束解码。解析器仍接受原完整动作命名空间。如果模型提出被移除的 status/query_d，原提案经一一别名映射后交给原执行器，记录预算拒绝和这次 API 消耗。不会将其改写为 stop，也不会把排除动作当作无效 JSON 吞掉。

所有臂继续使用统一的 `completion_evidence_v150`；原生完成／独立数值判断保留。升级单列，**不计完成**。回执丢失的计划单元必须同时报告是否真的触发故障、触发后升级、提前升级、超预算、无证据 stop，以及成功完成。

主要看正常回执完成率、丢失回执下的读取拒绝和已触发故障后的升级／无证据停止。同时记录每格原始提案、被排除动作尝试、历史副作用、请求、tokens、响应字节和延迟。配对比较按任务／状态／接口保留，改善与退化都报告，不以超预算消失替代正确恢复。

## 复现

```powershell
python -m research.reliability_reset.feasible_interface work/reset155-new --prepare
python -m research.reliability_reset.feasible_interface work/reset155-new --execute
python -m research.reliability_reset.feasible_interface work/reset155-new --verify work/reset155-replay
```

prepare 冻结协议、任务、提示及源码；execute 保存公共请求和供应商原响应正文，不保存认证头；verify 在本地重算投影、解析响应并重放模型及共享规则，不再调用 API。仍使用三个历史开发实例，只有一个环境血缘；本轮是工具接口干预，不是 RL 或模型权重提升。
