## 目的

### 规则覆盖率的代数投影：v1 作废，按源码语义重算

**更正：**先前 v1 投影把同一终末 egress port 上的目标包设为全丢、同时让背景包全部通过。固定 NIKA 的 `internalFaultLossConfig` 以 `standard_metadata.egress_spec`（端口）为唯一键，不能实现这个包级选择；因此 v1 的“15/30 弃答”不是合法的 pinned NIKA 场景，相关结论作废。

以历史 burst 的 376 个目标包为固定目标量，取 MON–FRI 的 P50/P90/P99 代表流共 15 个负载档位。report-only 条件设 `I=E=376+M`。可实现的 10000 bp 端口损失条件设 `I=376+M, E=0`：注入器阈值为 `round(65535×10000/10000)=65535`；固定 P4 的 hash extern 对 `max=65535` 计算 `h % 65535`，结果范围为 0–65534，故端口上全部包均满足 `< threshold` 并丢弃。[NIKA 故障参数与阈值换算](https://github.com/sands-lab/nika/blob/ac4422d8a4a03be2b905e28edf72993d467e1b81/src/nika/problems/link_interface/p4_gateway.py#L14-L60) · [固定 P4 端口键和丢包 hook](https://github.com/sands-lab/nika/blob/ac4422d8a4a03be2b905e28edf72993d467e1b81/src/nika/net_env/p4_dc_gateway/gateway.p4#L87-L96) · [P4 hash 对 max 取模的定义](https://p4.org/wp-content/uploads/2024/08/P4_tutorial.pdf)。按冻结规则重算，30/30 个**公式场景**均可确定，0 个弃答、0 个错误归因。该计算说明：在当前两类故障契约与同端口全量损失条件下，简单计数规则已足以区分，ServDeg 负载档位不会产生先前声称的规则盲区。它不是 packet/runtime/Agent 实验，也没有检验部分损失或独立并发故障。

可复算文件为 [投影脚本](project_nika_shared_port_rule.py) 和 [v2 投影结果](NIKA_SHARED_PORT_RULE_PROJECTION_2026_11_09.json)；机器结果同时记录被作废的 v1 假设与应丢弃的旧结论。

这是针对明确计数模型的代数覆盖率投影，不是 30 次环境运行、不是准确率估计，也不是 30 个独立样本。它把下一项研究问题具体化为：同一信息条件下，Agent 或带预算的测量策略能否用公开可执行的额外观测恢复这 15 个弃答场景的可辨识性，同时不增加错误的确定性归因？

## 对通信 Agent 实验的直接意义

1. **以真实数据约束负载档位。**单一“均匀背景流”不能代表这组数据：流量中位大小随日变化，WED 的 P50 包数和字节数明显较高；P99 包数为 1,290–2,785，P99 字节数为约 1.12–2.62 MB。下一轮可将日别画像与 P50/P90/P99 流量档位作为 trace-derived synthetic workload 的校准范围，并预先固定转换规则。
2. **不把端口级故障伪装成流级噪声。**同一 egress port 上的 NIKA 损失会作用于该端口全部流量；ServDeg 分位数可用于工作负载规模参考，却不能在保持故障语义不变的情况下制造“背景包通过、目标包全丢”的计数混淆。需要另行定义并验证不同的任务契约，才可研究部分损失或并发独立故障。
3. **保留逐包真值与同一包集配对。**ServDeg 只有按流聚合的 TCP 特征，没有 NIKA 路径/端口根因，也不是逐包 PCAP。它能校准负载分布，不能替代固定 IPv4 ID 的配对发送端，不能直接宣称真实包重放，也不能证明 NIKA Agent 能力。
4. **把安全弃答与归因正确分开。**在目标和背景流共享端口时，端口累计计数的混合损失可能让仅用 `E=0`/`E=I` 的规则落入 `underdetermined`。后续实验要报告正确归因、错误归因和弃答三类结果，并比较冻结规则的公开证据与实际额外探测，而不是把弃答都记成错误。

## 研究定位与下一步

已有网络 Agent 工作覆盖电信故障排查和证据路径评估；TelemetrySuffBench 直接研究遥测视图、根因识别与证据不足时弃答。当前可执行的差异化路径应进一步聚焦：**在流量异质性与共享端口计数聚合下，测量通信 Agent 为恢复根因可辨识性需要支付的探测成本，并与同工具权限、同预算的冻结规则比较。** 这个定位是待检验假设，尚不是已证创新。

当前配对故障的初始分类已被简单计数规则代数区分，故不再把“共享端口背景导致规则弃答”作为假设。下一步先审查 Agent 实际可见的拓扑/转发表信息能否把目标服务映射到计数端口，并保存原始只读 MCP 输出。若映射可见且稳定，就把该规则冻结为负对照，不以这组单故障配对主张 Agent 增量；若映射缺失，再设计不泄露 oracle 且不改变任务契约的最小观测实验。只有原生运行和独立任务簇复核后仍留下强规则无法解决的差异，才启动 Agent 配对试验。本报告未调用模型 API，也不声称模型效果提升。

## 文献边界

- CTBench：现实电信运维中的 RCA 与路径恢复，并对最终答案和证据路径评分。需避免把“网络 Agent 应给证据”本身当作新贡献。
- TelemetrySuffBench：控制遥测视图，区分检测、根因定位与安全弃答；与本项目的可观测性问题直接相邻。
- CESNET-TimeSeries26：多年、多粒度网络流量序列及长期漂移研究；它说明公开网络数据的时间跨度和按时期报告的重要性，但不是本次五日 ServDeg 的来源或标签。

本阶段的可验证产物是完整的跨日数据画像和可复算脚本。它将真实负载数据接入实验设计，尚未证明 Agent 优于强规则或形成顶会论文贡献。
