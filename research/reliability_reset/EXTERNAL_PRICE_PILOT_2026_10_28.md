# 外部基准的最小价格试点：设计与准入

2026-10-28。**仅为设计，未执行模型或外部任务；论文主张仍为 HOLD。** 此设计响应三份评估，目的在于判断一个有状态外部任务上的价格干预是否可公平测量，而非继续寻找评分漏洞。

## 可否证的问题与近邻

在同一个真实基准任务、公开工具和调用预算下，仅改变事先告知模型的检查单价，Agent 的检查行为及净效用是否改变？可执行、同信息的固定规则能否解释这种变化？如果价格实际不可见、计费不完整，或固定规则解释了差异，试点不能支持新的决策机制。

[CostBench](https://arxiv.org/html/2511.02734v1#S3) 已有工具定价、替代路径和价格变化；[CAM-DF](https://arxiv.org/html/2607.27083v1#S3) 已研究有成本的工具获取和停止；[Judged Useless](https://arxiv.org/html/2610.06191v1#S4) 已向模型展示单价并对旧轨迹按不同成本重计。候选区别是**有状态执行中的验证决定及原生任务评分**，但尚未证明这种区别改变结论或超出这些工作。价格、regret 或两个指标并列本身都不是创新。

## 一次技术试点怎么做

1. **对象。** 首选已留存原生重放的 AppWorld train 任务 `82e2fac_1`，源码与运行时固定到 [1.0.85 记录](NATIVE_CONTROL_185.md)。它只是方便排查的开发任务，不是未见任务。先从同一起始状态分别启动隔离进程，使用未修改的工具和完整原生评分；不得向 Agent 或规则提供参考解 `compiled_solution.py`、私有真值或测试代码。
2. **干预。** 两个条件使用相同任务、指令模板、工具权限、动作上限和单次运行的起始状态，仅将可见的检查单价设为 `0.02` 或 `0.10` 效用单位/次。事先公布任务成功收益与检查价格，但不暴露私有测试；单价必须在采取动作前出现，是实验中的无量纲成本，不是假装真实 API 金额。为避免将价格响应混同于硬预算拒绝，本试点不设置额外的费用型硬预算；若环境必须设预算，冻结的上限须足以支付动作上限内最高价格下的所有计费检查。模型版本、采样设置及运行标识均须记录；不假设服务商支持确定性种子。
3. **评分。** 并列保存原生完整任务成功 `Y`、实际检查次数 `N` 和预先声明的辅助效用 `U = Y − λN`，其中 `Y` 仅在原生完整评分完成后为 0 或 1，`λ` 是该条件的单价。环境崩溃、评分不可用及未触发的调用单独记为缺失或拒绝，不擅自记作任务失败。新效用下排序改变不自动意味着原生评分错误。
4. **计量。** 运行前列出应计费的读取/验证 API，说明成功、失败和重试是否计费；未在清单内的操作不追收费。`world.execute` 中可能包含多个 API 调用，不能把一个代码块当一次检查。只有在底层请求记录能完整识别与计数、且成本对 Agent 可见时才运行；否则停在接口准备阶段。全部尝试、拒绝、原生评分与安全脱敏响应独立留存并绑定摘要。
5. **规则对照。** 在不超出同一权限、公开信息与动作预算的前提下，事先固定并测试至少“直接停止”“可负担时固定一次公开检查”和“依据公开状态选择是否检查”三个可执行候选。须先确认其适用于实际接口、没有隐式私有真值或额外帮助，再选择覆盖面合理的公开规则族作为对照；仅有一个弱规则不能称为强基线。如无法定义同信息规则，试点不进入模型调用。

**已有计量缺口：**对固定 AppWorld 提交的[请求记录器源码](https://github.com/StonyBrookNLP/appworld/blob/42b5bcf3cd334fee33f0c37c02070a9f5807add5/src/appworld/requester.py#L77-L113)核查发现，它保存方法、URL 和请求数据，不保存响应状态；超出请求上限时会在加入列表前抛错，管理请求及 `track=False` 的调用也不计入该列表。1.0.85 的既有日志同样没有完整逐次响应正文。因此不能仅凭当前 `request_tracker.requests` 断言收费或失败记录完整；须在实际可用工具入口检查并补齐，再作程序控制。

先用程序化控制验证启动状态、收费、日志、权限和原生评分，再考虑最多 **4 条真实模型轨迹**（2 个价格 × 每档 2 次）验证接口，不用于统计显著性、模型排名或估计总体价格弹性。可能出现的供应商错误、漏记、评分异常和未完成都完整保留；同任务重复轨迹不能当作独立任务样本。本次未执行这次 API 实验，也没有估算真实费用。

## 最优参考与决策

VeriCost 的精确 DP 只对其已知有限状态、先验、动作和效用模型成立。AppWorld 的部分可观察状态和转移尚不足以建立同样的精确最优解；本试点**不报告相对全局最优的 regret**。在规则资格满足后，可如实比较预先冻结的有限候选及样本效用，不能把最佳观测称作理论最优。

进入真实轨迹前须全部具备：价格在动作前可见；多 API 计费完整；原生评分可重复且与新效用分开；无私有信息泄露；可执行的同信息规则族和预算冻结；以及能够说明该设计相对直接近邻可独立否决的增量。缺一项即 **NO-GO**；即使技术试点通过，仍需独立任务来源、健康对照、第二模型及按任务簇的样本设计，才能讨论论文结论。
