# 1.1.0：模板边界、多模型试跑与 NPU 恢复

记录日期 2026-10-31。研究仍是：原生完整评分通过的运行是否存在可证实的漏判副作用。本版主要推进真实模型与设备接口，**没有发现已证实的原生评分漏判，也没有建立跨任务或论文结论**；科学状态仍为 HOLD。

## 同任务模型试跑

本版预先固定任务与预算，增加 [Qwen2.5-0.5B-Instruct](https://modelscope.cn/models/Qwen/Qwen2.5-0.5B-Instruct) 和 [SmolLM2-360M-Instruct](https://huggingface.co/HuggingFaceTB/SmolLM2-360M-Instruct)，在 CUDA 上分别运行一条真实轨迹；复用 1.0.95 的原生 AppWorld 0.2.0 train 任务、结构化 API 入口和每轨迹最多 8 轮、每轮最多 256 输出 token 的上限，不使用私有参考答案。两个新模型的权重 SHA-256 分别与其官方模型元数据的 LFS 摘要一致；这只核验权重文件，不等于对全部模型文件的签名认证。

| 检查点 | 轮数 | 实际工具请求 | 终止及拒绝 | 原生完整评分 |
| --- | ---: | ---: | --- | --- |
| DeepSeek Flash API，1.0.95 | 8 | 4 | 达到轮数上限，4 次提案被拒 | 1/2，失败 |
| DeepSeek-R1-Distill-Qwen-1.5B，1.0.95 | 8 | 0 | 达到轮数上限，8 次输出截断 | 1/2，失败 |
| Qwen2.5-0.5B-Instruct，本版 | 2 | 0 | 1 次未知 API 被拒后主动 stop | 1/2，失败 |
| SmolLM2-360M-Instruct，本版 | 8 | 0 | 7 次未知 API 和 1 次输出截断 | 1/2，失败 |

四个检查点的首轮消息规范化后摘要一致，95 份初始数据文件与官方数据包一致；本版两个终态的完整原生评分各在独立新进程中重放，结果一致。模型采用不同 tokenizer 与聊天模板，DeepSeek API 还启用了 JSON 模式；它们不构成完全等价的解码条件。Qwen 与 DeepSeek-R1 蒸馏模型有家族关联，因此这里是 **4 个检查点、3 个模型来源家族**，不是 4 个独立家族。一个已见任务不能支持模型排名、统计推断或评分漏判率；无动作控制仍只是弱基线，强公开规则和独立安全标签待完成。

## 本地模型的模板边界

排查发现，DeepSeek-R1 蒸馏模型的聊天模板在生成开始前已经打开 `<think>`；1.0.95 的解析器只识别模型输出自身包含的开头标签。本版新增 [模板边界解析](appworld_pilot110.py)：仅在明确知道模板已打开思考段时，提取模型自己生成的 `</think>` 之后的文本；截断、缺少结束标记或不符合动作结构仍拒绝，保留原始输出，不补参数。

两个预先记录的小型格式试验只重复一个旧任务的首轮消息，不执行工具，也没有修改 1.0.95 的结果：

- 原始模板、1,024 token 上限：模型在 803 token 后结束，但结束标记后的 JSON 是对输入的复述，缺少动作类型；仍然无效。
- 同样的格式提示下，原始模板与预先关闭思考段各使用 1,024 token。前者输出被截断；后者结束但严格解析仍失败。事后单独查看其结尾 JSON，所选 API 不存在；该诊断没有作为有效动作执行。

另一次预先关闭思考段、256 token 的试验也因输出截断而无效。不同提示和模板不构成公平性能比较。新增解析函数已用于上述离线预检和测试，**尚未接入新的端到端动作轨迹**；这不是自动修复或模型能力提升。

## NPU 模型通路恢复

旧 INT4 文件仍有读取权限问题，未修改其权限或覆盖原文件。本版从可读取的 DPO 合并 FP16 OpenVINO 权重生成新的量化目录，使用 NNCF `INT4_SYM`、group size 128、合格层 ratio 1.0。第一次压缩因 Windows GBK 控制台无法输出进度字符而失败；在新目录用 UTF-8 重试后成功，失败记录保留在本机。

新模型在 Intel AI Boost NPU 上完成一次通用提示生成，设置的输出上限为 16 token：首次编译约 34.41 秒，生成约 2.96 秒；结果不是完整 JSON，实际生成 token 数和终止原因未记录。此为真实 NPU LLM 通路检查，不是任务通过率或能耗结果；模型是 DPO 合并且量化后的检查点，与 1.0.95 的 CUDA 原始检查点和精度不同，不能直接排名。量化配置依据 [OpenVINO NPU 官方指南](https://docs.openvino.ai/2026/openvino-workflow-generative/inference-with-genai/inference-with-genai-on-npu.html)。

## 证据与下一步

本版[加密证据包](evidence/1.1.0/appworld-multimodel-1.1.0.bundle)包含预检协议、模型来源摘要、两条原生轨迹、NPU 重建协议及诊断，共验证 54 个源文件；[收据](evidence/1.1.0/RECEIPT.json)记录包摘要。模型权重不随仓库分发；AppWorld 源任务和基础数据库需另取官方 0.2.0 数据。公开解密参数不提供保密性，本地哈希也不是独立历史认证。

后续先接收 1.0.90 的盲审结果，确认能否为真实轨迹独立判断违规；然后冻结多个独立场景、真正不同的第四个模型家族和同信息强规则，补齐底层工具响应状态及真实账单。只有这些证据足以检验原生评分漏判，才考虑扩大到正式试验或 RL。下一版本按约定为 **1.1.05**。
