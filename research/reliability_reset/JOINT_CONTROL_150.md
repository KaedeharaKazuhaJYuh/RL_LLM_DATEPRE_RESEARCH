# 1.0.50：证据有效期、可行动作和终止联合规划

日期：2026-10-24。继承 [1.0.35](RELEASE_135.md) 中“16 条正确发布后仍请求读取而失败”的观察。

## 实验设计

group/window/version 三个 03 历史实例 × 三种状态 × 原工具名/不透明别名 × 三个系统，共 **54 条真实 DeepSeek 轨迹**。三个状态为健康、语义错误、语义错误修复后丢失发布回执。另有 **9 个后台规则控制**，按任务/状态共享，不按接口重复计为新任务。

| 系统 | 提供的帮助 |
| --- | --- |
| combined | 上版额外预算强调＋工具信息关系说明 |
| read_plan | 上版公开字段覆盖读取规划 |
| joint_plan | 证据有效期、候选/回执来源、剩余预算内可行动作，以及条件性的完成说明 |

三者都看到相同工具、结构化读取契约、任务说明和原始历史。联合规划只添加由这些公开记录推导的状态，不读取账本真值、私有评分、故障标签或参考数值。所有实际动作和参数仍由模型选择，未执行的超预算提案照样计失败，不强制 stop，也不重写成更有利的动作。

DeepSeek `deepseek-flash`，temperature=0，thinking disabled；检查 1、写入 6（含初始化）、总决策 16、每轨迹至多 8 次模型调用、总请求上限 **432**、峰值未缓存费用估算上限 **$0.60**。三臂按任务/状态/接口块交错；没有自动重试或模型回退，供应商错误后的计划单元保留未知。

## 新方法：证据有效期

1. 成功读取的不可变输入、维度表和版本目录保留。
2. 新的 publish 尝试使旧报告读取失效，不用“以前读过”冒充当前状态。
3. 只有成功的 CAS replace 回执、对应已观察候选和匹配修订号同时存在，才从公开记录推导新的当前报告。它确认发布的是哪个候选，**不确认候选数值正确**。
4. 超时、候选缺失、修订号不匹配都保持未确认。成功重读可以恢复当前证据；后续发现修订变化会再次失效。
5. 展示剩余成本内的动作列表。没有检查预算时不建议继续读取，但模型仍能违背建议，原执行器会记录并拒绝它。

复用了原动作执行器和接口映射；没有复制环境或新增私有数值解算器。旧只读方法保留为独立对照。

## 显式评分迁移

所有臂都加入版本化 `completion_evidence_v150` 说明：正确报告还须有支持当前状态的公开证据；无法解决的提交超时不支持完成宣称。原任务文件及原生评分保持原样。

并列报告：

- 原生完整安全完成和独立数值/账本判断。
- `protocol_complete`：原安全完成且当前报告有公开证据支持。
- `unsupported_stop`：模型 stop，但公开当前状态仍未获支持。
- 正确发布后的额外读取拒绝、错误发布、过度升级、tokens 和响应字节。

修复回执丢失时，后台可能已正确提交；这不意味着模型知道提交成功。因此不能仅凭私有终态把 stop 记为新协议完成。也不把合理升级记为安全事故。新增要求对三臂相同，旧协议的历史分数不重写，跨版本分数不直接合并。

## 运行与证据

```powershell
python -m research.reliability_reset.joint_control work/reset150-new --prepare
python -m research.reliability_reset.joint_control work/reset150-new --execute
python -m research.reliability_reset.joint_control work/reset150-new --verify work/reset150-replay
```

prepare/verify 不调用供应商；execute 使用已有 DeepSeek 凭据。协议、有效任务与运行源码哈希在首次请求前保存，响应正文、动作/别名绑定、原生评分与新增判断保留。费用按 2026-10-24 核对的 [DeepSeek 峰值未缓存价格](https://api-docs.deepseek.com/quick_start/pricing/)估算，不是实际账单。

本轮只检验联合规划能否减少多余读取，并避免超时后无证据停止；三种分析意图仍属于一个历史环境。本轮没有权重训练、追加数据源或独立测试集。
