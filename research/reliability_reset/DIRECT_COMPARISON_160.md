# 1.0.60：AFT-Bench、INTENT、HyperAgent 与本项目的直接比较

| --- | --- | --- |
| §1 Introduction | 可调用≠可操作 | 我们的遗漏参数和超时后选错动作同属这一问题；不能重命名后称首次发现。 |
| §2 Related Work | 接口成本与语义 | 预算提示、接口裁剪、结果验证应放在已有系统设计脉络中。 |

| §3.3 Interface Semantics | 生命周期、效果、验证 | 候选／CAS 回执绑定、状态证据、工具可见面有直接交集。我们没有完整异步生命周期实现。 |
| §3.4 Ambiguity Resolution | 暴露状态或稳定续行 | 不能把证据跟踪或安全重试本身称作新恢复机制。 |
| §4.1 Evidence Layers | 冻结、SQLite、多模型 | 我们只有一个历史环境血缘、一个模型别名；工程堆叠并未形成更强外部证据。 |
| §4.2 Treatments/Workloads | 累积接口与移除消融 | 我们的匹配文字／软状态／投影是较窄的局部干预，不构成新实验范式。 |
| §4.3 Faults/Outcomes | 提交点与安全非行动 | 与修复后回执丢失及安全升级直接交集；必须把未触发故障与处理故障分开。 |
| §4.4 Instrumentation | 决策与运行时分离 | 我们保留原提案、不暗中修复是正确做法，但该原则已被直接讨论。 |
| §4.5 Statistics | 配对、任务聚类校正 | 我们每格一个开发样本，不能用 API 次数充当独立样本量。 |
| §4.6 Freeze | 证据锁定与一致性 | 源码／请求／响应绑定是复现基础；哈希不能独立认证历史真实性。 |
| §4.7 Validity | 条件效应与外推限制 | 我们也不能从强制注入故障推断生产发生率；需承认来源与协议依赖。 |
| §5.1 Discovery | 上下文与召回分离 | 下一步若做摘要或工具压缩，必须验证必要证据保留，不能只报告 tokens 减少。 |
| §5.2 Recovery | 中断与状态丢失分离 | 我们没有这些完整工作负载，不应把一次 CAS 修复泛称为普遍恢复。 |
| §5.3 Effect Semantics | 响应丢失、幂等、条件写 | CAS、防重复与提交未知都有直接近邻；SQLite 和有副作用写入也不是区别。 |
| §5.4 Verification | 终止宣称与世界状态 | 我们新增公开支持评分仍未在真实样本中产生旧／新完成分歧；没有新测量发现。 |
| §5.5 Heterogeneity | 模型—接口交互 | 我们没有跨模型证据，不能从 DeepSeek 的单轮行为建立普遍能力结论。 |
| §5.6 Summary | 机制分项而非总优越 | 本项目应保留投影组的参数失败和成本退化，不宣称全面更优。 |
| §6 Limitations | 受控世界的边界 | AFT 也保留外推限制；不能把对方的局限直接当成本项目已证明的增量。 |
| §7 Conclusion | 模型与接口共同决定可靠性 | 该一般性主张已被明确提出，停止作为我们的论文主贡献。 |

原文报告三个模型家族和六种工作负载，并以任务聚类分析接口干预；本项目不声称复现了这些结果。[AFT §4.1](https://arxiv.org/html/2608.23628v2#S4.SS1)、[§4.5](https://arxiv.org/html/2608.23628v2#S4.SS5)

**预算细节不能误读。** AFT 将执行预算写入任务模型并在配对中固定；其供应商调用的货币保护上限与 INTENT 的逐任务硬工具价格约束不是同一概念。当前手稿未让我们确认 AFT 对“检查配额×分析语义×回执失效”的完整交互做了专门检验，但这项未确认不能用来支持“首次联合研究”。[AFT §3.1](https://arxiv.org/html/2608.23628v2#S3.SS1)、[§4.4](https://arxiv.org/html/2608.23628v2#S4.SS4)

## INTENT：预算规划不是本项目的算法空白

| 原文章节 | 原文机制／评测 | 本项目对应与剩余证据问题 |
| --- | --- | --- |
| [§2](https://arxiv.org/html/2602.11541v1#S2) | 硬预算工具市场 | 我们用检查／写入配额，不是同一个价格模型；换预算单位不构成新算法。 |
| [§3](https://arxiv.org/html/2602.11541v1#S3) | 意图预测、前瞻与成本校准 | 我们只有公开字段覆盖枚举与剩余预算筛选，没有学习世界模型或同量级规划算法。 |
| [§4](https://arxiv.org/html/2602.11541v1#S4) | 加价 StableToolBench；软提示与强制约束对照 | 我们已有文字／状态／接口组，但不能把减少无效调用当成此前未研究的现象。 |
| [附录 B](https://arxiv.org/html/2602.11541v1#A2) | 辅助模型训练及评测细节 | “推理时干预”不等于整个系统从未训练。它不更新主 Agent 策略，但使用离线训练组件。我们的当前系统没有这些组件。 |
| [附录 D](https://arxiv.org/html/2602.11541v1#A4) | 缓存、消融与风险取舍 | 摘要缓存、少调用、更保守的升级都不能仅凭存在而宣称原创。 |

INTENT 的主要终点偏预算内完成与成本；在本轮所读设置中，没有确认其专门评估我们这种已提交报告回执丢失的账本后果。这个差异使其不是最直接的恢复近邻，**不意味着预算规划与恢复相结合就自然成为新贡献**。相应恢复比较仍需以 AFT 为主。

## HyperAgent：依赖、动态工具支持和完成验证已有研究

| 原文位置 | 原文机制／评测 | 本项目对应与处置 |

| [Task-Level Planning](https://arxiv.org/html/2608.02650v1#Sx4.SSx2) | 任务 DAG 与上下文图 | 本项目没有达到同等任务组合结构；工具裁剪不是独立新范式。 |
| [Task Execution](https://arxiv.org/html/2608.02650v1#Sx4.SSx3) | 绑定状态与子任务验证 | 原文不只验证函数是否可调用，也验证输出／效果支持；不能把它描述成只管参数语法。 |
| [Tool-Level Planning](https://arxiv.org/html/2608.02650v1#Sx4.SSx4) | 状态依赖的缺口扩展 | 我们动态列出预算可行工具与此不完全等同，但属于相邻系统设计，尚无独立算法优势。 |
| [Experiments](https://arxiv.org/html/2608.02650v1#Sx5) | AppWorld、组件消融与动态子目标 | 本项目尚没有不同状态结构的任务验证。更多 04／05 CSV 实例不能补齐这一点。 |

其检索工具数／搜索范围预算不能直接当成 INTENT 式逐任务硬货币预算；本轮也未确认专门的提交后响应丢失消融。对这些未确认项只保留限定，不作“它没有研究，因此我们新颖”的推论。

本表比较的是上述原文设置与我们**已经实现／执行**的内容，不把待做计划填成能力。来源分别为 [AFT §3–5](https://arxiv.org/html/2608.23628v2#S3)、[INTENT §3–4／附录 B](https://arxiv.org/html/2602.11541v1#S3)、[HyperAgent Method／Experiments](https://arxiv.org/html/2608.02650v1#Sx4)。

| 维度 | AFT-Bench | INTENT | HyperAgent | 本项目 1.0.50／1.0.55 |
| --- | --- | --- | --- | --- |
| 主要干预 | 操作接口语义 | 前瞻预算审批 | Schema 图与动态支持 | 文字、公开状态及工具表／枚举 |
| 预算含义 | 配对固定执行预算 | 逐任务硬工具费用 | 工具上下文／搜索范围 | 检查 1、写入 6、决策 16；另有限模型调用 |
| 执行证据 | 运行轨迹与后端状态 | 预测观察与真实工具反馈 | 绑定值、输出、效果 | 公共原响应、候选／回执；私有判定隔离 |
| 提交后恢复 | 幂等、条件操作、验证 | 本轮未确认专门测试 | 本轮未确认专门消融 | 已提交修复后丢失响应；主要为升级而非确认后完成 |
| 工作负载 | 多种操作故障；SQLite 复核 | 加价 StableToolBench | AppWorld | 三类分析意图，共用一个历史 CSV／SQLite 环境 |
| 主要对照 | 机制移除与匹配接口 | 软提示／强制预算基线 | Agent 基线与图组件消融 | 匹配文字／软状态／投影；共享公开规则 |
| 主要指标 | 恢复、效果、终止、上下文 | 完成、预算可行、成本 | TGC／SGC 与调用成本 | 原完整完成、公开支持、拒绝、故障激活、tokens |
| 当前证据边界 | 手稿报告多模型，未由我们复现 | 不等于无辅助训练 | 不仅做语法检查 | 一个模型别名；无独立家族和增量证明 |

我们的实际区别主要是较窄的分析任务与检查配额、逐条原响应取证，以及私有数值／账本和公开证据并列记录。目前这些区别仍是实现／记录粒度差别，没有证据表明它们产生了现有工作无法表达的科学结论。

## 重新启动跨任务实验的最小准入

先提交一个短设计，明确一个问题、一个可被强规则否决的主比较，以及它和三篇论文的具体实验设置差异。审查通过前，不新建测试家族、不下载新数据、不接入第二模型、不安排付费调用。

任务差异须体现在**状态转换结构**：例如单资源条件替换、可部分完成的多资源提交、授权随时间变化的执行流程。它们只是待审候选结构，不是已经独立的家族；若仍共用同一状态机／恢复脚本或可由变量重命名互相映射，则不能算独立复制。

准入设计必须同时提供：来源与实现血缘、健康／故障／未触发控制、各状态下公开可见证据、允许行动、独立世界状态判定、历史副作用责任、等权限强规则、任务簇级主指标、样本量／预算理由和冻结规则。正确升级是否符合任务政策要独立登记，不能仅由“没有出事故”推断其必要或最优。

建议先用离线反例问：**候选主张在 AFT 的效果／验证对照、INTENT 式硬预算基线和 HyperAgent 式依赖／完成验证都存在时，还预测什么不同结果？** 若答案只是“在另一个小型 CSV 环境也有效”，停止该主张；保留工程基准，不追加 API。
