# 研究演进与历史证据

本页按研究阶段汇总积累与结论；逐版本细节保留在原报告和 [CHANGELOG](../CHANGELOG.md)。不同数据、任务、预算和评分下的成功率不能合并比较。当前入口是 [FaultDA-Bench](../README.md)。

## V2–V3：建立可信执行与验证

V2 将单步数据分析路由连接到实际 CSV 操作，修复任务编号捷径、占位工具和同源参考计算等问题。受控任务上，规则、监督和 Bandit 都能达到较高分数，因此不能据此证明 RL 优于规则。[V1/V2 对照](../reports/V2_COMPARISON.md)

V3 增加多步产物传递、真实公开数据、冻结恢复策略、升级、预算及子进程故障。最终按来源与日志交叉评估：选择性恢复减少错误，但牺牲自动完成覆盖，不能宣称所有指标都胜过规则。这一阶段不是通用 LLM 权重训练。[V3 最终审计](../reports/V3_FINAL_AUDIT.md)

## V4：模型学习与设备路径

训练逐步转向 DeepSeek LoRA SFT、DPO 与 GRPO，同时加入多种子、困难组合和来源留出。早期开发集增益受任务难度、初始化与奖励方差影响，尚无稳定外部 RL 优势。历史伪优势和临时目录导致的错误分数在对应报告中保留修正，不作为当前成果。[V4 收尾](../reports/V4_5_10_V4_CLOSURE.md)

CUDA GPU 用于训练与 BF16 参考评测；Intel NPU 接入 OpenVINO 量化推理，其精度需单独检验，不能视为与 GPU 数值等价。[NPU 接入与审计](../reports/V4_NPU_ENABLEMENT.md)

## V5：系统优化与更强模型对照

Python 保留模型和实验主流程，C++ 提供可选数值内核，Go 提供单机持久队列、设备占用、租约和结果去重。局部计算加速不等于端到端 LLM 加速，也不等于模型效果改善。[系统接入](../reports/V5_ALPHA_2.md) · [正式版范围](../reports/V5_0_0_RELEASE.md)

更严格的监督继续训练对照削弱了早期 RL 增益解释：V5.0.05 中继续 SFT 优于此前 RL；V5.0.10 的 RL 相对匹配 SFT 仅多通过一条相关题，未设为默认模型。[监督对照](../reports/V5_0_05.md) · [性能与模型实验](../reports/V5_0_10.md)

V5.0.15-beta.2 完成条件恢复的三种子五臂 CUDA 实验。继续 SFT 28/240，GRPO/branch 0/240，普通反事实/paired 4/240，确认门槛未通过。这些是给定正确前后步骤的受限恢复结果，不能当作完整数据分析 Agent 的泛化能力。[beta.2 冻结报告](../reports/V5_0_15_BETA_2.md)

## FaultDA-Bench：独立基准研究

| 阶段 | 实质进展 | 当前解释 |
| --- | --- | --- |
| P0 | 非幂等报告追加、持久状态、查询失败、安全升级、独立验证 | 机制探针，不作为原创核心；与已有恢复研究重叠 |
| 0.2.0-dev | 三类分析、语义修复、六个固定基线、DeepSeek 接入 | 简单组合基线解决当前可观察任务，没有新的联合失败证据 |
| 0.2.05-dev | 字段映射复核、三来源×两意图设计、说明配对诊断 | 说明修正未提高完成率；来源交叉仍不是全新来源验证 |
| 0.2.10-dev | 公开元数据抽取、历史布局及条件恢复诊断 | 两布局事实问答均 12/12，条件完成均 4/9；发现正确报告被再次写错 |
| 0.2.15-dev | 数值语义判断、公开规则动作建议、逐步状态退化检测 | 原始策略安全完成 2/6，辅助策略 6/6，强规则同为 6/6；不属于 RL 提升 |
| 0.2.20-dev | 三段式历史归因冻结套件、预算反例、独立重放与篡改检测 | 六条脚本路径符合工程要求；科学 HOLD 不变，无新模型成绩 |

## 如何引用仓库内结果

使用具体版本报告、任务清单、模型设置、分母和轨迹哈希，不引用 README 中的简短描述替代实验定义。被撤回或仅属开发诊断的分数必须带上相应限定。仓库目前不提供已完成正式确认或已证明稳定 RL 优势的结论。
