## 0. 修订摘要与决策记录

本版相对原规划做出以下**约束性调整**：

1. **统一来源数量。** 原型期使用 **6 个开发侧来源（训练 3 / 开发 3 / 最终测试 0）**；论文确认阶段新增**至少 6 个此前未用于该项目训练、诊断、选模或协议修改的最终测试来源**，故论文阶段至少 **12 个不重叠来源**。推荐争取 18 个左右（训练 5 / 开发 5 / 最终测试 8），均为研究目标，**不是 KDD 录用门槛**。历史 V1–V5 已用过的来源只能归入开发侧或历史对照，不能改名为“全新盲测”。
2. **区分隐藏真值与 Agent 观察。** “已提交 / 未提交”是环境真值；“确认未知”是 Agent 的知识状态，不是独立的物理提交状态。相同错误消息的干预对必须允许通过**合法、付费、可能失败的检查动作**获取信息；无法获取足够信息时允许安全停止或升级，不能要求模型猜测不可观测真值。
3. **把指标变成可计算定义。** 明确分母、哪些操作属于真正不安全的副作用、失败/拒绝如何计分；不再仅用含糊的“状态识别准确率”衡量动作质量。
4. **收束比较对象。** 第一版主赛道只设 `Prompt-only Agent` 与 `Fine-tuned Agent`；`System Reliability` 降级为工程附录/后续研究，不与 Agent 能力排行榜混排。增加通用工具 Agent 和不同模型家族的基线。
5. **提前隔离 Benchmark。** 无需等待 V5.0.15-beta.2 全部完成才冻结基准研究规范；可在稳定提交上创建独立分支，但必须在首次正式模型评测前冻结协议、划分、指标、基线清单和评测次数，禁止利用最终测试结果继续调参。

## 1. 定位与研究问题

**FaultDA-Bench（Fault-aware Data Analysis Agent Benchmark）** 面向“状态不确定性与故障恢复的可验证数据分析 Agent”。它从现有训练环境中独立出来，目标不是再训练一个模型，而是建立可复现、可扩展、能区分**模型决策错误、环境故障、状态不确定和不安全恢复**的公开基准。

### 1.1 研究问题（RQ）

- **RQ1：故障下的状态判断。** 当相似错误消息对应“未提交”“已提交但确认丢失”“存在未提交的部分产物”时，Agent 是否会正确认识到不确定性，并使用合法工具获取必要信息？
- **RQ2：安全恢复。** 在检查、重试、继续、回滚（如任务支持）与保守停止之间，Agent 是否能完成任务且避免重复副作用和错误产物提交？
- **RQ3：真实可验证的数据分析。** 模型生成的答案、数据文件及终态是否满足任务契约，而不是只与某一条预设动作路径或自然语言描述一致？
- **RQ4：分布外泛化。** 新数据来源、措辞、工具组合和故障语义分别造成什么影响？联合变化又带来什么影响？
- **RQ5：归因与评测盲区。** 普通终局正确率是否掩盖不安全的中间行为？能否区分模型选错工具与正确动作遭遇环境故障？

### 1.2 论文贡献候选（需要实验证明）

1. **可控的状态歧义故障基准。** 具有真实可检查执行状态的故障成对干预与可复现协议。
2. **安全恢复评价协议。** 同时衡量终局正确、状态检查行为、重复副作用、保守停止和成本。
3. **跨模型、跨分布的经验发现。** 证明已有单一成功率或只评估正常工具使用的方式遗漏了哪些重要行为。

这些是**待验证贡献**；不得在完成相关工作比对和实证之前声称“首次”或“现有基准完全没有”。

## 2. 与已有 Benchmark 的差异性验证

研究开始时建立逐篇能力矩阵，至少对照：InfiAgent-DABench、DSBench、ToolSandbox、τ-bench，以及其他最新的 data-analysis agent / stateful tool-use / failure-recovery benchmark。

对每个基准逐项记录：是否有真实文件副作用、故障发生位置、提交状态是否可能不确定、是否提供可观察的检查动作、任务契约验证方式、未见来源/组合划分、按簇统计、代码数据许可与公开程度。

**继续做项目的关键门槛：** 在完成查新后，能够指出至少一个**具体且可复现实验验证**的评测缺口，并用对照实验说明其影响。如果现有工作已经完整覆盖核心问题，优先调整研究问题而不是继续扩充同类任务数量。

## 3. 基准任务、交互与参数设定

每个 episode 包含五层，但必须区分公开观察与隐藏标注：

| 层 | 包含内容 | Agent 是否可见 |
| --- | --- | --- |
| 数据层 | CSV 路径/数据访问接口、列与类型、授权信息、输入摘要 | 按任务协议开放合法部分；原始真值副本不开放 |
| 分析层 | 去重、缺失值、类别处理、异常值、日期、聚合、相关性、滚动统计等 | 目标和允许的工具接口可见；正确计划和答案隐藏 |
| 持久状态层 | 未提交、准备中、已提交、已放弃；提交版本、操作 ID、产物摘要 | **真实状态隐藏**；只能经查询接口获得许可的信息 |
| 故障层 | 提交前超时、提交后确认丢失、读取故障、部分写入、崩溃等 | 只能看到实际工具反馈；故障标签、注入点隐藏 |
| 语言层 | 中文/英文提示、同义改写、参数表达、长度变化 | 当前提示可见；对应标准答案隐藏 |

### 3.1 四种任务形态

- **Recovery：** 给定初始操作及后续目标，着重评测故障发生后的决策。
- **Planning：** 从任务请求自主生成工具序列及必要参数。
- **Verification：** 通过允许的检查操作判断产物是否满足契约，并正确结束或拒绝提交。
- **Composed：** 规划 + 故障恢复 + 最终验证的完整多步链路。

**分阶段实施：** `alpha.1` 先验证 Recovery / Verification；`alpha.2` 再加入 Planning / Composed。四种任务形态作为最终计划保留，不要求首个原型一次完成全部。

### 3.2 两个参数难度切片

1. **Controlled-binding：** 为隔离恢复决策，可以像 V4 环境一样提供合法参数绑定；仅评价指定难度下的恢复可靠性，不能据此声称模型具有自主参数解析能力。
2. **Autonomous-binding：** Agent 根据任务文字、schema 和工具接口推断列名及工具参数，允许合理的状态查询；用于测试更完整的数据分析能力。

两类切片分别报告，**不得把分数无条件混为一个排行榜总分**。在 Autonomous-binding 下禁止直接公开 oracle 计划、目标输出或仅从 gold 推导的内部绑定。

### 3.3 可用动作与预算

最低动作接口建议：

- `execute_tool(action, params, operation_id)`：按工具契约执行数据操作；`operation_id` 用于关联执行与后续状态检查。Agent 不能直接指定已存在的真实提交回执。
- `query_operation_status(operation_id)`：返回 `committed` / `not_committed` / `indeterminate`，也可能查询失败；语义及可信期限必须有明确定义。
- `inspect_artifact(artifact_id)` / `verify_output_hash(artifact_id, expected_public_hash?)`：仅查看被授权的产物元数据；不能返回评测 gold 或私有状态。
- `stop` / `escalate`：明确成功结束或无法安全推进时请求人工/上级处理。是否允许 `rollback` 应按操作契约逐类定义。

每个任务记录最大决策步、工具调用上限、检查上限、时限及实际资源。**查询和重复尝试均计入成本与预算**；检查不是免费答案通道。

## 4. 状态机、观察和故障干预协议

### 4.1 必须区分两类状态

**隐藏持久状态**（真实环境状态，供评测器使用）例如：

- `NOT_COMMITTED`：操作没有产生已提交副作用；
- `PREPARED`：可存在隔离的暂存产物，但未成为公开有效结果；
- `COMMITTED`：已完成持久提交，具备可核对的操作 ID / 修订号 / 输出摘要；
- `ABORTED`：操作终止且未发布有效副作用。

**Agent 可见认知状态**例如：`known_committed`、`known_not_committed`、`uncertain`。`uncertain` **不等于**隐藏状态中的一个“第三种提交结果”。

数据处理任务的 `current_artifact` 指向哪个版本、操作是否已被确认提交、暂存文件是否隔离、取消的 worker 是否仍可返回结果，都必须能在环境中一致复现。仅复刻同一自然语言历史而不复制真实文件/提交状态，**不算可靠快照**。

### 4.2 首批核心成对干预

| 干预 | 首次对 Agent 的反馈 | 隐藏差别 | 可接受的恢复策略（按后续检查结果） |
| --- | --- | --- | --- |
| **Before-commit timeout** | 相同的 `operation timed out` | 无有效提交 | 查询状态；确认未提交后安全重试 |
| **After-commit acknowledgment loss** | 相同的 `operation timed out` | 已完成提交，只是确认未返回 | 查询状态；确认已提交后检查/继续，不盲目重复副作用 |
| **Partial-write / No-write** | 相同或近似的失败反馈 | 隔离暂存区是否留有残片 | 拒绝残片成为有效产物，必要时清理或重试 |
| **Transient-read / Invalid-action** | 工具调用失败 | 外生读取故障或参数/动作本身无效 | 使用合法诊断区分暂时失败与应修正参数的情况 |

后续扩展：进程崩溃、取消后迟到结果、租约失效与重复提交。与 worker 租约有关的测试优先放在工程附录，不得用作首版 Benchmark 的唯一创新支柱。

### 4.3 成对干预的可比性要求

- 配对任务使用相同的自然语言目标、初始 CSV、允许工具、合法参数空间、预算、故障前历史和**相同的首条错误观察**；只改变预先指定的环境提交状态或故障注入时点。
- 为每条干预保存故障 seed、快照/文件摘要、操作 ID、提交日志和隐藏状态真值；这些只进入**评测侧私有日志**。
- 若后续调用 `query_operation_status`，允许它在状态可查时返回不同结果；这正是策略应该利用的信息。可设置独立的 `indeterminate` 条件模拟暂时不可查。
- 如果两个隐藏状态在整个可用动作空间下都**不可区分**，不可要求 Agent 必然采取不同动作；此时评估其是否选择安全等待、终止或升级，而不是评估“猜中真值”。
- 明确真实提交边界，区分 `staged_file_exists` 和 `committed_output_visible`，拒绝把临时残片误当成已提交成果。

### 4.4 非幂等副作用的最低要求

不少 CSV 转换本身是幂等的。单纯重复执行去重或类别规范化，未必构成有害副作用。因此首版至少设计 **一种自然、合法、可验证的非幂等操作**，例如向任务报告追加一个已确认记录或发布一条不可重复计入的聚合条目；它必须对应实际分析工作流，不得只是为刷分制造玩具陷阱。

对每类操作明确：

- 是否幂等、重复调用是否产生不同结果；
- 是否支持 `operation_id` 去重，以及开启/关闭去重的对照；
- 什么情况下属于**真实不安全副作用**（额外记录、重复计数、覆盖正确产物、接受已撤销任务的迟到结果等）；
- 如何由独立执行日志和最终产物验证器判定，而不是凭模型自述。

如执行器天然阻止全部重复副作用，应该报告“执行层安全”与“Agent 决策正确”两个维度，不能把执行器自动兜底算成模型自身的恢复能力。

## 5. 数据来源、划分与 OOD 设计

### 5.1 数量与阶段（统一口径）

| 阶段 | 训练来源 | 开发来源 | **最终独立测试来源** | 使用范围 |
| --- | ---: | ---: | ---: | --- |
| `alpha.1`–`alpha.2` 原型 | 3 | 3 | 0 | 6 个开发侧来源；可使用已知历史来源，但要标明已见 |
| `beta.1` 最低论文确认 | ≥3 | ≥3 | **≥6** | 至少 12 个来源且不同 split 完全不交叉 |
| 冲刺配置（建议） | 5 | 5 | 8 | 18 个来源，扩大领域和真正独立任务簇 |

数量属于项目内部研究目标，**不是官方会议硬指标**。选择新来源时优先覆盖缺失值、混合类型、类别不平衡、有序时间序列、异常值、重复数据，以及中英文列或值；同时避免所有任务都出自同一类模板。

### 5.2 数据隔离与冻结

1. 历史 V1–V5 使用过的 UCI 来源和评测题目，无论曾被标注为 `test` 还是 `holdout`，如已经参与过诊断、协议设计或模型选择，统一标记为 **seen/development**。不能作为 Paper A 的“全新外部盲测”。
2. 最终测试来源须在确认版中**全新选择并登记**，训练数据、模板调参、错误诊断、模型选择、手工排错都不得读取其答案或逐题模型表现。
3. 在首次正式模型评测前冻结：来源 URL/许可/DOI、原档案和派生 SHA-256、任务簇 ID、生成规则、故障语义、允许动作、主指标、基线列表、评测次数、随机种子与统计方法。
4. 先用专家在独立构建/验收环境验证任务可达与 oracle 正确；专家失败只允许修复协议并完整记录，不能查看候选模型测试结果后改任务。
5. 如最终测试出现测试本身缺陷，需要公开记录受影响版本、废止该轮确认并冻结**新测试集**；旧集只可继续用于诊断。
6. 论文完成时可发布公开测试任务和结果；若未来保留私有 leaderboard 测试，则与已发表公开确认集分开版本管理，**公开测试的反复试跑不再算未见确认**。

### 5.3 OOD 轴的设计

分别建立 `new_source`、`new_wording`、`unseen_composition`、`unseen_fault_semantics` 切片，并提供联合 OOD 切片。单轴实验应尽可能保持其他因素相同，联合切片则报告难度叠加后的表现；不得把来源留出直接称为全面的提示/组合盲测。

数据统计以 `source_id × intent_id × task_instance_id` 为基础任务簇（同簇包含多提示、故障和重复运行），并明确哪些实例在语义上高度相似。任务数和 episode 数分别报告。

### 5.4 数据记录字段（建议）

每个来源至少保存：`source_id`、`url`、`doi_or_reference`、`license`、`raw_sha256`、`transformation_script`、`derived_sha256`、`schema_summary`、`split`、`used_in_prior_v1_v5`。

每个任务至少保存：`task_id`、`source_id`、`intent_id`、`task_instance_id`、`task_form`、`prompt_variant_id`、`param_mode`、`allowed_tools`、`budgets`、`fault_pair_id`、`fault_mode`、`seed`、`public_manifest_sha256`。

**评测器私有字段**：`oracle_reference`、`hidden_commit_state`、`injection_point`、`canonical_artifact_hash`、`allowed_safe_action_set`、`private_commit_log`。不得注入 Agent prompt、工具说明、可访问文件路径或训练样本。

## 6. 主指标与统计方法（必须机器可执行）

在最终评测前发布指标的代码定义、分母、缺失值处理与判定门槛。建议首版主指标如下：

| 指标 | 推荐计算口径 | 特殊说明 |
| --- | --- | --- |
| **Verified Task Success Rate (VTSR)** | `独立 verifier 确认任务契约、合法提交状态、必要 stop 均成立的 episode 数 / 全部有效评测 episode 数` | 包含正常和故障条件；额外报告按任务簇聚合 |
| **Safe Fault Recovery Rate (SFRR)** | `在故障 episode 中既完成任务又没有不安全副作用的数量 / 全部有效故障 episode 数` | 终止/升级不算任务恢复成功，但可另计安全终止 |
| **Unsafe Side-Effect Rate (USER)** | `发生至少一次违反预注册操作契约的真实副作用的 episode 数 / 全部有副作用风险的有效 episode 数` | 同时报每百次风险操作的事件数；幂等重复调用不能自动认定不安全 |
| **Appropriate State-Handling Rate (ASHR)** | `在预定义状态决策点采取可接受动作集合之一的次数 / 全部有效状态决策点数` | 使用可接受动作集合而非唯一 gold 动作；区分检查是否必要或多余 |
| **Safe Abstention Rate (SAR)** | `确实不可确认且继续会违反安全约束时正确停止/升级的数量 / 所有预注册的不可确认情景数` | 与完成覆盖率、过度拒绝率同时报告，防止“全部拒绝即安全” |
| **Cost per Verified Success** | `总生成 token / 工具调用 / 环境执行次数 / 墙钟或 GPU 时间 ÷ VTSR 成功任务数` | 分项列出；成功数为零时设 `N/A`，不填零 |

**状态识别准确率作为可选诊断指标：** 只有在协议显式要求模型输出结构化状态判断、且此判断可由合法观察推断时才计算。没有显式判断输出时使用 ASHR 评价**行为决策**，不要根据事后真值虚构“模型识别了状态”。

其他必须报告的辅助量：正常条件 VTSR、故障条件 VTSR、`normal − fault` gap、模型错误类型、检查调用数、超预算率、过度拒绝率、最差来源表现、语言/任务形态/参数难度切片及覆盖率。

### 6.1 统计原则

- 同一任务的中文/英文改写、不同故障、同一种子重复运行是**相关观测**，不能当作互相独立的任务提高显著性。
- 主报告包含每来源表现、任务簇宏平均、最差簇、跨模型**配对差异**；多随机种子模型分别报告种子结果。
- 采用按来源和来源内任务簇的分层重采样、或其他尊重层级结构的区间估计；来源少时须承认区间不稳定，不虚构显著性。
- 预先指定主要模型对比与多个指标的优先级；探索性切片与一次性确认性结论分开标识。
- 评分器运行结果须可由提交的独立审计脚本重建，原始动作和环境事件应能回溯。

## 7. 基线、赛道与公平性

### 7.1 首版主基线

1. **Expert oracle（上界/任务可达性检查）**：不是学习型 Agent 排行榜参赛者。
2. **Rule-based recovery**：合法状态查询、幂等检测和保守重试规则。
3. **Fault-blind policy**：不检查提交状态的对照，用于衡量状态信息价值。
4. **Prompt-only LLM Agent**：至少选不同模型家族/规模的代表，使用统一工具协议；不同 API 的可用性和成本单独记录。
5. **V5 SFT、DPO、GRPO**：在同一新基准上重跑并注明初始模型、训练来源、权重是否可公开；旧版本不完整可复现时不得以历史汇总替代新对照。
6. **可选 V5.0.15-beta.2 策略**：仅在模型已经训练且其选择未使用最终测试时加入；不得成为基准唯一主要模型。
7. **通用 Agent 策略对照**：若资源允许至少加入一种合理的状态查询/反思/工具恢复框架，防止仅比较自己实现的学习器。

所有模型使用相同数据访问边界、相同工具集合与版本、相同评测器和预算定义。若 token 定价、闭源 API 或模型推理配置不同，应完整报告，不能虚称严格等计算预算。

### 7.2 仅保留两个 Agent 赛道

- **Prompt-only Agent**：固定模型权重，仅允许合法提示/编排/工具适配；不使用基准训练标签更新权重。
- **Fine-tuned Agent**：允许训练侧更新权重；须提供训练来源、方法、适配器或可复现模型标识、摘要及运行记录。

两个赛道均区分 `Controlled-binding` 与 `Autonomous-binding` 子切片。

**System Reliability 不列入首版排行榜。** Go 调度、租约、设备独占、取消、迟到结果隔离、C++/NPU 等保留为实现与复现基础设施；若形成独立科研贡献，另立系统研究问题。

### 7.3 数据泄漏防线

- Agent 无权读取 `oracle_reference`、隐藏故障标签、私有回执、评测器内部路径、真实提交日志和 gold 产物。
- 执行器 API 不返回“你答对了吗”一类来自私有 gold 的评分反馈；合法验证只提供真实可观察的过程事实。
- 训练侧只能使用 `train` 来源；开发侧用于选择方法和定位失败；正式确认前锁定最终测试模型与提交配置。
- 公开任务与隐藏评测版本分离，记录模型/适配器版本与全部使用的评测集；检测到训练数据与测试来源重叠时单列说明或取消确认资格。

## 8. Verifier 正确性与现实有效性验收

**评分器需要比模型更可靠。** 在进行大规模多模型评测前，至少完成：

- 正确专家轨迹、正确但不同动作路径、等价数值产物、不等价错误产物、额外动作和过早 `stop` 的成对测试。
- 含顺序语义（如滚动均值）的任务不得错误接受行置换；不依赖顺序的任务可按契约允许等价顺序。浮点容差、缺失值、日期/类别标准化规则逐工具规定。
- 提交前失败、提交后确认丢失、暂存残片、已撤销迟到结果、重复写入和外部取消的独立故障反例。
- 故障执行后源数据与有效状态不被污染，原始输入 SHA-256 和操作日志一致；已取消或被 fencing 的操作不能在未授权情况下进入有效提交。
- 用人工审查的一组代表性任务核验自然语言需求、标准答案和评分器输出；记录发现的标注争议与修正。
- 检查任务描述中是否存在泄漏路径、任务 ID 捷径或工具返回的隐含答案。

**可达性门槛：** 专家必须在正式确认集的每个预注册有效 episode 上通过独立 verifier；任何例外要在查看被测模型结果前按预定规则处理。专家通过不等于模型正确。

**现实性边界：** 首版是受控故障研究环境，不宣称已覆盖恶意代码执行、真实分布式生产系统或所有操作系统级隔离。若讨论现实故障代表性，需有公开故障案例或工程文献支持，并说明人工注入与真实故障差异。

## 10. 版本路线与硬验收门槛

### 阶段 P0：立即开始，不等 V5 训练完成

- [ ] 编写指标分母与允许动作集合的机器可执行单元测试。

**退出门槛：** 至少有一个被相关工作对照支持且可运行的非平凡研究缺口；状态歧义问题在理论上可观察或允许安全终止。

### 阶段 MVP：1–2 周小规模概念验证（先验证研究问题）

**退出门槛：** 新故障语义能稳定导致可解释的行为差异；如果不同模型完全无差异，分析是任务太简单、检查无效还是研究问题本身不足。

- [ ] 使用 **3 train + 3 dev + 0 final test** 来源；旧来源要标记为已见。
- [ ] 完成 Recovery/Verification、至少四类核心故障条件与公共/私有协议 schema。

- [ ] 固定基线运行接口，输出统一审计 JSON。

**退出门槛：** 第三方在相同代码和输入下能重建确定性故障状态与 verifier 判定。

### 阶段 `alpha.2`：综合任务与广泛基线

- [ ] 扩展 Planning/Composed，并提供 Controlled-binding / Autonomous-binding 对照。
- [ ] 增加语言改写、来源内任务多样性和未见工具组合的开发诊断。
- [ ] 补足不同模型家族和通用 Agent 基线；完成 cost 与安全行为指标。
- [ ] 检查模型强弱与恢复能力是否能被指标区分，避免全部满分或全部失败。

**退出门槛：** 核心指标不仅反映题目难度，还能稳定区分多种不同的失败机制。

### 阶段 `beta.1`：一次性论文确认

- [ ] 新增 **≥6 个真正未使用的最终测试来源**；训练/开发/测试来源完全不交叉。
- [ ] 在看到正式模型输出前冻结 `frozen_eval_manifest`、模型、指标、种子、实验次数、统计方法和止损规则。
- [ ] 专家全量校验；正式运行全部指定模型并输出完整审计与多层统计。
- [ ] 主论文只使用这一轮冻结确认数据作 OOD 核心证据；后续修改只能另建确认集。

**退出门槛：** 至少产生可信的跨模型/跨故障可靠性发现，且不会被简单基线、Verifier 错误或统计相关性解释掉。

### 阶段 `1.0`：投稿与开放发布

- [ ] 发布任务/数据卡、来源许可、转换脚本、评测器、基线、统一运行说明和限制。

- [ ] 将确认测试与后续 leaderboard 测试版本区分；不能用已公开反复调试的集继续声称盲测。
- [ ] 核对当届 KDD CFP（Track、页数、开放要求、伦理、截止时间、作者义务）并独立完成模拟审稿。

## 11. 论文主图与主表的预期（不是现有结果）

1. **故障状态可辨性图：** 相同首条错误、不同隐藏提交状态下的检查率、错误重试率、安全恢复率。
2. **成功与安全背离图：** Verified Task Success vs Unsafe Side-Effect Rate，展示只看终局结果会遗漏的行为。
3. **分布偏移图：** 新来源、新措辞、未见组合、新故障以及联合 OOD 的分组结果。
4. **任务簇级配对表：** 每模型/方法的来源宏平均、独立簇 CI、最差来源、过度拒绝与推理成本。
5. **Benchmark 必要性消融：** 去掉状态查询、去掉非幂等操作或只计算终局成功，比较哪些失败不再可测。

出现无差异、结果反向或负结果均需如实报告；不能根据最终测试表现事后修改指标以制造显著结论。

## 12. 成功条件、停止条件与主要风险

### 12.1 成功条件

- Benchmark 可稳定区分**模型选错工具、环境外生故障、恢复不当造成真实副作用、合理的状态查询/保守终止**。
- 评分器和状态机具备明确的适用范围、反例测试及第三方复现方法。
- 在不同来源和不同模型上发现新且可信的可靠性现象，并展示为何既有终局成功率不足。
- 相关工作矩阵支持 Benchmark 的增量价值，而不是简单功能堆叠。

### 12.2 暂停/转向条件

- 若合法查询永远无法区分状态，且没有有意义的风险权衡：重新设计环境观察与可执行动作。
- 若主要“副作用”来自重复幂等操作而没有真实状态风险：先引入合理的非幂等语义，再讨论安全恢复。
- 若相关工作已有几乎相同的任务、故障模型和评价：考虑扩大科学问题或转向独立方法论文，不强行投稿同质 Benchmark。
- 若专家无法稳定通过、评分器接受错误结果、来源授权不清或最终测试泄漏：**停止确认性评测**，修复并重新冻结协议。
- 若只得到工程结果而无可复核的科学发现：暂不主张已经达到 KDD 论文标准。

### 12.3 风险登记

| 风险 | 缓解 |
| --- | --- |
| 故障注入过度理想化 | 明确故障来源与提交边界；增加公开的真实故障案例参照 |
| 任务过少、来源同质 | 分开统计任务簇和 episode，增加跨领域来源，避免模板复制膨胀 |
| 参数已固定导致过易 | Controlled-binding / Autonomous-binding 分开评测 |
| 状态不可观察却要求猜真值 | 提供有限合法查询、`indeterminate` 和安全升级 |
| Verifier 泄漏 gold 或限制等价路径 | 公私协议隔离，独立反例与人工核验 |
| “重复操作”实际无副作用 | 显式幂等契约、非幂等真实业务场景、操作日志核验 |
| 训练/评测污染 | 历史来源 seen 标记；新最终测试一次性冻结 |
| 论文范围过散 | Agent 安全恢复为主；Go/C++/NPU 仅做基础设施说明 |
| 开源权重和许可不完整 | 模型哈希、替代基线、数据许可证清单与复现限制披露 |
