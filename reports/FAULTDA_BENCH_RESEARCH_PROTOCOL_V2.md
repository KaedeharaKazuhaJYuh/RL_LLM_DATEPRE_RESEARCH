# FaultDA-Bench 研究协议 v2：证据约束下的分析语义恢复

日期：2026-10-09。状态：**修订后的执行规划，尚未通过创新性与实证门槛**。适用于 `faultda-bench`，不改变 `v5` 模型结果。

实施进展：首个开发版本 `0.2.0-dev` 已实现受控任务与强基线，并完成单模型接入，见[版本报告](../faultda_bench/reports/SEMANTIC_V1_RELEASE.md)。下文保留规划定义；独立人工审阅、第二模型、完整隔离和最终确认条件未完成，不能把开发版本当作整个协议验收。

## 1. 与 v1 的关系及修改理由

保留用户原始 [v1](FAULTDA_BENCH_RESEARCH_PROTOCOL_V1.md) 不变。本版替代 v1 的研究定位、贡献候选和接下来实施顺序；来源隔离、真实副作用、公共/私有信息边界、可复现和禁止测试集调参等约束继续生效。冲突时以本版明确列出的修订为准。

UndoBench 已研究正常能力与恢复能力分离、故障成对干预和副作用安全；其仓库还列出主动探测/谨慎弃权基线。Verified Tool Calls 已研究后置条件验证与幂等恢复。原 P0 的主要机制应作为已有思想的本地开发对照，不能作为原创核心。[核验与证据边界](../faultda_bench/docs/OVERLAP_AUDIT_2026_10_09.md)

“旧证据”“带预算的检查”“确定性分析评分”也不是单独的创新点。新的候选增量是：**在同一数据分析任务中，联合操控提交歧义与语义证据缺口，测量两者是否产生简单组合基线无法解释的恢复失败，以及这种失败能否在等成本下减少。** 这是可证伪的假设，尚不能宣称文献空白。

研究用途按会议论文级别准备可审计证据；不预先承诺录用、效果提升或特定会议门槛。README 只描述技术范围、使用方法及已验证结果。

## 2. 研究问题与候选贡献

暂定中文定位：**FaultDA-Bench：证据约束下数据分析 Agent 的语义恢复评测**。保留项目名，收窄问题。

| 问题 | 可检验假设 | 不支持该假设的结果 |
| --- | --- | --- |
| RQ1 耦合失败 | 提交歧义与分析语义扰动同时存在时，失败增加超出两者各自增量 | 联合失败可由单因素结果解释，或仅是预算减少造成 |
| RQ2 检查分配 | 同预算下，针对具体分析契约选择证据比固定查询顺序更有效 | 通用恢复规则加静态语义验证已达到同等表现 |
| RQ3 归因与泛化 | 有效方法在独立来源与新意图组合上仍有收益，且收益来自决策 | 收益仅来自去重、强制注入关键证据、模板记忆或更多调用 |

候选交付物：带公开分析契约的因子化任务集；可分离提交、语义、证据和副作用的评测协议；跨来源可复核的经验结果。不是以新指标数量、CSV 包装或题量作为贡献。

## 3. 最小差异实验：先证明值得扩展

第一轮仅使用开发数据。三类意图各人工审阅至少四个独立任务实例，共至少 12 个开发实例；这不是最终样本量，也不是 12 个独立来源。

| 意图 | 正常分析契约 | 语义扰动 | 必须能获取的合法证据 |
| --- | --- | --- | --- |
| 分组汇总 | 指定业务键、过滤范围、缺失值政策和分组总量 | 多对多连接放大行数，整体数值看似合理 | 键重数、连接计划、分组计数及必要行样本 |
| 时间窗口 | 指定时区、窗口闭合方向、排序和缺失日期策略 | 边界/时区错位、乱序滚动 | 原时间值、转换配置、窗口边界和产物片段 |
| 版本绑定分析 | 明确采用请求时快照或提交时最新版本，二者分轨 | 缓存产物绑定旧快照；数值对旧输入确实正确 | 授权版本清单、实际执行血缘、产物修订号 |

按相同基础实例与初始环境建立 2×2 对照：C0S0 无扰动、C1S0 仅提交确认丢失、C0S1 仅语义扰动、C1S1 二者联合。语义扰动通过真实工具参数/数据关系/缓存路径产生，不只伪造一条错误消息。另加提交前失败和部分写入作外部边界验证，不混入主 2×2 估计。

每组再按证据条件 E 划分：E0 可直接取得充分证据；E1 必须组合多个合法检查；E2 在给定动作与预算下不可充分确认。E2 单独评安全升级，不计入“本可恢复”的主成功率。检查预算先用 2、4、6 次扫描；耗时、token、风险调用另记，不把一次巨大数据读取与廉价状态查询视为完全等价。使用统一分页与返回大小限制。

核心例子：报告已提交且 operation_id 正确，但按错误连接关系汇总。仅查 committed 会错误停止；重新计算再追加会产生第二份报告。Agent 必须先判断已有产物与任务契约是否一致，再按授权修复协议更正。数值正确但来源版本不被授权也不合格；请求时快照轨道中，合法旧快照不能误判为过期。

## 4. 环境与权限：哪些需要新增实现

P0 保持 `0.1.0-p0`，原 84 条结果保持原义。下列功能是**下一实现版本 `0.2.0-dev` 的待办**，不能用当前探针声称已支持：

- 公共任务契约：输入范围、输出 schema、分析政策、版本语义及允许的修复方式；自主绑定轨道不提供正确列名答案。
- 私有 oracle：从授权原始快照独立重算，检查分组/窗口/数值、血缘、最终有效产物唯一性及全过程副作用；不使用 Agent 生成的血缘声明作为可信真值。
- 合法观察工具：提交状态查询、产物检查、源版本/血缘查询、限定数据读取。返回事实而非 `correct=true`、参考答案或故障标签；失败与不可用也计费。
- 新修复动作：先暂存更正，再以 expected_revision 做比较并交换，将旧报告标记 superseded。保持历史审计；禁止靠删除日志掩盖重复效果。修复自身若丢失确认，仍需查询，不无限重试。
- 风险语义：每个契约标明暂存、发布、下游消费的边界。可更正错误按终态恢复和历史错误发布分别记分；不可逆的重复下游消费不能因最终只剩一条记录就消失。
- 可辨性：用环境状态对与合法观察轨迹检验 E2；不能根据事后真值决定 Agent 本应猜到什么。若检查组合足以区分，就不能标为不可辨。
- 执行隔离：私有 oracle、故障种子、评分日志与数据修复权限均不进入 Agent 文件系统；当前 Python API 边界不能代替进程隔离。

正常轨与扰动轨提供相同工具权限、预算和提示模板。配对使用相同初始快照/环境种子和冻结模型；相同模型 seed 不代表不同对话路径会得到相同采样结果。API 不支持确定性 seed 时，按随机交错顺序重复并记录时间、模型版本与参数。

## 5. 必须设置的对照

| 基线 | 目的 |
| --- | --- |
| 盲重试 / 全部升级 | 检验副作用与成功率是否被单一指标掩盖 |
| 通用 verify-before-retry + 幂等键 | 对照已有恢复机制；关闭/开启幂等分别报告 |
| 通用恢复 + 静态分析语义校验 | **关键强基线**，检验简单组合是否足够；享有与候选方法相同合法数据访问 |
| 来源版本刷新 + 通用恢复 | 排除只是处理陈旧上下文；若称 Concord/REVISE 复现，必须核对并记录其实现版本，否则称受启发的适配 |
| 同一 LLM 的固定检查、随机检查、任务条件检查 | 等模型、等权限、等预算分离检查分配收益 |
| 强制关键证据 / 全知 oracle | 仅诊断上界，明确特权，不进公平排行榜 |

先做 Prompt-only：DeepSeek 为连续性主基线，增加至少一个不同模型家族；没有 API 实跑就不填写模型分数。模型、提示和调用设置先冻结。不得仅选择弱小模型制造差距。

Fine-tuned/RL 另轨开展：同一初始权重、同轨迹与预算对比 SFT、继续 SFT 和 RL；训练侧验证器可提供奖励，最终测试 oracle 严格隔离。至少三训练种子只是最低开发要求，不保证统计功效。只有基准缺口成立后才投入训练，不为了延续 RL 主题先承诺提升。

## 6. 指标与统计约定

新版本主报“契约完成率”：终态满足授权分析结果、版本与有效产物唯一性 / 该条件全部 episode；再报“安全完成率”：前述成功且无契约禁止的历史副作用 / 同一分母。保守升级不算完成。历史错误发布、重复消费、输入污染分别报事件率，不以修复成功抹除。

P0 的 VTSR/SFRR/USER/ASHR/SAR 不改名重算。新指标输出必须标 `0.2.0-dev`，禁止与 P0 混池。自主绑定不沿用 P0 的固定动作允许集作为金标准；合法但非最短的检查以成本体现，不武断判错。

补充诊断：虚假完成 = 错误终态却宣告完成 / 全部宣告完成；同时给其计数 / 全部 episode。不可辨条件的安全升级率以预定 E2 为分母，可辨条件过度升级率以 E0/E1 为分母；零分母为 null。报告完成率—成本和风险—覆盖曲线，不通过全拒绝取得“安全第一”。

在每个 E0/E1、预算和基线内，令 p_cs 为契约失败率，主交互量为 I = p_11 - p_10 - p_01 + p_00。正值是加性尺度上的额外失败，不自动等同普遍因果机制。报告四个单元原始计数、区间和基线成功支持度；全失败造成的天花板/地板效应需单列。并报告正常配对成功子集上的条件恢复率，避免单用条件率隐藏基础能力不足。

按原始来源聚类重采样，保留每个来源内部的实例、种子、同义改写和四个条件成组关系；另报告逐来源结果及意图敏感性分析。同一原档案派生 CSV 不是新来源。开发阶段估计簇间变异再确定确认样本量、最小有意义效应和重复数，**在看到最终数据前冻结**。多方法/多指标明确主比较与多重比较处理。

## 7. 数据隔离与阶段验收

沿用 v1 的 3 train + 3 dev 开发来源目标；最终至少 6 个全新独立来源，来源数是项目设计目标，不是会议要求。当前历史来源全部开发侧。冻结清单包括来源许可、原文件哈希、谱系、任务生成版本、public/private schema、预算、指标与模型参数；确认集不得用于故障模板设计或选择最有利模型。

1. **现在：定位修订。** 核查重叠、保留原始协议、建立本版强对照与退出规则。完成本步不代表完成新环境。
2. **最小可行性验证。** 实现第 3–4 节的至少 12 个开发实例与 2×2 对照，先用固定程序测试状态、评分器和反例，再在冻结开发方案上跑两模型；不读最终来源。
3. **继续或收束决策。** 若差异只在通用恢复＋静态校验未实现时出现，或来源变换只是相同动作重放，保留为工程扩展，不扩大原创性主张。若独立任务上出现可解释交互且强基线仍有缺口，再扩六开发来源。
4. **正式确认准备。** 完成许可、人工任务审阅、最小效应/功效评估、基线复现和外部复核；冻结后一次性运行全新来源。负结果与协议偏差一并保留。

明确中止原创性主张的条件：查新发现等价实验已被覆盖且无实质增量；候选方法只靠多花成本或 oracle 泄漏赢；在合理模型/来源上没有可复现缺口。此时项目仍可作为复现与工程研究，不靠增加题量掩盖问题。
