# V4 初步：DeepSeek 与奖励学习

用户选择保持 DeepSeek，现有接口与请求格式继续沿用。默认模型为 deepseek-chat，温度默认为 0，可通过 DEEPSEEK_MODEL 与 LLM_TEMPERATURE 显式配置；每次实验保存实际模型配置。历史实验温度曾为 1.0，因此新旧结果只有在配置、任务和验证器一致时才能直接比较。

## 本轮完成

增加 DeepSeek + 上下文 Bandit 的最小实验：LLM 为任务提出工具建议；学习策略输入由公开任务/数据特征和 LLM 建议组成；执行选中的工具后，通过独立验证器的分数更新相应动作；验证阶段冻结权重。学习器不读取正确动作标签，task_id 仅用于缓存查找，不进入特征。

三个比较组为直接执行 DeepSeek 建议、仅使用本地特征的 Bandit、增加 DeepSeek 建议的 Bandit。两个学习组使用相同训练顺序种子与交互次数。保存训练动作/奖励、学习曲线、验证轨迹和各策略检查点，验证前后检查权重哈希一致。LLM 请求时间计入两个含 LLM 的验证组预算。

首轮默认 12 个训练任务、12 个验证任务、6 轮训练、3 个学习种子。请求总量最多 24 次，同一任务的 DeepSeek 建议由各策略共用；这些学习种子不是三次独立 API 重复。数据使用已有 V2 的训练/验证划分，仅用于开发试跑，不访问其 test 划分，也不建立 V4 外部盲测结论。

## 凭据与运行

支持当前进程 DEEPSEEK_API_KEY，或仓库根目录下被 Git 忽略的 .env.local。该文件可保存 DEEPSEEK_API_KEY、DEEPSEEK_MODEL 和 LLM_TEMPERATURE，进程配置优先。请在本机填写密钥，不要发送到聊天或提交到 Git。

```text
python -m research.v4_readiness
python -m experiments.v4_pilot --limit 12 --epochs 6 --out work/v4_deepseek_pilot_001
```

输出目录必须不存在，避免覆盖旧实验。API 中途失败时保留已取得的建议和脱敏失败类型；没有自动重试或续跑，避免无意重复付费。summary.json 记录请求数、输入/输出 token、API 耗时和比较结果；费用金额暂不推算，待确认账单单价后补充。

## 与课题的关系

这是“冻结 LLM + 外部奖励学习策略”的起点，是一步决策的上下文 Bandit，不是 PPO/GRPO，也没有更新 DeepSeek 权重。它先检验语言模型建议是否能帮助奖励驱动的动作选择，以及学习策略是否优于直接采纳建议。

如果课题要求直接对 LLM 做 RL 微调，后续需要支持权重训练的开放模型与训练算力。DeepSeek 托管接口当前用于对照、建议和轨迹采集；本项目尚未实现其权重更新接口。

## 当前验证与下一步

44 项本地回归测试全部通过，包含模拟客户端完整链路、奖励更新、验证冻结、缓存 ID 不进入特征、错误脱敏和结果不覆盖。模拟客户端结果不作为真实 DeepSeek 成绩。当前未检测到密钥，真实 API 请求数为 0。本地配置模板显式设置温度为 1.0，与早期 DeepSeek 记录保持一致；未配置该值时客户端默认仍为 0。

下一步先配置密钥并跑 24 次请求的开发试验，检查实际 token/延迟与失败类型；随后扩大开发数据与独立 API 重复次数，增加多步状态和终局奖励；在这些条件稳定后再比较监督初始化与多步 RL，最后冻结外部测试。
