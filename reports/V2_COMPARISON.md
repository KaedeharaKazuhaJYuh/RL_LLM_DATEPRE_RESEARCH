# V1 与 V2 本地修复及对照实验报告

## 版本与结论

V1 固定于 `e59cbb5669f4d6e681fe51d38a60ab6d2cae6cb3`；本地保留完整 Git 副本。V2 位于独立分支 `codex/v2-verifiable-routing`。本次在 Python 3.12.14、NumPy 2.3.5 下执行，未调用任何真实 LLM API。

**V2 修复了实际分析和验证的主要缺陷；目前并没有证明 RL 优于简单规则。** 共同测试中 V1 通过 15/72，V2 规则通过 72/72；V2 中规则、监督与 Bandit 五次实验都达到 100%，说明这个控制基准已经饱和，下一步应增加未见模板与外部数据，而不是继续追求该集合的分数。

## 本地目录

- V1：`../v1`
- V2：`../v2`

V1 的受版本控制源文件未修改；运行 Python 产生的缓存不属于代码修改。V2 保存了旧任务与历史报告供追溯，但正式入口不再接受旧任务 schema。

## 修复范围

| 原问题 | V2 处理 | 边界 |
|---|---|---|
| CSV 是读取失败文本且路径不符 | 恢复两处历史路径的三张真实 CSV；新增数据清单、哈希、schema 校验 | 历史评分不重新包装成独立验证结果 |
| 清洗只返回固定审计值 | 中位数填补、日期解析、截断、类别规范化、去重会保存实际 CSV | 截断阈值和列名来自公开参数；未学习参数选择 |
| 任务编号决定分析 | 取消 task_analysis 与编号干预；规则只读任务文本 | 旧 T12–T50 被明确标为历史原型，不声称全部功能已完成 |
| 参考输出同源 | 独立 NumPy/参考循环 oracle，不调用被测工具；增加手算案例 | 仍需要更多独立人工抽检与边界测试 |
| 错误也有高奖励 | 缺 oracle 抛错；答案、哈希证据、真实产物、合法性、预算全部通过才得分 | 证据为执行收据，不是密码学隔离的防恶意环境 |
| Bandit 看不到需求 | 文本哈希特征加具名数据 profile；去除单候选掩码 | 文本模板很有限，尚不代表开放语言泛化 |
| 训练与评估混合 | 216 训练、72 验证、72 测试；按 30 个生成数据实例分组；测试冻结 | 是合成实例划分，不是 30 个真实外部来源 |
| 轨迹缺失 | 保存提议/执行动作、参数、观察、结果、下一状态、概率、终止原因、成本和版本 | 当前明确是单步；尚未实现多步 Offline RL |
| 文件通配易混合 | 显式矩阵 manifest；汇总拒绝旧版或混合元数据 | 重放文件产物需本地 artifacts 或重新运行 |
| LLM 适配输入含混 | 保留可选 DeepSeek 路由，提供工具描述、公开参数和具名状态，记录调用/token | 仅 mock 测试通过；没有密钥，真实调用未验证 |

V2 对调用数、步骤数、执行前后耗时做预算检查。超时结果失败，但本地 Python 工具没有操作系统级抢占式终止；它仍不是任意代码执行沙箱。没有为未完成的多步恢复、模型训练、绘图或开放业务报告功能宣称完成。

## 实验一：V1 原生诊断

V1 原生 Rule 为 50/50。无合同保护 Bandit 的 seed 1–5 为 14、16、15、14、15 /50，均值 29.6%。这是一遍在线学习结果，不能与 V2 的多轮训练后冻结测试直接计算提升比例。

直接调用 V1 原有 8 个测试函数，7 个通过、1 个因数值变体路径缺失失败。V2 的 unittest 测试为 25/25，覆盖真实产物、手算 oracle、错误奖励、证据、预算、缺文件、编号不变性、状态区分、冻结评估、模型保存恢复和模拟 LLM。两套测试不同，不把 7/8 与 25/25 当作同一测试集的准确率比较。

## 实验二：共同输入、共同独立评分

测试为 6 张未参与训练的合成表 × 12 种操作，共 72 题。两版得到相同 CSV、题目和一次工具调用预算；评分采用 V2 独立 oracle，清洗题要求真实结果文件。

V1 通过其原运行器执行。适配器只捕获原工具输出、规范化 schema 回答形状，并产生可核实的输入读取收据，不补算其答案或替它生成清洗文件。为兼容 V1 编号分支，还给它对应的历史任务族编号，因此 V1 保留了额外编号先验。此对比衡量系统对新任务的适用性，**不是控制工具实现不变的策略算法对比**。

| 指标 | V1 | V2 Rule |
|---|---:|---:|
| 成功任务 | 15/72 | 72/72 |
| 通过率 | 20.83% | 100% |
| 单任务平均墙钟时间（含预扫描） | 0.277 ms | 1.197 ms |

V1 的 15 个成功来自 schema 6 题、缺失率 6 题、类别计数 3 题；后三题类别计数因中文列名失配失败。其余失败来自数值缺失处理、固定列名、没有真实清洗产物或根本未执行对应运算。

V2 本轮约慢 4.3 倍，但表很小，绝对差约 0.920 ms。它做了 V1 未做的产物写入和完整校验，因此不能将这个差异全归因于策略开销。该单次微型运行还受文件缓存影响，不能外推到大表或远程 LLM 延迟。

## 实验三：V2 内部学习与状态消融

每个种子测试 72 题。Bandit 固定 alpha=0.5、6 个训练 epoch，共 1296 次交互；监督分类器使用 216 个训练动作标签；规则不训练。参数在本次开发试验中固定，未用验证集调优，也未因测试分数反复调参。

| 方法 | seed 1–5 成功题数（每次 /72） | 平均通过率 |
|---|---|---|
| rule | 72, 72, 72, 72, 72 | 100.00% |
| supervised | 72, 72, 72, 72, 72 | 100.00% |
| bandit | 72, 72, 72, 72, 72 | 100.00% |
| random | 6, 4, 4, 4, 8 | 7.22% |
| majority | 6, 6, 6, 6, 6 | 8.33% |
| bandit_data_only | 6, 6, 6, 6, 6 | 8.33% |

数据特征消融保持数据、奖励、训练轮数和算法不变，仅移除文本特征。其 8.33% 与完整状态的 100% 对照，说明任务意图对当前路由任务不可缺少；不说明通用语言理解已经解决。

由于同一文本模板在各分区都出现，规则和监督方法同样满分。**当前应优先选简单规则作为成本基线；Bandit 的贡献是可运行的学习对照，不是已证明的最终最佳方案。** 五个 seed 的同题重复不等于 360 个独立测试问题。

## 复现

在 V2 根目录安装 `numpy==2.3.5` 后：

```text
python -m unittest discover -s tests -v
python -m scripts.run_matrix --out-dir reports/my_run --epochs 6
python -m research.compare_v1 --v1-root ../v1 --out-dir reports/my_comparison
```

实验拒绝覆盖已有同名输出和产物空间；更换 out-dir 可开始新实验。`research.benchmark` 可确定性生成任务与恢复历史 CSV；数据哈希在各平台使用 LF 行尾。

逐题日志位于 `reports/v2_release_20260913/`，状态消融位于 `reports/v2_data_only_20260913/`，共同实验位于 `reports/v2_release_comparison_20260913/`。训练日志、模型参数和实际生成的 CSV 位于本地 `artifacts/`，不随 Git 提交；完整观察及表格内容在结果日志中保留，重跑可重新生成文件。

## 后续优先级

1. 增加完全未见的指令模板与真实外部数据；不能仅更换数值后再次报告满分。
2. 扩大 oracle 的手算与变异测试覆盖，加入日期、缺失、单位和排序边界。
3. 在具备真实中间状态、可修复错误和延迟奖励后，再实现多步环境与 Offline RL。
4. 配置现有 DeepSeek 密钥后单独跑真实 LLM 对照，并记录 token 成本；本次不能评价 LLM 性能变化。

本次没有改变 main，也没有把 v2 结果与旧表混合为一个“算法提升百分比”。
