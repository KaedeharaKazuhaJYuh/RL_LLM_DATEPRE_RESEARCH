# V4.5.8 计划：真实数据、故障恢复与原生工具验证

V4.5.7 已加入独立的 C++17 移动平均原型，位置在 `native/`。它只接受有限的 `double` 数组与正整数窗口，并返回完整窗口的均值；不解析 CSV，也没有接入 Python 的 `rolling_mean` 工具、验证器或 RL 训练。因此现有实验仍使用原 Python 实现。这个原型仅用于建立编译和接口边界，尚无跨语言差分或性能结论。

V4.5.8 把以下工作作为同一个可复现的研究阶段，而非只增加语言占比：

1. **公开真实 CSV**：选取许可允许重新分发或允许公开下载且来源稳定的数据，保存来源、许可、版本、下载日期、原始摘要和脱敏检查。先冻结原始文件，再生成任务与训练/开发/盲测拆分，避免同一原始记录或改写答案跨集合泄漏。真实数据须与合成任务分别报告。
2. **同义改写**：为同一任务构造不改变工具顺序、参数和目标结果的中文与英文改写，人工或程序复核语义等价。按任务族、数据来源和改写类型分层报告，避免只靠词面变化制造“泛化”成绩。
3. **超时与部分写入故障**：在受控子进程中注入慢执行、超时、仅写入部分 CSV、写后崩溃等情形；记录故障阶段、输入/输出摘要、退出码和是否留下残留文件。故障注入可重复，训练与盲测故障模式隔离。
4. **工具进程隔离与状态验证**：每次工具调用使用隔离的工作目录与明确的时间、内存和输出大小限制；取消或超时后确认进程树退出。将临时产物校验后原子登记，验证列、行序、行数、内容摘要、文件完整性以及失败后输入和已登记状态未被破坏。Windows 与 Linux 分别验证进程树清理语义。
5. **C++ 原型验收**：在现有 Python 工具保持默认的前提下，对数值有效性、空输入、窗口边界、浮点误差和真实 CSV 的转换成本做差分测试；再测小表与压力表的完整流程耗时。只有正确性和端到端收益达到 [V5 架构规划](V4_5_7_V5_ARCHITECTURE_PLAN.md)的门槛，才考虑可选 Python 绑定。若未达到，就保留原型作为负结果。

交付时应包含数据来源清单、固定划分与摘要、故障矩阵、进程隔离与状态不变量测试、C++ 差分及端到端计时、按切片报告的成功率和失败案例。V4.5.8 完成之前，不把 C++ 原型计为已经加速生产工具，也不把公开 CSV 等同于最终外部盲测。
