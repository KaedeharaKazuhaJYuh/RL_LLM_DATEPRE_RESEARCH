# V5.0.0：首个正式研究版

日期：2026-09-29。V5.0.0 将 alpha.2 的 Python/C++/Go 执行链路与 beta.1 的 DeepSeek 在线 RL 配对审计冻结为一个可复核的**研究软件基线**。正式版表示接口、协议、版本信息和现有验证材料已整理完成，不表示 RL 模型已在任意新任务上稳定胜过监督学习，也不表示 Go 已实现多机分布式调度。

## 本版交付

- Python 保留数据任务、验证器、DeepSeek LoRA SFT/DPO/GRPO 训练及冻结评测的主实现。首次新来源加新措辞测试的失败结果和第二次来源留出确认均保留在 [beta.1 报告](V5_BETA_1.md)及机器可读审计中。
- C++17 滚动均值共享库通过 C ABI 与 Python `ctypes` **可选**接入。已验证数值差分和真实 CSV 完整 episode；仅在明确设置 `V5_ROLLING_BACKEND=native` 与 `V5_ROLLING_LIB` 时启用。大表探针观察到提速，但小表 LLM 任务仍默认 Python，详见 [alpha.2 报告](V5_ALPHA_2.md)。
- Go 提供单机持久队列、设备独占、租约、取消、失联隔离、人工确认恢复及结果去重。GPU/NPU 本机作业与 Windows 子进程取消已验收；远程工作节点、网络分区恢复和多机吞吐仍未验收。
- `VERSION`、README 和 Python 包元数据统一到 `5.0.0`；[版本规则](../VERSIONING.md)固定后续 `V5.0.05`、`V5.0.10` 等编号，并避开 `V5.0.40–V5.0.49` 与 `V5.4.*`。

## RL 证据与边界

第一次冻结的新措辞两步评测：原三步课程追加 GRPO 后 **11/144**，对应 SFT **12/144**，预设门槛失败。之后仅用旧合成训练来源构造 96 道两步环境奖励课程，在另一批事先冻结的两份新 UCI 来源上，三种子配对合计从 SFT **96/144** 到 RL 更新后策略 **102/144**，新增 11、回退 5；种子净变依次为 **−2、+2、+6**。正式版发布前使用本机原始评测与适配器文件重跑 `research.v5_beta_confirmation_audit`，其输出与仓库中 [冻结审计 JSON](v5_beta1_confirmation_paired_audit.json) **逐字节一致**（SHA-256 `0beddd3e578f849f7d77255821182ba1afc33e566615c0406237055236e3e002`）。

第二轮只留出**数据来源**，提示模板与工具组合已在训练中出现。按任务簇进行的探索性 bootstrap 净变化 95% 区间为 **−7 到 +19**，跨过零；一个种子和一个来源发生净退化，也未做等预算二步 SFT 对照。因此结论限于“二步环境奖励课程后的 RL 策略在这组已见模板、两份新来源上的预设初步门槛达成”，不能单独归因于 GRPO 优于同预算监督训练。beta 权重不设为默认模型。

## 发布验证

在本地完整仓库、Python 3.12 环境下，`python -m unittest discover -s tests -v` **运行 93 项，其中 91 项通过、2 项因未指定可选 C++ 库而跳过**；指定现有 Windows C++ DLL 后，这 2 项单独运行通过。现有 C++ 测试可执行程序通过。Go `test ./...` 全部通过，`research.benchmark` 成功重建 360 道 V2 任务及历史 CSV；版本元数据检查通过，下一编号输出 `V5.0.05`。Python `5.0.0` wheel 构建成功，但 wheel **不含** `tasks/` 和 `data/`，所以复现实验必须使用完整 Git 仓库。发布前 `main` 的最新 GitHub Actions 在提交 `51b1d9c` 上通过；本次正式版的新提交尚须推送后由 CI 再验证。

## 使用和后续

模型权重、原始本机评测日志及设备转换产物位于 Git 忽略的 `work/`，不随公开仓库提供；仓库提供代码、固定协议、公开派生数据、摘要和逐题审计。没有这些相同模型文件或等效重新训练，其他机器可以复核运行逻辑及审计数据，不能逐字节重放模型输出。DeepSeek API 只在需要在线生成或重新训练时使用；静态测试、历史审计和基准重建不调用 API。

下一次编号为 **V5.0.05**。优先补等预算二步 SFT 对照、冻结全新提示模板与第三批新来源、复测 beta 权重在 NPU 上的量化影响；系统侧继续验证真实目标负载的 C++ 端到端收益，以及有认证的远程 Go worker 与多机故障恢复。只有这些门槛通过后，才考虑更换默认策略或声称分布式系统已完成。
