# V3 区分度基准雏形

V3 是规划诊断基准，不是完整的多步执行环境。它先回答一个关键问题：策略能否在没有见过的数据源和提示模板上，选择正确且有顺序的工具计划。

## 三条赛道

- `single`：12 种单工具任务。训练使用直接中文表述，测试使用未见英文/间接表述。
- `composition`：6 种两步组合，要求工具和顺序都完全正确。
- `clarification`：需求信息不足，正确行为是澄清，而不是猜一个工具。

训练集和测试集同时按数据源、字段命名风格和提示模板族隔离。当前包含 24 个合成数据源、480 个任务，其中训练和测试各 240 个。测试评分采用计划完全匹配；多一步、少一步或顺序错误均失败。

## 当前边界

当前版本只评估规划，不执行两步工具链，也不评价中间状态、参数依赖和错误恢复。因此它适合筛掉只会记模板的策略，但不能用来声称完成了多步 Agent 或 Offline RL。

下一阶段应将计划接入状态化执行器：每步重新观察产物，允许最多三步，并分别报告规划正确率、执行成功率、恢复率、调用成本和端到端耗时。

## 雏形结果

在 240 个测试任务上，冻结的 V2 关键词策略与字符三元组最近邻均为 12/240（5%），随机计划五个种子为 9–13/240（均值 4.58%），Oracle 上界为 240/240。V2 的满分现象在这一规划诊断上不再出现。

这个落差包含中英文提示模板族迁移，因此目前主要说明旧方法不能跨模板直接泛化，不能单独归因于多步规划能力。后续需要补充“同语言未见改写”和“只改变任务组合”的正交测试切片。
