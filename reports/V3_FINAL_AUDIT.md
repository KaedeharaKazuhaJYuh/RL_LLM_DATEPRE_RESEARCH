# V3 最终审计与验收

本次将 V3 收束为 **3.6-final 本地诊断基准**。完成范围：合成规划切片、两步文件状态传递、预算控制、真实公开数据上的故障注入、冻结恢复与升级、独立结果验证、子进程超时和可重复运行。它不包含已训练的通用 LLM/RL 规划器。

## 发现的问题与处理

| 问题 | 处理与证据 |
|---|---|
| V3.5 的 85/90 是修复分类结果，被容易误读为端到端恢复 | 新主评估对每种策略独立执行工具并验证结果；旧结果保留为历史记录 |
| 每个来源绑定一种日志，来源与日志影响混杂 | 改为 8 个来源 × 15 个故障案例 × 4 种日志，共 480 条；每折完整留出来源 |
| 阈值只看正确校准样本，空校准可能放行 | 新策略使用全部有效校准标签，在校准零观察错误约束下取最高覆盖率；无可行阈值全部拒绝 |
| 通用异常类型导致错误自动修改 | 空日志或只有异常类型时升级；无执行、无虚构修复成功 |
| 升级与成功修复被合并成高分 | 分别报告覆盖率、接受样本分类准确率、选择性风险、实际执行成功率；零接受时风险为 null |
| 旧规则执行分数借用了学习策略结果 | 已改为独立执行，最终主评估也独立运行无恢复、规则和选择性策略 |
| 多步执行前未检查整体工具权限和调用预算 | 预先检查计划长度、权限、输入哈希；每次调用前检查总调用数和累计时间，重试消耗预算 |
| 澄清分支依赖 gold 决定运行行为 | 根据空计划作出澄清决定，gold 仅参与评分 |
| 同目录重跑可能读到旧子进程产物 | 每次使用新目录，要求正常退出且 JSON 完整；增加启动握手，将启动时间与故障等待分开 |
| Windows 全新检出显示大量旧文件变化 | 历史文本的 CRLF 与 LF 属性冲突，统一换行；前后哈希验证无测试内容污染 |

## 最终结果

主评估每个来源具有相同的日志/故障交叉条件。每折 6 个来源训练、1 个校准、1 个测试；阈值与权重在测试期不变。此协议替代 V3.5 作为主结果。

| 策略 | 测试数 | 自动处理 | 升级 | 实际修复通过 | 接受样本错误率 |
|---|---:|---:|---:|---:|---:|
| 无恢复 | 480 | 480 | 0 | 0 | 100% |
| 固定规则 | 480 | 480 | 0 | 424 | 11.67% |
| 选择性恢复 | 480 | 355 | 125 | 355 | 0%（观察值） |

选择性恢复覆盖率与全样本执行成功率均为 73.96%。125 次升级中，120 次来自截短日志，5 次来自带包装前缀的日志。规则完成更多任务，但有更多失败；选择性策略不能被描述为在所有指标上胜出。

来源级 bootstrap 执行率区间为 73.125%–74.792%。8 个来源、重复故障模板以及留一法训练集的重叠限制了统计解释；这仅是本基准来源重采样的描述性区间。零观察错误不等于真实风险为零。新协议利用了此前测试反馈，因此是开发后的回归评估，不是从未接触的新外部验证集。

规划与运行：关键词 96/456，最近邻 24/456，Oracle 456/456；Oracle 执行 456/456；注入字段错误后无恢复 144/456，允许一次重试并计入预算后 456/456。Oracle 是上界，不是学习模型的性能。

## 复现与验收

本地最终运行：38 项测试全部通过；全量验收五项检查全部通过。30 条子进程案例通过，包含 20 次实际终止和 10 次残缺产物拒绝。测试与验收前后已跟踪文件哈希均未变化。历史换行统一作为独立提交，92 个已跟踪文件只有换行差异。

在仓库根目录、安装已有依赖后运行：

```text
python -m unittest discover -s tests -v
python -m research.v3_release --out work/v3_acceptance
```

前者包含权限、零预算、哈希错误、缺失输入、重试预算、错误校准、空校准、升级不执行、数据划分和指标核对等回归检查。后者运行全量规划/执行、480 条恢复比较和 30 条子进程案例，并检查已跟踪文件前后哈希一致。实验报告在指定输出目录，临时执行产物在忽略目录 artifacts/。

真实数据的原始 ZIP 校验值、DOI、许可及派生文件校验值见 tasks/v3_real/manifest.json；主评估启动前核验派生文件。下载缓存齐全时，可用 python -m research.v3_real_data --cache <缓存目录> 重建。

## 能力边界

1. 原始请求中的正确字段、参数和可恢复输入地址是公开受信上下文；当前修复不解决从自然语言重新推断缺失参数的问题。
2. 主恢复评估中的 timeout 是模拟错误观察，随后重试真实工具；独立子进程测试验证真实终止和残缺产物拒绝，二者尚未组成通用进程隔离执行器。普通多步工具的时间限制为调用前/后检查，不能中断卡死调用。
3. 旧 126 条压力案例包含模拟延迟、预先编排复合错误以及未知损坏。保留用于回归，不把它们等同于自主多阶段恢复；旧 Wilson 区间不作为论文主证据。
4. 数据来源真实，故障是人为注入；四种日志包含文本包装而非外部服务错误协议。无真实 LLM 微调、RL 训练或在线服务验证。

因此 V3 的完成结论是“可复现本地诊断与恢复基准已收束”，不是“开放环境研究问题已解决”。V4 应使用全新外部任务和预先冻结的协议检验后续改进。
