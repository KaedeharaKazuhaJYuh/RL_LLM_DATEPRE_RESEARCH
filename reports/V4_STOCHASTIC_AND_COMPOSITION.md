# V4 随机执行与组合泛化审计

日期：2026-09-17。此报告追加在 V4 稳定性实验之后；前次运行、检查点和负结果均保留。所有本地策略在评估中冻结权重。

## 要回答的问题

此前的 100% 是贪心选择动作的开发验证结果。它既不能说明按策略概率实际采样时的成功率，也不能说明策略理解未训练过的两步组合。本轮分别审计这两个问题，再让 DeepSeek 在相同组合探针上执行一次直接规划对照。

## 随机执行

沿用 v4-sequence-1 的 12 条验证任务，每条有正常与一次模拟读失败条件。每个方法用三个训练种子，每个任务条件各重复采样 20 次，共 1,440 条执行轨迹。相同种子、任务、条件和重复编号使用相同随机数流；不同策略采取的动作仍可能不同。没有重新训练或筛选检查点。

| 方法 | 原贪心通过率 | 本轮采样通过率 | 采样成功数 | 采样平均回报 |
|---|---:|---:|---:|---:|
| 监督初始化 | 100% | 21.81% | 314/1,440 | 0.0586 |
| 原逐回合 REINFORCE | 69.44% | 27.64% | 398/1,440 | 0.1168 |
| 批量更新 | 100% | 21.81% | 314/1,440 | 0.0586 |
| 批量更新＋监督保持 | 100% | 21.88% | 315/1,440 | 0.0592 |

原 RL 在采样成功率上高于监督基线，但贪心表现下降。因此不能笼统说“RL 总体退化”或“稳定化方案整体改善”。稳定化修复的是贪心动作排序；它没有提高本轮随机执行成功率。先前报告中的 100% 必须附上评估模式。三种子与 20 次重复不是独立任务来源：验证数据只有两个来源，不能用 1,440 当作独立样本计算外部泛化置信度。

## 新组合开发探针

使用原验证来源 04、05，构造六种训练中未出现的有序两步组合，共 12 条任务。工具、公开参数绑定、最多四次决策和三次工具调用、最终状态验证与旧协议一致。任务有正常和首个工具调用失败两种条件；专家轨迹 24/24 通过，确认任务可执行。探针输入与答案保存在 `tasks/v4/composition_dev_v1`。

四个冻结本地策略各运行三个种子、12 任务、两种条件，即每方法 72 回合；**四者全部为 0/72**。常见失败是把新提示映射到旧的完整动作序列，例如要求“填补空值再按日期汇总”却执行“去重再计算移动平均”。这支持目前的字符 n-gram softmax 策略记忆模板组合、缺乏动作组合泛化的判断，不能把旧基准满分解释成通用多步规划能力。该探针仍来自旧验证来源，是开发诊断，不是新外部测试。

## DeepSeek 直接规划对照

仅对 12 条新组合任务的**正常条件**调用 DeepSeek；它与本地策略共享任务、工具、参数绑定和评分，但本地策略上表包含正常及故障条件，因此跨表不能直接比较总体通过率。保持模型 `deepseek-chat` 和固定动作绑定，两次独立运行仅改变温度。

| 温度 | 通过 | 格式或动作校验拒绝 | API 请求 | 输入 / 输出 tokens |
|---:|---:|---:|---:|---:|
| 1.0 | 6/12 | 6 | 25 | 28,794 / 404 |
| 0.0 | 12/12 | 0 | 36 | 42,636 / 524 |

两轮合计 61 次请求，输入 71,430、输出 928 tokens。每轮请求上限 48；未自动重试失败响应。温度 0 这一次结果很好，但每种温度只有一次完整运行，不能据此估计稳定性，也不能断言全部格式错误只由温度引起。温度 1.0 的六次拒绝属于响应结构或动作校验失败，并非六次已观察到的规划错误。当前记录不保存原始响应内容，不能进一步确定其具体格式。

DeepSeek 官方 [JSON Output 说明](https://api-docs.deepseek.com/guides/json_mode/)指出 JSON 模式保证合法 JSON 文本，但也提示偶尔可能返回空内容；合法 JSON 本身不保证满足本项目的动作白名单。官方 [Tool Calls 说明](https://api-docs.deepseek.com/guides/tool_calls/)提供严格 schema 模式，但需要 beta 接口。下一阶段可单独比较严格工具调用与目前 JSON 模式，不将未经验证的接口直接替换主结果。

## 研究判断与下一步

当前外部 softmax 控制策略的优势在于廉价可控的工具执行研究；它在新组合上完全失效，不适合作为课题中“LLM 已学会规划”的证据。DeepSeek 对新组合的单次温度 0 对照说明语言模型可作为教师或强基线。下一步应把新组合任务扩到训练、开发、最终测试三种真正隔离的来源与模板划分，并收集正确动作轨迹；然后在可训练的开放权重语言模型上比较监督微调与受约束的策略优化。DeepSeek API 不能通过这里的 REINFORCE 更新其权重。

短期操作顺序：先固定温度 0 的直接调用设置并重复推理评估；再补工具调用接口对照和错误类型诊断；最后根据本机算力决定可训练模型及训练预算。若新增训练任务只复制同类模板，应先检查跨组合泛化，避免重现旧协议满分但新组合零分的问题。
