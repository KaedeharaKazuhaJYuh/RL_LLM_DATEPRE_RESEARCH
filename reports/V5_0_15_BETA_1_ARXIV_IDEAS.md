# V5.0.15-beta.1：arXiv 检索与两个研究假设

检索日期：2026-10-08。围绕多轮工具 RL、反事实归因、组内零方差、故障恢复与改写泛化检索 arXiv，并查阅以下原始摘要及部分正文。本报告是针对性检索，不是穷尽查新；论文的实验结论未在本机复现，以下两个自拟方向不能据此宣称全球首次。

## 已有工作与可借鉴点

| 原始论文 | 关键思想 | 对本项目的启发与边界 |
| --- | --- | --- |
| [RC-GRPO，2026-02](https://arxiv.org/abs/2602.03025) | 用奖励条件轨迹训练与不同奖励 token 引导组内探索，缓解同分组导致的无更新 | 可作为有效采样基线；引入条件 token 后必须把它计入策略上下文及概率计算，不能把不同条件直接视为同一策略分布 |
| [RTMC，2026-04](https://arxiv.org/abs/2604.11037) | 用共享状态的 rollout 树估计逐步 Q 值和优势，无需单独训练 critic | 是上一版状态分支规划的直接近邻；状态签名必须包含影响后续结果的信息，不能只比较文件内容 |
| [Credit Assignment with Resets，2026-05](https://arxiv.org/abs/2605.25507) | 在中间位置重置并采样多个后缀，比较随机重置与模型定位错误后的重置 | 可把整条轨迹重跑改成局部续跑；论文主要研究推理，文件副作用和故障状态恢复需要本项目另做验证 |
| [CRAFT，2026-06](https://arxiv.org/abs/2606.29476) | 在自蒸馏智能体 RL 中复用同组兄弟轨迹，估计带符号的 token 反事实归因 | 说明泛泛的“反事实信用分配”已经有直接工作；可借鉴复用采样和独立消融，不能直接套用其教师上下文假设 |
| [TRACE，2026-07](https://arxiv.org/abs/2607.13988) | 在工具边界利用冻结参考模型对正确答案的概率变化构造过程奖励 | 可对照学习式状态价值与本项目的精确工具验证；正确答案属于训练器特权信息，不得出现在评测时的策略输入 |

因此，“GRPO＋过程奖励＋分支续跑”应当表述为已有方法的应用与适配。更具体的贡献需要回答：可控故障能否提供更可靠的恢复信用？数据语义变换能否提供比提示改写更强的泛化训练信号？

## 自拟方向一：成对故障干预的恢复优势

**问题。** 正确工具动作遭遇超时，与模型选错工具都可能得到失败终局。只按终局奖励会混合工具选择能力、环境随机性与恢复能力。项目已具备正常/瞬时读取失败/超时/部分写入的可控环境，适合主动干预这个混淆因素。

**方法假设。** 从同一训练状态快照分出正常与故障两条支路，固定任务、文件内容、预算及可复现的环境随机数；在故障支路的同一观察状态内，按行为策略采样多个恢复动作和后缀，比较各自的终局验证分数。组内恢复优势只在同一故障上下文中计算。正常支路用作任务可解性和基础能力的配对诊断；不要直接将两种不同观察混成原 GRPO 的同一组。

建议先定义诊断量：`恢复缺口 = 正常终局得分 − 故障终局得分`；训练前后在相同任务上比较缺口变化，并同时报告正常得分，防止正常能力下降造成“缺口缩小”的假进步。训练更新仍用同状态候选恢复分支的相对终局优势。若引入跨条件差分作为奖励，应单独推导和消融，不把它直接称为无偏因果策略梯度。

**具体区分度。** 增加两种显示相似超时信息、但提交状态不同的训练环境：动作执行前超时；动作已提交但响应丢失。让策略使用可观察的文件/状态检查判断是否重试，评测“重复副作用率”和“无污染恢复成功率”。现有环境若只模拟执行前故障，必须先扩展状态检查动作及持久提交语义；不能靠提示中的故障标签告诉模型答案。遇到不可观察的隐藏状态时，应允许检查或保守停止，而不是要求策略猜中。

**最小实验。** 先以训练来源的一个两步任务族、两个故障语义做小预算试验；对照普通故障增强 GRPO、普通分支 GRPO、等数据 SFT 和成对干预方案。所有分支、正常对照和检查调用都计入预算。只有在新故障措辞、新来源、不同提交时点上改善且正常不退，才扩大到三种子。主要可证伪点：若只降低训练故障失败率，或相同预算的普通分支已取得全部收益，此方向没有独立贡献。

**与已有工作的区别。** RTMC/重置方法主要提供分支归因框架；这里研究的具体变量是工具提交状态和外生故障干预，以及恢复收益与正常任务收益的分解。这是候选贡献边界，仍需后续查新和实验确认。

## 自拟方向二：任务契约约束的语义变换 RL

**问题。** 本项目的新措辞泛化与数值组合很弱。仅奖励输出一致，可能让多个错误答案互相一致；仅比动作文本，又会错误惩罚不同但等价的有效执行。

**方法假设。** 对同一训练任务构造有明确数学契约的输入变换，同时变换提示、参数和预期输出；以变换前后执行结果是否满足契约来定位脆弱决策。可优先用：列重命名与参数同步映射、无关列添加，以及不依赖行序的统计任务上的行排列。滚动均值依赖顺序，不能随意打乱行；去重、裁剪边界、浮点容差也必须逐工具定义，不能采用通用“语义相同”判断。

对一个任务簇，主训练回报使用多个变换版本的**真实终局成功率**或预注册的最差版本分数；一致性只作为有界辅助项，必须经过真实正确性验证。不同版本各自保留完整策略上下文、行为概率和奖励分组，不跨不同提示直接共享未校正的轨迹概率。候选动作的等价性以最终数据契约判断，而不是要求 JSON 字符串或工具顺序完全相同。

**最小实验。** 先在现有薄弱数值任务上实现两类精确变换；对照同样数据增强的 SFT、同样数据增强的普通 GRPO，以及额外加入簇级鲁棒目标的 RL。验证阶段留出新的变换组合和新来源，并加入违反变换前提的反例，检查验证器是否错误给奖。每个变换执行都计费。若收益只来自额外样本而非目标函数，结论应归于数据增强。

**创新边界。** 数据增强、一致性学习和蜕变测试都不是新概念；候选贡献是把工具可执行契约用于 RL 的任务簇鲁棒目标，并把“同样错误但一致”的奖励漏洞排除在外。当前检索不足以证明这一组合无人研究。

## 优先级与规划调整

beta.1 优先做方向一的最小试验；它最能利用本项目已具备的故障注入和产物验证，也可与普通分支基线形成清晰差异。方向二先交付变换契约与反例测试，不与方向一一开始就合并，以免无法归因。RC-GRPO 暂作为探索基线候选；先计量零优势组占比和额外训练成本，再决定是否加入。

任何“突破”结论必须比较最强匹配监督对照和对应消融，报告独立任务簇、全部种子、环境调用/token/时间成本，以及来源级区间。仅有两个来源时，跨来源总体区间不稳定，应逐来源报告并扩大来源数，不能靠增加同题故障重复制造统计把握。本次只完成查新与设计，不新增训练结果。
