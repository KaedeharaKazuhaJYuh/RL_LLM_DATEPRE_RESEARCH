# V4 首次真实 DeepSeek 试跑

2026-09-15 完成。代码基于 c90063a，模型 deepseek-chat，温度 1.0。使用既有 V2 开发数据中的 12 条训练任务、12 条验证任务，不使用 test 划分。每个学习种子训练 6 轮、72 次工具交互；三个种子分别为 1、2、3。

## 结果

| 方法 | 种子 1 | 种子 2 | 种子 3 | 验证通过率 |
|---|---:|---:|---:|---:|
| 直接 DeepSeek | 12/12（仅一套 API 响应） | — | — | 100% |
| 本地 Bandit | 5/12 | 3/12 | 4/12 | 三种子均值 33.33% |
| DeepSeek + Bandit | 5/12 | 3/12 | 5/12 | 三种子均值 36.11% |

同一任务的 DeepSeek 建议只调用一次，各方法共享冻结建议。三种子不是独立 API 重复，也不是 36 个独立验证任务；两个学习组只相差一次验证成功，不能声称显著提升。当前最直接的观察是：这套小样本冷启动学习策略明显弱于直接采用 LLM 建议。

## 实际用量

- 24 次成功 API 请求，输入 10,091 tokens，输出 1,040 tokens。
- 累计请求耗时约 22.69 秒；直接 DeepSeek 验证平均约 1.02 秒/任务。
- 首个沙箱运行发生 URLError，成功响应为 0；网络权限放开后完整运行成功。报告用量来自成功运行的响应，不等同于提供商账单审核。
- 金额尚未计算，需结合实际账单单价和缓存计费确认。

## 分析及限制

训练任务按公开任务 ID 排序选取，没有按正确动作筛样。本轮覆盖 12 种工具中的 8 种，缺少 deduplicate、describe_numeric、normalize_dates、clip_outliers。训练末轮两个学习组为 8–9/12，而验证仅 3–5/12，提示小样本和任务覆盖限制，不能仅凭本轮确认因果。

Hybrid 的 LLM 建议是一组额外输入特征，策略从零学习如何利用它，没有直接把 LLM 建议作为初始策略。这可以解释为何有正确 LLM 建议仍可能选错工具，但需要对照实验验证。当前更新的是外部 Bandit 权重，不是 DeepSeek 权重，属于一步奖励学习试验。

三个种子的策略都通过验证前后权重哈希不变检查；保存了训练奖励、验证结果和检查点。真实结果文件在 work/v4_deepseek_pilot_002，成功结果摘要另存为报告附件。密钥仍在被 Git 忽略的本地配置，不进入实验产物。
