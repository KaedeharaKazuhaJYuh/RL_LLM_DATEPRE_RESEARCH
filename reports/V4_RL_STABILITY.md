# V4 RL 退化诊断与优化

日期：2026-09-16。保留原始负结果，新增独立运行 work/v4_sequence_stable_001；本轮无 API 请求，无 DeepSeek 权重更新。

## 为什么退化

1. **贪心正确不代表采样可靠。** 原监督模型在训练示范状态的最高概率动作准确率为 100%，但给专家动作的平均概率只有约 61.5%。评估取最高概率动作，训练却从完整分布采样；连续三至四次决策会累积出错机会。平均概率不能直接当作整条轨迹成功概率。
2. **原更新破坏了部分已学动作。** 原 REINFORCE 的三个种子在训练示范状态的动作准确率分别降至 80.95%、91.07%、92.86%，相对监督策略的平均 KL 为 0.04214、0.01594、0.04373。这是实际观测到的行为漂移。尽管专家动作平均概率上升，部分状态的动作排序仍变坏，因此平均置信度不能替代逐状态正确性。
3. **更新机制缺乏稳定性保护。** 原实现每条轨迹立即更新，共 960 次，整条终局回报用于全部动作，只有跨任务共享的历史基线，没有监督保持或策略距离限制。稀疏终局奖励、采样噪声和状态间共享参数是可能的影响因素；尚未通过单因素实验确定各自贡献，不将退化归结为一个已证实的原因，也不把合法 REINFORCE 实现误报为梯度公式错误。

## 修改

- 每 48 条轨迹在同一冻结策略下采样，再进行一次按回合数平均的策略梯度更新；20 轮，共 960 个回合、20 次更新。
- 按任务和故障条件维护仅依赖过去批次的回报基线，EMA 为 0.9/0.1，不使用当前批次回报作为该批次基线。
- 总梯度范数限制为 1；训练示范状态和采样状态上的最大单步 KL 限制为 0.01，超出时回溯缩小步长。
- 额外对照加入监督交叉熵保持项（权重 0.2）及监督参考策略 KL 项（权重 0.5）。参考权重不更新。
- 学习率 0.1，种子 1、2、3，固定最后一轮。参数在运行前写入 manifest，不按验证分数筛选检查点。

这仍是带约束的 REINFORCE，不是 PPO。限制更新幅度的研究背景可参考 [Schulman 等，Proximal Policy Optimization Algorithms](https://arxiv.org/abs/1707.06347)，不能将本实现描述成论文算法复现。

## 对照结果

沿用 v4-sequence-1：24 条训练任务、12 条开发验证任务，分别运行正常与一次模拟读失败条件。每个种子验证 24 回合。

| 方法 | 种子 1 | 种子 2 | 种子 3 | 平均通过率 | 平均回报 |
|---|---:|---:|---:|---:|---:|
| 原监督基线 | 24/24 | 24/24 | 24/24 | 100% | 0.8400 |
| 原逐回合 REINFORCE | 12/24 | 18/24 | 20/24 | 69.44% | 0.5344 |
| 批量更新＋条件基线＋幅度限制 | 24/24 | 24/24 | 24/24 | 100% | 0.8400 |
| 上述方案＋监督及参考策略保持 | 24/24 | 24/24 | 24/24 | 100% | 0.8400 |

两种新方法平均工具调用数均为 2.5。新增真实本地工具训练回合共 5,760，验证回合 144；原基线引用已保存检查点与原始报告，未重跑原训练。新权重确实改变：批量方案与监督权重的距离约 0.100–0.113，带保持方案约 0.126–0.136。所有评估冻结权重，未拿验证结果做梯度更新。

带保持方案在训练示范状态上的动作准确率保持 100%，平均参考 KL 为 0.00014–0.00043；专家动作概率约 61.9%–62.0%。采样训练仍不稳定，不能把贪心验证满分解释成随机执行也已可靠。

**结论是恢复稳定性，并非证明 RL 超过监督学习。** 无监督保持项的批量方案同样满分，因此本轮没有证明附加保持项在当前任务上有独立收益。批量化、条件基线、有效更新幅度同时改变，尚不能分离它们的贡献。保持项作为可选方案保留，不强行宣称它是最优方案。

后续补充审计显示：该“稳定性”仅针对贪心执行。随机执行成功率没有随两种稳定化方案提高，新组合任务中四个本地策略均失败。详见 [随机执行与组合泛化审计](V4_STOCHASTIC_AND_COMPOSITION.md)；这些补充结果限制了本报告的结论范围。

## 验证与复现

55 项测试通过，包括正奖励推动采样动作概率上升、大步长回溯满足 KL 限制、参考模型冻结、单独 KL 保持项降低策略偏离，以及既有环境和评分回归。KL 约束只覆盖本批训练状态，不能保证任意未见状态上的距离。

先运行原监督与 RL 入口产生检查点，再执行稳定性实验：

```text
python -m experiments.v4_sequence_train --out work/reproduce_original
python -m experiments.v4_sequence_stabilize --previous work/reproduce_original --out work/reproduce_stability
python -m unittest discover -s tests
```

摘要和逐轮诊断分别保存为 reports/v4_sequence_stability.json、reports/v4_sequence_stability_curves.jsonl。检查点位于本地 work/v4_sequence_stable_001。旧运行未被覆盖。
