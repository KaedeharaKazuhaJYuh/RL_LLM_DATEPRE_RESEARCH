# V5.0.05：两步课程监督对照预设方案

冻结日期：2026-09-29。问题是 V5 beta.1 的 96/144→102/144 是否超过“使用同一两步课程、继续做监督训练”的效果。这个对照沿用已公开的 beta.1 来源留出确认集，**不是新的盲测**；它只能补齐一个竞争性解释，不能证明跨新提示模板泛化。

## 固定输入与预算

- 基座为本机 `work/modelscope_deepseek_r1_1p5b`，其既有 beta 审计基座摘要为 `58858233513d76b8703e72eed6ce16807b523328188e13329257fb9594462945`。三个起点分别为种子 20260921、20260922、20260923 的 `work/v4_llm_composition_sft100_seed*/adapter`，文件摘要由冻结的 [beta.1 配对审计](v5_beta1_confirmation_paired_audit.json)核对。监督训练直接继续这些 LoRA 适配器，不重新从基座初始化。
- 训练协议只用 `tasks/v5/beta_curriculum_v1`（manifest SHA-256 `15af9fde24ed0c8955f50db3fc0fe272540f4a4cbc32e961c9c4c065b88b88ff`）。对每个种子复用原 GRPO 的 `schedule_static` 顺序：16 个任务条件组，每组 4 次专家回放，共 64 个训练 episode。正常/瞬时读取故障分组、同一输入表和专家两步计划均保持一致；不读取确认集的标签来生成训练样本。导出器逐组核对既有 GRPO 运行记录，若顺序不同则拒绝运行。
- 每种子的监督优化步数匹配已记录的 RL 实际优化器步数：8、10、13 个有效 GRPO 组 × 2 PPO epoch，即 **16、20、26** 步。SFT 梯度累积为 4、BF16、学习率 `2e-6`、最大长度 768、种子同上；其余保留既有 SFT 训练器设置，不根据确认集结果调参。64 个专家 episode 与 64 次 RL 采样 episode 数量相同，**决策 token 数、前向计算和 wall time 未必相同**，因此本方案称“episode 与优化步数匹配的监督对照”，不称严格等 FLOP 对照。

## 冻结评测与判定

用 `experiments.v4_llm_eval` 在 `tasks/v5/beta_confirmation_v1`（manifest SHA-256 `e18137564a4234de0461b4623c927b4db5bf88cc894862d5610aa0844e64331c`）分别评测三个新 SFT 适配器；沿用 BF16 GPU、贪心解码、最多 48 token、正常/瞬时读取/超时/部分写入四条件。每个种子 48 次执行，合计 144 次。与 beta.1 中相同起点 SFT 和 RL 的既有冻结记录逐题配对，报告总通过数、每种子净变、每来源和动作组合切片、新增与回退。不得只选最佳种子或覆盖原始结果。

只有新 SFT 对照全部完成后才作结论：若 GRPO 的合计通过数高于该监督对照，且至少两种子不低于该对照，才把现有 beta.1 结果描述为“在本协议下还超过匹配预算的监督继续训练”；否则撤回任何关于 RL 方法特有收益的暗示。无论结果如何，已见提示模板、两份来源和非等 FLOP 的限制继续保留。V5.0.05 的版本号仅在代码、原始结果与审计完成后使用。
