# V4.5.1 发布说明与今日整理

日期：2026-09-20

## 版本定位

V4.5.1 是 V4 可训练 LLM 路线的阶段版本。它把 DeepSeek 1.5B 的监督初始化、偏好优化、在线 GRPO 审计修正和 Intel NPU 推理接入放入同一条可复现链路。NPU 接入从本版本开始计入正式版本范围。

## 今日完成

1. 完成 SFT→DPO 偏好优化试验。环境验证的专家动作与提前停止、错误动作组成偏好对；BF16 DPO 在冻结开发集上通过 83/96。
2. 完成在线 GRPO 最小闭环，包括轨迹采样、环境终局奖励、组内相对优势和受约束更新。
3. 审计并修正 GRPO 分组错误。旧实现混合正常与故障条件，产生了不应存在的相对优势；修正后 64 条均衡训练轨迹全部通过但组内没有奖励方差，冻结开发集仍为 83/96。因此旧的 85/96 不再作为 RL 提升证据。
4. 在零优势组跳过优化器，防止没有有效奖励信号时由数值误差造成权重漂移。
5. 接入本机 Intel AI Boost NPU。OpenVINO NPU 计算图、DeepSeek 1.5B INT4 推理、LoRA 合并和冻结评测均已打通。
6. 完成同一 24 条开发执行的设备对照：GPU BF16 DPO 为 21/24，OpenVINO CPU FP16 合并模型为 21/24，NPU 混合 INT4/INT8 最佳为 15/24。NPU 已可运行，但当前量化精度不足以替代 GPU 金标准评测。
7. 完整单元测试 61/61 通过。

## 当前架构

数据和任务协议由 V4 source split 与未见工具组合划分提供；训练链路依次为监督轨迹导出、LoRA SFT、action-level DPO、在线 GRPO；运行环境负责工具执行和终局奖励；冻结评测分别覆盖 GPU BF16、CPU FP16 和 NPU 量化模型。GPU 负责梯度训练及主结果，NPU 负责量化研究和辅助推理。

## 已知问题

- 当前 GRPO 训练任务过易，同组轨迹奖励缺少方差，无法形成稳定的策略梯度信号。
- 现有 83/96 是合成开发协议结果，还不是最终盲测或外部真实数据结论。
- NPU 量化模型有明显精度损失；全 INT4 合并模型仅为 3/24，动态 LoRA 为 8/24，混合 INT4/INT8 虽提升到 15/24，仍低于 21/24 的 BF16 基线。
- 当前 NPU 路径只覆盖推理。现有 OpenVINO NPU 后端不承担 LoRA/GRPO 梯度训练。
- 需要把 API 重复调用、模型快照、训练数据哈希和最终冻结测试统一到一个发布清单中。

## 下一阶段计划

1. 设计具有组内奖励方差的困难训练任务，加入部分成功、多步错误恢复、预算压力和未见组合，先验证 GRPO 是否获得真实学习信号。
2. 固定 SFT、DPO、GRPO 三个模型快照，在完全相同的冻结集合上做多次 DeepSeek API 与本地执行对照，报告置信区间和失败类型。
3. 为 NPU 做逐层敏感度与量化消融，比较 INT4、混合 INT4/INT8、关键层 INT8/FP16，以及提示模板对结构化动作输出的影响。
4. 建立 v4.5.1 复现清单，记录代码提交、依赖、模型、适配器、数据哈希、设备和随机种子。
5. 在上述审计完成后再创建最终盲测集，避免开发阶段污染测试结论。

## 版本结论

V4.5.1 已建立可运行的 RL LLM 研究骨架和 NPU 推理路径，但尚不能宣称 GRPO 优于 DPO，也不能宣称 NPU 替代 GPU。下一步的研究重点是制造可学习且不泄漏的奖励差异，并降低 NPU 量化带来的结构化动作精度损失。
