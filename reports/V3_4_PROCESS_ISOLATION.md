# V3.4 子进程隔离与来源级不确定性

V3.4 使用真实子进程替代适配层模拟，验证超时终止和部分写入拒绝。每轮包含正常完成、纯超时、先写入残缺 JSON 后超时三类任务，共运行10轮、30个案例。

| 指标 | 结果 |
|---|---:|
| 总案例 | 30 |
| 符合预期 | 30/30 |
| 被父进程强制终止 | 20 |
| 被拒绝的残缺产物 | 10/10 |

父进程使用硬截止时间等待子进程；超时后终止进程并回收输出。产物只有在能够完整解析且状态为 `complete` 时才有效。因此部分写入文件即使存在，也不会被当作成功。

此外，V3.4 对三个冻结数据源进行10000次来源级bootstrap。学习恢复在每个来源均为100%，规则恢复在每个来源均为80.95%，所以两个区间都退化为单点。这不是高精度证据，而是暴露出三个来源共享同一故障模板、来源间异质性不足。后续必须增加更多来源并让故障分布随来源变化。
